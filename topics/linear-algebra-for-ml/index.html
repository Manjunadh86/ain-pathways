Linear Algebra for ML

Linear algebra is the mathematics of vectors and matrices: ordered lists and rectangular grids of numbers, together with the rules for adding, scaling and multiplying them. Machine learning stores data and model parameters in these objects, so that one matrix operation does the work of thousands of separate multiplications and additions.

1Overview

Why it matters

Almost every line of ML code is linear algebra under other names. A dataset is a matrix with one row per example. A linear model and a neural-network layer are matrix multiplications. An embedding is a vector, and "how alike are these two texts?" is a dot product. Once you can read shapes and know what a product does, documentation such as y = xA^T + b stops being notation and becomes something you can check by hand.

Without it, the failures are concrete. Code stops with a shape mismatch its author cannot interpret. Worse, it runs and returns wrong numbers because a transpose was missing or two arrays were combined along the wrong axis. A model is fitted on two columns that carry the same information and the solver returns unstable weights. A similarity search ranks long vectors above relevant ones because nothing was normalised. Anyone who writes NumPy or PyTorch code, tunes a model or debugs a retrieval system needs enough linear algebra to predict the shape and the meaning of a result before running the code. This lesson builds that working level and leaves the proofs to a mathematics course.

Key terms

Scalar
A single number, such as a learning rate of 0.01 or the brightness of one pixel.
Vector
An ordered list of numbers. In ML it usually holds the features of one example, the weights for one output, or an embedding.
Matrix
A rectangular grid of numbers arranged in rows and columns. A dataset with one example per row and one feature per column is a matrix.
Tensor
In ML libraries, an array with any number of axes. Scalars, vectors and matrices are tensors with 0, 1 and 2 axes.
Shape
The size of an array along each axis, written as a tuple such as (4, 3) for 4 rows and 3 columns.
Dot product
The single number obtained by multiplying the matching entries of two equal-length vectors and adding the results.
Transpose
The matrix obtained by swapping rows and columns, so that a matrix of shape (2, 3) becomes one of shape (3, 2).
Inverse
For a square matrix A, the matrix that undoes it. Multiplying A by its inverse gives the identity matrix. Not every matrix has one.
Determinant
One number computed from a square matrix that says by what factor it scales area or volume. Zero means the matrix flattens its input and has no inverse.
Eigenvector and eigenvalue
A direction that a square matrix only stretches without turning, and the factor by which it stretches it.

2Explanation

Introduction

You already use the objects of linear algebra. One cell of a spreadsheet is a scalar: a single number. One row, say a delivery order with its distance, its number of stops and a rain flag, is a vector: an ordered list of numbers. The whole sheet, with one order per row and one feature per column, is a matrix. Stack several sheets of the same size, or the red, green and blue layers of a photo, and you have a tensor, which in ML libraries simply means an array with any number of axes. NumPy's beginner guide (opens in a new tab) uses the same four words for arrays with 0, 1, 2 and more dimensions.

Every such array has a shape: its size along each axis. Four orders with three features each form a matrix of shape (4,3)(4, 3)(4,3). A colour photo of 256 by 256 pixels can be stored with shape (256,256,3)(256, 256, 3)(256,256,3), and a batch of 32 of them with shape (32,256,256,3)(32, 256, 256, 3)(32,256,256,3). Most ML bugs that are not about data quality are about shapes, so the habit this lesson builds is to write the shape next to every variable.

Linear algebra then supplies a small set of operations on these objects. The central one is the dot product: multiply two vectors entry by entry and add the results. With features x=(2,1,0)x = (2, 1, 0)x=(2,1,0) and weights w=(2,3,4)w = (2, 3, 4)w=(2,3,4),

x⋅w=2×2+1×3+0×4=7x \cdot w = 2 \times 2 + 1 \times 3 + 0 \times 4 = 7x⋅w=2×2+1×3+0×4=7

That line is a linear model's score for one row. Matrix multiplication is the same calculation repeated for every row and every set of weights at once, and it is the operation that NumPy, PyTorch and every other ML library are built to run fast.

The rest of the lesson covers how the dot product and the matrix product work and how to read their shapes; what the transpose, inverse and determinant of a matrix mean; what eigenvalues and the singular value decomposition reveal about a matrix; and why libraries want whole-array expressions instead of loops. The aim is working intuition: enough to read linear regression, neural networks and embeddings without stopping at the notation.

How it works

The dot product: one number from two vectors

For two vectors of the same length nnn, the dot product multiplies matching entries and adds the results:

a⋅b=∑i=1naibia \cdot b = \sum_{i=1}^{n} a_i b_ia⋅b=i=1∑n​ai​bi​

It has two readings, and ML uses both. As a weighted sum it is a model's score: features times weights. As a similarity it says how far two vectors point the same way, because

a⋅b=∥a∥ ∥b∥cos⁡θa \cdot b = \lVert a \rVert \, \lVert b \rVert \cos\thetaa⋅b=∥a∥∥b∥cosθ

where ∥a∥=a⋅a\lVert a \rVert = \sqrt{a \cdot a}∥a∥=a⋅a​ is the length (norm) of aaa and θ\thetaθ is the angle between the vectors. Take a=(3,4)a = (3, 4)a=(3,4) and b=(4,3)b = (4, 3)b=(4,3): a⋅b=12+12=24a \cdot b = 12 + 12 = 24a⋅b=12+12=24, both lengths are 5, so cos⁡θ=24/25=0.96\cos\theta = 24 / 25 = 0.96cosθ=24/25=0.96 and the vectors nearly align. Dividing a dot product by both lengths gives cosine similarity, the standard way to compare embeddings. When every vector already has length 1, the dot product is the cosine.

Matrix multiplication: a table of dot products

A matrix times a vector takes the dot product of each row with the vector, so XwXwXw turns a dataset XXX of shape (4,3)(4, 3)(4,3) and a weight vector of length 3 into 4 predictions. A matrix times a matrix repeats this for every column of the second matrix:

The top-left entry is row 1 of the first matrix dotted with column 1 of the second: 1×5+2×7=191 \times 5 + 2 \times 7 = 191×5+2×7=19. Three rules cover most of what goes wrong:

  • Shapes. (m,n)(m, n)(m,n) times (n,p)(n, p)(n,p) gives (m,p)(m, p)(m,p). The two inner sizes must be equal, and the outer sizes are the shape of the result.

  • Not element-wise. In NumPy and PyTorch, A * B multiplies entry by entry and A @ B is the matrix product. The numpy.matmul (opens in a new tab) page gives the rules for @, including that arrays with more than two axes are treated as stacks of matrices.

A matrix can also be read as a function that moves vectors: multiplying by A=[2112]A = \begin{bmatrix} 2 & 1 \\ 1 & 2 \end{bmatrix}A=[21​12​] sends (1,0)(1, 0)(1,0) to (2,1)(2, 1)(2,1). The product ABABAB then means "apply BBB, then AAA", which is why the order matters.

Transpose

The transpose A⊤A^\topA⊤ swaps rows and columns: entry (i,j)(i, j)(i,j) moves to (j,i)(j, i)(j,i) and a shape (m,n)(m, n)(m,n) becomes (n,m)(n, m)(n,m). It is mostly a tool for making shapes line up. PyTorch stores a layer's weights as (outputs, inputs) and computes y=xA⊤+by = xA^\top + by=xA⊤+b, and least squares uses X⊤XX^\top XX⊤X. The rule (AB)⊤=B⊤A⊤(AB)^\top = B^\top A^\top(AB)⊤=B⊤A⊤ says that transposing a product reverses its order.

Identity, inverse and determinant

The identity matrix III has ones on its diagonal and zeros elsewhere, and Ix=xIx = xIx=x. The inverse of a square matrix AAA is the matrix A−1A^{-1}A−1 with A−1A=IA^{-1}A = IA−1A=I. It undoes what AAA does, so the equation Ax=bAx = bAx=b has the solution x=A−1bx = A^{-1}bx=A−1b.

Whether an inverse exists is decided by the determinant, a single number that says by what factor the matrix scales area (in two dimensions) or volume; 3Blue1Brown's determinant lesson (opens in a new tab) animates this picture. For a 2 × 2 matrix it is ad−bcad - bcad−bc:

det⁡[2112]=2×2−1×1=3\det \begin{bmatrix} 2 & 1 \\ 1 & 2 \end{bmatrix} = 2 \times 2 - 1 \times 1 = 3det[21​12​]=2×2−1×1=3

This matrix triples every area. A negative determinant means the matrix also flips orientation, like a mirror. A determinant of zero means the matrix flattens the plane onto a line or a point. Different inputs then land on the same output, nothing can undo that, and the matrix has no inverse: it is singular. This happens exactly when one column is a combination of the others, which for a data matrix means a redundant feature. The number of columns that are not combinations of the others is the rank of the matrix.

In code, solve Ax=bAx = bAx=b with np.linalg.solve(A, b) (opens in a new tab) and do not form the inverse. The Deep Learning book (opens in a new tab) describes the inverse as mainly a theoretical tool, and the numpy.linalg.inv (opens in a new tab) page shows a nearly singular matrix whose computed "inverse" is wrong although no error is raised.

Eigenvectors and eigenvalues

Most vectors change direction when a square matrix multiplies them. An eigenvector does not: it is only stretched, by a factor called its eigenvalue λ\lambdaλ.

Av=λvAv = \lambda vAv=λv

For the matrix above, A(1,1)=(3,3)A(1, 1) = (3, 3)A(1,1)=(3,3) and A(1,−1)=(1,−1)A(1, -1) = (1, -1)A(1,−1)=(1,−1). So (1,1)(1, 1)(1,1) is an eigenvector with λ=3\lambda = 3λ=3 and (1,−1)(1, -1)(1,−1) is one with λ=1\lambda = 1λ=1: the matrix stretches the plane by 3 along one diagonal and leaves the other diagonal alone. The product of the eigenvalues, 3×13 \times 13×1, equals the determinant.

Eigenvectors answer the question "what happens if this matrix is applied again and again?" The direction with the largest eigenvalue takes over, which is how PageRank is computed. The eigenvectors of a dataset's covariance matrix are its directions of greatest spread, the basis of PCA. They are defined only for square matrices, and for some matrices they are complex numbers, as an example on the numpy.linalg.eig (opens in a new tab) page shows.

Singular value decomposition (SVD)

The SVD does a similar job for a matrix of any shape. It writes A=UΣV⊤A = U \Sigma V^\topA=UΣV⊤: a rotation, a stretch along perpendicular axes by the singular values σ1≥σ2≥⋯≥0\sigma_1 \ge \sigma_2 \ge \dots \ge 0σ1​≥σ2​≥⋯≥0, and a second rotation (either rotation may include a mirror flip). Large singular values mark strong patterns in the matrix; small ones mark detail or noise. Keeping only the kkk largest gives the closest approximation of rank kkk, stored in k(m+n+1)k(m + n + 1)k(m+n+1) numbers instead of mnmnmn.

Why libraries want whole-array expressions

A Python loop handles one number at a time through the interpreter. X @ w hands the entire job to compiled code. NumPy's linear algebra relies on BLAS and LAPACK (opens in a new tab) libraries tuned for the processor, and its introduction calls this style vectorization (opens in a new tab).

python
import numpy as np

X = np.random.default_rng(0).normal(size=(100_000, 50))   # 100,000 rows, 50 features
w = np.ones(50)

slow = [sum(x * wj for x, wj in zip(row, w)) for row in X.tolist()]   # one number at a time
fast = X @ w                                                          # one matrix-vector product
print(np.allclose(slow, fast))                                        # True

On the laptop used to check this lesson the loop took about 0.4 seconds and the matrix product between 1 and 3 milliseconds; exact timings depend on the machine. The matrix form has two more advantages. The same expression works for one row or a million, so a model is written once for any batch size. And because a model becomes a short chain of standard operations, a framework can move it to a GPU and differentiate it automatically, which calculus for ML builds on.

What the example shows

  • A prediction for one row is a dot product. Predictions for all rows and all outputs are one matrix product, and the shapes (4,3)(3,2)→(4,2)(4, 3)(3, 2) \to (4, 2)(4,3)(3,2)→(4,2) say what each axis of the result means.
  • The transpose is there to make the inner sizes agree, not for any deeper reason.
  • A non-zero determinant means the outputs keep enough information to recover the inputs. A zero determinant means one output repeats another, and here the solver refuses.

Edge cases and limitations

The element-wise product runs where a matrix product was meant
When two arrays have the same shape, both A * B and A @ B execute. For the 2 by 2 matrices in this lesson, the element-wise product is [[5, 12], [21, 32]] while the matrix product is [[19, 22], [43, 50]]. No error separates them, so check which one the formula calls for: a product written with no symbol between two matrices in a textbook is always the matrix product.
Broadcasting turns a subtraction into a table
Subtracting a vector of shape (4,) from a column of shape (4, 1) does not give four differences. The shapes are stretched against each other and the result has shape (4, 4), every prediction minus every target. With predictions 13, 18, 24, 29 stored as a column and targets 12, 20, 24, 30 stored flat, the mean squared error comes out as 79.5 when the correct value is 1.5. Print the shape of every difference, and flatten or reshape so that both sides agree before subtracting.
A nearly singular matrix returns an answer without an error
A singular matrix does not always make the solver raise an error, because rounding inside the computation can leave a tiny non-zero value where an exact zero belongs. The numpy.linalg.inv documentation shows a 3 by 3 matrix whose third row is twice the first plus the second, so it has no inverse, yet inv returns entries of size 10 to the 15th power and no error. The page recommends numpy.linalg.cond: as a rule of thumb a condition number of 10 to the power k can cost up to k digits of accuracy, and double precision carries about 16.
A square weight matrix hides a missing transpose
The shape rule catches a forgotten transpose only when the matrix is not square. With 2 inputs and 2 outputs, x @ W and x @ W.T both run. For the worked example's 2 by 2 weights and the row (6, 2), the correct product is (18, 5) and the wrong one is (13, 20). Test a layer on a case you have computed by hand, and prefer test shapes in which every axis has a different size.
Floating-point results are close, not exact
numpy.linalg.det returns 2.9999999999999996 for the matrix [[2, 1], [1, 2]] whose determinant is 3, because it is computed by a factorisation in binary floating point. Comparing such results with == fails. Use numpy.allclose or a tolerance, and treat a determinant or singular value of about 1e-15 beside entries of ordinary size as zero.
Eigenvectors and singular vectors have no fixed sign, and eigenvalues may be complex
If v is an eigenvector then so is -v, so two libraries or two runs can return opposite signs for the same direction; scikit-learn documents this sign indeterminacy for its SVD components. A rotation matrix such as [[0, -1], [1, 0]] turns every vector, so it has no real eigenvector and numpy.linalg.eig returns the complex pair i and -i. Compare directions up to sign. When you need real stretch factors for any matrix, use the SVD, which always exists and has real, non-negative singular values.

When to use it, and when something simpler is enough

Use it when

  • You apply the same arithmetic to every row of a dataset or every item of a batch. Write it as one matrix expression and let the library run it.
  • You need a single number for how alike two feature vectors or embeddings are. Use a dot product, or cosine similarity when the vectors have different lengths.
  • You need to know whether features are redundant or a system of equations has one solution. Check the rank and the condition number of the matrix.
  • You want to compress a table or reduce many correlated features to a few. Use a truncated SVD or PCA and inspect the singular values.
  • You are reading or debugging model code. Annotate each array with its shape and check each product with the inner-sizes rule.

Think twice when

  • The relationship you need is not a weighted sum. A matrix product alone cannot express thresholds or curves; neural networks get those from non-linear functions placed between the matrix products.
  • You are about to compute an explicit inverse or determinant of a large matrix to solve a system. Call a solver such as numpy.linalg.solve or lstsq instead.
  • The matrix is almost entirely zeros, like word counts over a large vocabulary. A dense array wastes memory; use a sparse format and algorithms that accept it.
  • The calculation involves a handful of numbers and runs once. A plain loop is clearer and its speed does not matter.

A simpler alternative. Plain Python loops over lists do the same arithmetic and are fine for learning the definitions or for a few hundred numbers. They stop being enough when the data reaches many thousands of rows, when the code must run on a GPU, or when a framework has to compute gradients, because all three depend on whole-array operations.

Key takeaways

  • A scalar, a vector, a matrix and a tensor are arrays with 0, 1, 2 and more axes, and writing down the shape of each one is the quickest way to catch mistakes.
  • A dot product multiplies matching entries and adds them up. It serves both as a weighted sum of features and as a measure of how closely two vectors point the same way.
  • A matrix product is a table of dot products. Shape (m, n) times (n, p) gives (m, p), the inner sizes must match, and the order of the factors matters.
  • A zero determinant means the matrix flattens its input and cannot be inverted, which for data means redundant columns. In code, call a solver and do not form the inverse.
  • Eigenvectors are the directions a square matrix only stretches, and the SVD extends the idea to any matrix. Keeping the largest singular values gives a compact approximation.
  • Libraries express models as matrix operations because one call into compiled or GPU code replaces millions of interpreted steps and works unchanged for any batch size.

Keras image loading: folders of photos become tensors with four axes

KerasDocumented in official docs

Keras is a deep-learning library. Its API reference for image data loading documents image_dataset_from_directory, which turns a folder of image files into batches of arrays, and its Conv2D reference documents the input shape that a convolution layer accepts. [13][14]

The problem

Image files arrive in several formats and in arbitrary sizes, while a network needs every input to be numbers arranged in the same way. A convolution layer accepts one 4D tensor per batch, so something has to decode, resize and stack the files into that shape and keep the labels lined up with the images.

Where this topic fits

The tensor shape is the contract between the data pipeline and the model. The loader sits between the files on disk and the first layer and outputs arrays of shape (batch_size, height, width, channels). Every layer after it states its own input and output shapes in the same terms, which is what lets you check a model on paper before running it.

How it is applied, step by step

  1. Each file is decoded into a grid of pixel values with three axes: height, width and colour channels. The default colour mode, rgb, gives 3 channels; grayscale gives 1 and rgba gives 4.
  2. Every image is resized to image_size, which is (256, 256) by default. Arrays can only be stacked along a new axis when they all have the same shape.
  3. Images are stacked along a new first axis in groups of batch_size, 32 by default. One batch is a float32 tensor of shape (32, 256, 256, 3), which is 6,291,456 numbers.
  4. Labels are produced alongside. With the default label mode they form an int32 vector of shape (batch_size,), so entry i of the labels belongs to image i of the batch.
  5. A Conv2D layer takes the 4-axis batch and returns another 4-axis tensor of shape (batch_size, new_height, new_width, filters). The batch axis passes through unchanged, so the same model handles 1 image or 32.
  6. The order of the axes is a setting, not a law. Keras defaults to channels_last, and the same layer accepts (batch_size, channels, height, width) when configured as channels_first.

Why this approach fits

A rectangular array per batch is what makes whole-array computation possible. Pixel (i, j) of channel c sits at the same position in every image, so one set of weights can be applied to all 32 images in a single call into optimised code instead of a loop over files. The leading batch axis also separates "how many examples" from "what one example looks like", which is why the layer's documented shapes hold for any batch size.

Limitation or tradeoff

Forcing every image into one shape costs information: resizing to a fixed square distorts or crops pictures with a different aspect ratio. The axis order is not stored in the array, so a (256, 256, 3) image fed to code that expects channels first either raises a shape error or, when the sizes happen to be compatible, runs on scrambled data. Dense tensors are also heavy: one default batch of 6,291,456 float32 values takes about 25 MB before the model has done anything.

What the sources document

  • image_dataset_from_directory generates a dataset from image files in a directory, with defaults batch_size=32, image_size=(256, 256), color_mode "rgb" and label_mode "int". Supported formats are .jpeg, .jpg, .png, .bmp and .gif. [13]

PyTorch nn.Linear: a whole batch through one matrix product

PyTorchDocumented in official docs

PyTorch is an open-source deep-learning framework. Its reference page for torch.nn.Linear (version 2.14) documents the fully connected layer used in most neural networks, and its Tensors tutorial documents the array type the layer operates on. [15][16]

The problem

A fully connected layer has to turn each input row of in_features numbers into out_features numbers, using weights that training will adjust. During training it receives batches of rows, and the batch size can change from call to call, so the computation must be defined for any number of rows at once.

Where this topic fits

The layer is this lesson's matrix product with learnable entries. Inputs arrive as a tensor whose last axis has size in_features. The layer multiplies by the transpose of its weight matrix, adds the bias, and hands a tensor whose last axis has size out_features to the next layer or activation function.

How it is applied, step by step

  1. The layer stores a weight matrix A of shape (out_features, in_features). Row j holds the weights that produce output j. It also stores a bias vector with out_features entries.
  2. An input batch x has shape (batch, in_features). Against A the inner sizes would be in_features and out_features, so A is transposed to shape (in_features, out_features).
  3. The product of x and the transposed weights takes the dot product of every input row with every weight row. Its shape is (batch, out_features).
  4. The bias is added to every row by broadcasting, which completes the documented formula: y equals x times the transpose of A, plus b.
  5. Leading axes are carried along. The documented input shape allows any number of them, so the same layer works on one row, a batch of rows or a batch of sequences.
  6. Because the layer is built from tensor operations, it can be moved to a GPU or another accelerator, where the same product is computed in parallel.

Why this approach fits

Written as one product, the layer does not care how many rows it receives, and the whole batch is computed in a single call instead of a Python loop over rows and outputs. The weights are also one object with a known shape, which is what an optimiser and automatic differentiation need: the gradient of the output with respect to the weights is itself a matrix expression. The next lessons on neural networks and backpropagation rely on exactly this form.

Limitation or tradeoff

The number of weights is in_features times out_features. Connecting a flattened 256 × 256 × 3 image (196,608 numbers) to 1,000 outputs would take 196,608,000 weights in one layer, which is one reason image models use other layer types. A linear layer is also only a weighted sum: two of them stacked with nothing in between equal a single linear layer, because the product of two matrices is another matrix. Finally, the weight is stored as (out, in), and when the two sizes are equal a missing transpose raises no error.

What the sources document

  • torch.nn.Linear applies an affine linear transformation to the incoming data, written on the page as y = xA^T + b. [15]
  • The input has shape (*, H_in), where * means any number of dimensions including none and H_in equals in_features. The output has shape (*, H_out), where all but the last dimension match the input and H_out equals out_features. [15]
  • The learnable weight has shape (out_features, in_features) and the bias has shape (out_features); both are initialised from a uniform distribution between minus and plus the square root of k, with k = 1 / in_features. [15]
  • The page's example creates nn.Linear(20, 30), passes an input of size (128, 20) and prints an output size of torch.Size([128, 30]). [15]
  • The Tensors tutorial says tensors encode a model's inputs, outputs and parameters, are similar to NumPy's ndarrays except that they can run on GPUs or other hardware accelerators, and that the @ operator or matmul computes the matrix product while * or mul computes the element-wise product. pgvector with OpenAI embeddings: nearest neighbours by dot product

pgvector (open-source PostgreSQL extension)Documented in an open-source project

pgvector is an open-source extension that adds vector similarity search to PostgreSQL. Its README documents the distance operators and index types, and OpenAI's embeddings guide documents the vectors its embedding models return and which distance function to use with them. [17][18]

The problem

A search or retrieval feature has to find, among stored passages of text, the ones most related to a query. Each passage is represented by an embedding, by default a vector of 1,536 floating-point numbers for text-embedding-3-small, and relatedness has to be reduced to one number per stored row that the database can sort by.

Where this topic fits

The dot product is the scoring function inside the ORDER BY clause. Before it, an embedding model turns passages and the query into vectors. After it, the top rows go back to the application, for example as context for retrieval-augmented generation.

How it is applied, step by step

  1. Each passage is embedded once and stored in a column of type vector(n) beside its text.
  2. At query time the query text is embedded with the same model, so that it lies in the same space as the stored vectors.
  3. For each candidate row the database computes the inner product of the stored vector and the query vector: multiply matching entries and add them up.
  4. Because these embeddings have length 1, the inner product equals the cosine of the angle between the two vectors, and no division by the lengths is needed.
  5. The operator for inner product returns its negative, so sorting in ascending order puts the most similar rows first. Multiplying by -1 recovers the similarity.
  6. With an HNSW or IVFFlat index built for inner product, the database finds approximate nearest neighbours without scoring every row.

Why this approach fits

A dot product needs one multiplication and one addition per dimension, nothing else, and it is the same operation whatever the vectors mean. For vectors of length 1 it gives the same ranking as cosine similarity while skipping the two length calculations, which matters when millions of rows are scored. Doing it inside PostgreSQL keeps the vectors next to the rest of the data, so the same query can filter by ordinary columns.

Limitation or tradeoff

The shortcut holds only for vectors of length 1. With unnormalised vectors a raw inner product favours long vectors over well-aligned ones, and OpenAI's guide warns that an embedding shortened by hand must be normalised again. Index limits also bite: pgvector indexes vector columns up to 2,000 dimensions, so the 3,072-dimension default of text-embedding-3-large needs the halfvec type or a smaller dimensions setting. An approximate index can miss true nearest neighbours, and a high similarity score says two texts are related, not that the stored text answers the question.

What the sources document

  • pgvector describes itself as open-source vector similarity search for Postgres. Its operators include <-> for L2 distance, <#> for negative inner product, <=> for cosine distance and <+> for L1 distance. [17]
  • The README notes that <#> returns the negative inner product because Postgres only supports ascending-order index scans on operators, and says to multiply by -1 to get the inner product. [17]
  • The README advises that if vectors are normalized to length 1, like OpenAI embeddings, inner product should be used for best performance. HNSW and IVFFlat indexes can be created with the vector_ip_ops operator class. [17]
  • Vectors can have up to 16,000 dimensions, while indexes support up to 2,000 dimensions for the vector type and up to 4,000 for halfvec. [17]
  • OpenAI's guide defines an embedding as a vector (list) of floating point numbers whose distances measure relatedness, gives default lengths of 1536 for text-embedding-3-small and 3072 for text-embedding-3-large, and says the embeddings are normalized to length 1, so cosine similarity can be computed slightly faster using just a dot product. [18]

Google PageRank: ranking web pages with a dominant eigenvector

GoogleDocumented in official docs

PageRank is the link-analysis method Google Search launched with. US patent 6,285,999, "Method for node ranking in a linked database" (inventor Lawrence Page, now assigned to Google), sets out the calculation, and Google's guide to its Search ranking systems says PageRank remains one of its core ranking systems. [19][20][21]

The problem

Web pages vary enormously in quality, and the text of a page does not say how much it should be trusted. The patent's method gives each document an importance rank calculated from the ranks of the documents that cite it. That definition is circular, and for a collection with millions of documents the resulting equations cannot be solved by inspection.

Where this topic fits

The eigenvector is the answer itself. The links are written as a transition matrix, the ranks are the vector that this matrix leaves unchanged, and that vector is found by repeated matrix-vector multiplication. The ranks depend only on the link structure, so they can be computed ahead of any query and then used as one input when results are ordered.

How it is applied, step by step

  1. Number the N pages and record the links in a matrix: a page with n outgoing links passes a share of 1/n to each page it links to.
  2. Blend in a random jump: with probability alpha an imagined surfer jumps to any of the N pages, and otherwise follows a link. The blend is the transition matrix A.
  3. Describe where the surfer might be as a vector of N probabilities, starting with 1/N for every page.
  4. Multiply the vector by A. The result is the distribution after one more click. Repeat the multiplication.
  5. The vector stops changing when it reaches the steady state p with Ap = p. That is an eigenvector of A with eigenvalue 1, the dominant one.
  6. Read the entries of that vector as the ranks. A page ranks high when pages that rank high link to it.

Why this approach fits

"A page is important if important pages link to it" defines each rank in terms of the others, and an eigenvector equation is exactly a statement of that kind: a vector that the matrix maps to itself. Finding it by repeated multiplication needs nothing but matrix-vector products. Each page links to only a few others, so the link matrix is almost entirely zeros and one multiplication costs about one pass over the links, which is feasible where factorising an N by N matrix is not.

Limitation or tradeoff

The ranks measure link structure, not truth and not relevance to a particular query, so they are only one signal, and Google's guide says the way PageRank works has changed a great deal since launch. The iteration also needs care: the patent notes that pages with no outgoing links occur in significant numbers and complicate the computation, and without the random-jump term rank can pile up inside loops of pages that link only to each other. The vector must be recomputed as links change.

What the sources document

  • The patent defines the rank of a page A as r(A) = alpha/N + (1 - alpha)(r(B1)/|B1| + ... + r(Bn)/|Bn|), where B1 to Bn are the pages linking to A, |Bi| is the number of forward links of Bi, alpha is a constant between 0 and 1 and N is the total number of pages. [19]
  • It states that after one link the probability distribution is p1 = A p0, and that if the iteration converges it converges to a steady-state probability that is a dominant eigenvector of A, where A combines a uniform random-jump term weighted by alpha with a link matrix B whose entries are 1/n_i when node i points to node j. [19]
  • It says that with millions of documents the solution cannot be found by inspection, so a simple iterative procedure starting from ranks of 1/N is used, that sufficient convergence typically takes on the order of 100 iterations, and that alpha is typically around 15%. [19]
  • Google's guide to its Search ranking systems says PageRank was one of the core ranking systems used when Google first launched, that how it works has evolved a lot since then, and that it continues to be part of the core ranking systems. [20]
  • The abstract of Brin and Page's 1998 paper presents Google as a prototype large-scale search engine that makes heavy use of the structure present in hypertext, with a full text and hyperlink database of at least 24 million pages. [21]

scikit-learn latent semantic analysis: a truncated SVD of a document-term matrix

scikit-learnDocumented in official docs

scikit-learn is an open-source Python machine-learning library. Its user guide and TruncatedSVD reference describe truncated SVD for text, known as latent semantic analysis, and its example "Clustering text documents using k-means" applies it to newsgroup posts and reports the results. [22][23][24]

The problem

Text converted to tf-idf features gives a very wide and very sparse matrix: in the example, 3,387 documents by 7,929 terms with about 0.7 % of the entries non-zero. Two posts on the same subject may share few exact words, so their rows look unrelated, and clustering in thousands of dimensions is slow and unstable.

Where this topic fits

The truncated SVD is the step between turning text into numbers and clustering it. It receives the sparse document-term matrix and returns a dense matrix with one row per document and 100 columns, which k-means then groups.

How it is applied, step by step

  1. Each document becomes a row of tf-idf weights with one column per term, giving a matrix X of shape (3387, 7929).
  2. Truncated SVD computes only the 100 largest singular values and their singular vectors, so that X is approximated by the product of three smaller matrices.
  3. Each document's new coordinates are 100 numbers. Every coordinate is a weighted combination of terms that tend to occur together across the collection.
  4. The rows are rescaled to length 1, so that the distance between two documents depends on direction and not on how long the documents are.
  5. k-means runs on the 100-column matrix. A new document is mapped into the same space by multiplying its tf-idf row by the matrix of right singular vectors.
  6. To interpret a cluster, its centre is mapped back to the term space with the inverse transform and the terms with the highest weights are read off.

Why this approach fits

The SVD finds the combinations of terms along which the documents differ most, and keeping only the strongest ones compresses 7,929 columns into 100 while keeping documents with related vocabulary close together. In the six-sentence illustration, the first two sentences share only the word "launch" and have a cosine similarity of 0.17 as raw tf-idf rows; after reduction to two components it is 0.98. Because this variant does not centre the data, it works directly on the sparse matrix without turning it into a dense one.

Limitation or tradeoff

The new coordinates are mixtures of terms with positive and negative weights, so they are hard to name, and their signs can differ between runs. Much is discarded: in the example the 100 components keep 18.4 % of the variance, and the right number of components has to be chosen by trying. The user guide itself says LSA makes erroneous assumptions about text, and the method is purely linear. Where meaning matters more than speed and transparency, learned embeddings are the usual alternative.

4Common mistakes

  1. Writing A * B when the formula calls for the matrix product, or the other way round.

    Why it causes problems
    With equal shapes both operations run and return an array of the expected size, so nothing fails. The numbers are simply different, and a model built on the wrong product trains to nonsense or predicts values that look plausible and are wrong.
    How to recognise it
    Compute one small case by hand. For [[1, 2], [3, 4]] and [[5, 6], [7, 8]] the matrix product starts with 19 and the element-wise product starts with 5. In code review, look at every * between two arrays that both have two or more axes.
    How to fix it
    Use @ or matmul for matrix products and keep * for scaling and for entry-by-entry operations. When translating a formula, a product written with no symbol between two matrices is a matrix product.

  2. Combining an array of shape (n,) with one of shape (n, 1) and letting broadcasting build an n by n table.

    Why it causes problems
    A loss or an error metric computed on the table is a number of the right type and the wrong value. In the example in this lesson the mean squared error becomes 79.5 where the correct value is 1.5, and training then optimises the wrong quantity without any error message.
    How to recognise it
    Print the shape of the difference between predictions and targets. It should be (n,) or (n, 1), never (n, n). A loss that is far larger than the visible errors suggest is another sign.
    How to fix it
    Bring both arrays to the same shape before combining them, for example by flattening the predictions or reshaping the targets to a column, and assert the shapes at the start of the loss function.

  3. Calling an inverse function to solve a system or fit a model.

    Why it causes problems
    Forming the inverse and then multiplying takes more work than solving the system directly and loses more accuracy. When the matrix is close to singular, as with duplicated or strongly correlated features, the inverse can be badly wrong and is returned without any warning.
    How to recognise it
    Search the code for inv( followed by a multiplication. Check numpy.linalg.cond of the matrix: in this lesson's exercise a matrix with one redundant column has a condition number near 1e17, which leaves no trustworthy digits in double precision.
    How to fix it
    Call numpy.linalg.solve for a square system and numpy.linalg.lstsq for least squares. Remove redundant columns, or use a regularised model, when the condition number is very large.

  4. Ranking by raw dot product when the vectors have different lengths.

    Why it causes problems
    A dot product grows with the length of both vectors, so a long vector pointing in a mediocre direction can outrank a short one pointing exactly the right way. In a search system this pushes relevant items down the list and nobody sees an error.
    How to recognise it
    Compare the ranking by dot product with the ranking by cosine similarity on a sample. In the first exercise, the item with the largest dot product, 12, has a cosine of only 0.88, while two items with cosine 1.0 have dot products of 10 and 2.5. Also check whether the vector lengths are all 1.
    How to fix it
    Normalise vectors to length 1 when they are stored and when they are queried, after which the dot product equals the cosine. Otherwise compute cosine similarity explicitly. Normalise again after any step that changes the vectors, such as cutting off dimensions.

  5. Treating the wrong axis as the batch, such as passing X.T or summing over axis 0 where axis 1 was meant.

    Why it causes problems
    A (4, 3) dataset passed as (3, 4) is read as 3 examples with 4 features. If the next step happens to accept that width the code runs. Summing over the wrong axis is quieter still: for the worked example's X, axis 0 gives three column totals (20, 4, 2) and axis 1 gives four row totals (3, 5, 8, 10).
    How to recognise it
    Check that the first number of the data's shape equals the number of examples and that it matches the length of the targets. After any sum or mean, check that the result has one entry per example or one per feature, whichever was intended.
    How to fix it
    Adopt one convention, rows are examples and columns are features, and write the expected shape in a comment or an assertion beside each array. Name the axis argument explicitly in every reduction.

Step 5. By dot product guide e wins with 12, although it points about 28 degrees away from the query (cosine 0.882). Guides a and b point in exactly the query's direction, since a=2qa = 2qa=2q and b=q/2b = q / 2b=q/2, so both have cosine 1.

Step 6. A dot product is the cosine multiplied by both lengths. Guide b has the right direction but a length of only 1.12, so its dot product is 2.5 and it falls to fourth place; guide e has a length of 6.08 and is lifted to first. Cosine similarity divides the lengths out, which puts b level with a. Once every vector has length 1 the two measures are the same numbers, which is why systems that store normalised embeddings can rank with a plain dot product.

import numpy as np

np.set_printoptions(suppress=True)

# six days x four columns: online orders, in-store orders, total orders, returns
X = np.array([[12, 30, 42, 3],
              [15, 28, 43, 4],
              [ 9, 35, 44, 2],
              [20, 22, 42, 5],
              [18, 25, 43, 4],
              [11, 33, 44, 3]], dtype=float)

# 1. Redundancy
print("shape:", X.shape, " rank:", np.linalg.matrix_rank(X))
print("online + in-store - total:", X[:, 0] + X[:, 1] - X[:, 2])

U, s, Vt = np.linalg.svd(X, full_matrices=False)
print("singular values:", s.round(3))

# 2. The square matrix X^T X inherits the problem
G = X.T @ X
print("G.shape:", G.shape, " rank:", np.linalg.matrix_rank(G))
print(f"det(G) = {np.linalg.det(G):.1e}   cond(G) = {np.linalg.cond(G):.1e}")

# 3. Drop the redundant column
X3 = X[:, [0, 1, 3]]
G3 = X3.T @ X3
print("rank without total:", np.linalg.matrix_rank(X3))
print(f"det(G3) = {np.linalg.det(G3):.0f}   cond(G3) = {np.linalg.cond(G3):.0f}")

# 4. Low-rank approximations of the original table
share = s**2 / (s**2).sum()
for k in (1, 2):
    Xk = (U[:, :k] * s[:k]) @ Vt[:k]
    print(f"k={k}: keeps {share[:k].sum():.3%} of the squared singular values, "
          f"largest error {np.abs(X - Xk).max():.2f}")
    print(Xk.round(1))

Step 1. The table has four columns but rank 3, because total = online + in-store on every row. One column is a combination of the others, so the columns span only three directions and one singular value is zero.

Step 2. G is 4 × 4 with rank 3, so it is singular. Its determinant is zero up to rounding; the printed −1e-07 is noise next to entries in the thousands. The condition number of about 101710^{17}1017 means that up to 17 digits can be lost, more than the roughly 16 that double precision holds. A solver may raise an error or return huge meaningless numbers. In modelling terms, infinitely many weight vectors give identical predictions: add any amount to the online and in-store weights and subtract it from the total weight.

Step 3. Without the total column the rank equals the number of columns, the determinant is 453,441 and the condition number is about 16,000. Around four digits may be lost, which leaves plenty. The system now has one solution.

Step 4. Rank 1 keeps 98.876 % of the squared singular values with a largest error of 6.72. Rank 2 keeps 99.998 % with a largest error of 0.40.

Step 5. No. The rank-1 matrix says every day is the same day at a slightly different scale: it gives 13.3 online orders for day 4, where the table has 20, and 14.7 for day 3, where the table has 9. The 98.9 % mostly reflects the overall size of the numbers, since totals near 43 dominate the squares, and says little about how days differ. That is why PCA subtracts each column's mean before decomposing. The second component captures the trade-off between online and in-store orders, and with it every cell is within 0.4. Storage is k(m+n+1)=2×11=22k(m + n + 1) = 2 \times 11 = 22k(m+n+1)=2×11=22 numbers against 24 for the full table, so nothing is gained here. For 10,000 days and 400 columns the same rank would need 20,802 numbers instead of 4,000,000.
