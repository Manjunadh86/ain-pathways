Exploratory Data Analysis

Exploratory data analysis (EDA) is the habit of summarising and plotting a dataset before you model it. You compute a few statistics for every column, draw its distribution and its relationships with other columns, and use what you see to find data problems and to decide which models and features are worth trying.

1Overview

Why it matters

A training algorithm accepts any table of numbers. It will fit a column in which one value was typed in the wrong unit, a "missing" code such as −1 that it reads as a real measurement, or a column that was only filled in after the outcome was known, and it will report a metric at the end without complaint. The damage shows up later, as a model that is wrong for a whole group of cases or one that looks excellent in testing and fails in production.

EDA is the cheap check that catches these problems while they are still one line in a notebook. It is also where modelling choices get their reasons: a long-tailed target suggests a log transform, two features that move together warn that their coefficients will be unstable, a curved scatter plot rules out a straight line. Anyone who trains models, reviews someone else's model or signs off a dataset as fit for use needs to be able to run this first pass and write down what it showed.

What you will be able to do

  • Profile a table (size, types, missing values, duplicates, summary statistics) and read the result for impossible or suspicious values.
  • Read a histogram, a box plot and a scatter plot for skew, multiple peaks, outliers, curves and changing spread.
  • Compute quartiles, the interquartile range and box-plot fences by hand and confirm them with pandas.
  • Choose between Pearson and Spearman correlation and say what a gap between the two indicates.
  • Turn observations into a written list of data fixes and modelling hypotheses to test on a validation split.

Key terms

Median
The middle value when a column is sorted. Half the values lie below it and half above, and a few extreme values barely move it.
Quartiles and interquartile range (IQR)
The first and third quartiles (Q1, Q3) are the values below which 25 % and 75 % of the data fall. The IQR is Q3 minus Q1, the spread of the middle half.
Skew
Lopsidedness of a distribution. A right-skewed column has a long tail of large values, which pulls the mean above the median.
Outlier
A value far from most of the others in its column. It may be an error or a genuine extreme case, and only inspection can tell which.
Histogram
A bar chart that splits a column's range into equal-width bins and shows how many values fall in each bin.
Box plot
A drawing of a column's median and quartiles as a box, with whiskers for the rest of the range and separate points for values beyond the fences.
Pearson correlation
A number from −1 to +1 that measures how closely two columns follow a straight-line relationship.
Spearman correlation
Pearson correlation computed on the ranks of the values, which measures whether one column tends to rise as the other rises, in a straight line or not.

2Explanation

Introduction

You already do a small version of this. Before trusting a spreadsheet someone sent you, you scroll through it, sort a column to see its largest and smallest values, and notice the row where the date is in the wrong format. Exploratory data analysis is that instinct made systematic: every column gets the same questions, and the answers are written down.

Take sixteen flats advertised for rent, each with a floor area in square metres. The mean area is 104.6 m², which sounds like a list of large flats. The median, the middle value, is 62 m². A gap that size between two measures of "typical" is a question, and sorting the column answers it: fifteen flats are between 28 and 140 m², and one is recorded as 689. Somebody entered square feet. No model has been trained, and there is already a data problem to fix and a reason to distrust the mean. The worked example follows this dataset to the end.

Three kinds of tool do the work. Summary statistics are single numbers that describe a column, such as its mean, median, quartiles and count of missing values. A distribution is the way a column's values are spread out, and histograms and box plots draw it. Correlations and scatter plots describe how two columns move together. None of these is new if you have read statistics for ML. What EDA adds is an order in which to use them and a question to ask after each one: is this a problem with the data, or something the model should know about?

EDA sits between collecting and cleaning the data and engineering features, and it loops: a plot exposes a problem, you fix or flag it, and the summaries are recomputed. It produces two lists. One is of data fixes. The other is of modelling hypotheses, which are guesses to test on held-out data and not conclusions. The rest of this lesson covers what to compute, how to read the three basic plots, how a correlation coefficient can mislead, and how to turn what you see into hypotheses.

How it works

Analysis first, model second

The NIST/SEMATECH e-Handbook describes EDA as an approach, not a set of techniques (opens in a new tab): it postpones assumptions about which model the data follow and lets the data show their structure first, mostly through graphics. The handbook names John Tukey's 1977 book Exploratory Data Analysis as the seminal work. It also contrasts two orders of work (opens in a new tab). The classical order is problem, data, model, analysis, conclusions: a model is imposed and the analysis estimates its parameters. The exploratory order is problem, data, analysis, model, conclusions: the analysis comes first, with the goal of inferring which model would be appropriate. In machine learning that means looking before the first call to fit.

Explore only the rows you will train on. Set the test set aside first (see train/test splits), because every decision made after looking at a row has been influenced by that row. The scikit-learn example discussed below does exactly this (opens in a new tab).

Pass 1: structure and summary statistics

Start with facts about the table itself: how many rows and columns it has, the type of each column, how many values are missing and how many rows are exact duplicates. Then summarise each column. In pandas, DataFrame.describe() (opens in a new tab) returns the count of non-missing values, the mean, standard deviation, minimum, quartiles and maximum of every numeric column. With include="all" it also covers text columns, for which it returns the count, the number of distinct values and the most frequent one.

python
df.shape                    # (rows, columns)
df.dtypes                   # a number stored as text is already a finding
df.isna().sum()             # missing values per column
df.duplicated().sum()       # exact duplicate rows
df.describe()               # count, mean, std, min, 25%, 50%, 75%, max
df["city"].value_counts()   # each category and how often it occurs

Read the output as a list of questions.

  • A count below the number of rows. Values are missing. How many, and in which rows?
  • A minimum or maximum that cannot be true. An age of 150, a negative distance, or a placeholder such as −1 or 9999 standing in for "unknown".
  • A mean far from the median (the 50% row). The column is skewed or contains extreme values. They pull the mean and leave the median almost where it was.
  • Lopsided gaps. Google's ML Crash Course suggests comparing (opens in a new tab) the gap between the minimum and the 25th percentile with the gap between the 75th percentile and the maximum. When they differ greatly, the column probably contains outliers. The same page warns that anomalies can also hide behind statistics that look balanced.
  • A standard deviation of zero, or a single category. The column is constant and carries no information.
  • A category that appears only a few times, or the same category spelled two ways.

Pass 2: one column at a time

pandas draws every plot in this lesson directly from a DataFrame, as its chart visualization guide (opens in a new tab) shows:

python
df["rent"].plot.hist(bins=12)             # distribution of one column
df.boxplot(column="rent", by="rooms")     # one box per group
df.plot.scatter(x="area_m2", y="rent")    # two columns against each other
pd.plotting.scatter_matrix(df)            # every pair of numeric columns at once

A histogram divides a column's range into equal-width bins and draws a bar for the number of values in each. NIST lists what it shows (opens in a new tab): centre, spread, skewness, outliers and the presence of more than one mode (peak). The shape is the information. A long right tail is typical of prices, incomes and waiting times. Two peaks usually mean that two different groups have been mixed. A tall spike at one value is often a default or a placeholder. Bin width changes the picture, so try two or three widths before believing a shape.

A box plot reduces the same column to a few numbers. The box runs from the first quartile Q1Q_1Q1​ to the third quartile Q3Q_3Q3​ with a line at the median, so its length is the interquartile range, IQR=Q3−Q1\text{IQR} = Q_3 - Q_1IQR=Q3​−Q1​. The variant described by NIST (opens in a new tab) adds fences:

lower fence=Q1−1.5×IQR,upper fence=Q3+1.5×IQR\text{lower fence} = Q_1 - 1.5 \times \text{IQR}, \qquad \text{upper fence} = Q_3 + 1.5 \times \text{IQR}lower fence=Q1​−1.5×IQR,upper fence=Q3​+1.5×IQR

These are the inner fences. The outer fences use 3 in place of 1.5. Points between an inner and an outer fence are drawn one by one as mild outliers, and points beyond an outer fence as extreme outliers. A fence is a prompt to look at a row, not a rule for deleting it: in a skewed column, genuine values land outside. Box plots are most useful side by side, one per group, where a shift in level or spread between groups is visible at a glance.

Tools compute quartiles in slightly different ways. pandas interpolates linearly (opens in a new tab) between the two nearest sorted values, and this lesson does the same.

Pass 3: two columns at a time

A scatter plot puts one column on each axis and draws a point per row. NIST's list of questions it answers (opens in a new tab): are the two related, is the relationship a line or a curve, does the spread of yyy change with xxx, and are there outliers?

A correlation coefficient condenses a scatter plot into one number between −1 and +1. Pearson's rrr measures how close the points lie to a straight line:

r=∑(xi−xˉ)(yi−yˉ)∑(xi−xˉ)2 ∑(yi−yˉ)2r = \frac{\sum (x_i - \bar{x})(y_i - \bar{y})}{\sqrt{\sum (x_i - \bar{x})^2}\,\sqrt{\sum (y_i - \bar{y})^2}}r=∑(xi​−xˉ)2​∑(yi​−yˉ​)2​∑(xi​−xˉ)(yi​−yˉ​)​

Spearman's coefficient is Pearson's rrr computed on ranks (1 for the smallest value, 2 for the next, and so on) in place of the values. It measures whether yyy tends to rise as xxx rises, along a line or a curve, and one wild value can shift it only a little. DataFrame.corr() (opens in a new tab) computes Pearson by default and Spearman with method="spearman". Compute both. A large gap between them means a curve or an outlier, and the plot will say which.

The reason to plot every pair you care about is a set of four small datasets published by Anscombe and reproduced in the NIST handbook (opens in a new tab). All four have the same means, the same fitted line y=3+0.5xy = 3 + 0.5xy=3+0.5x and a correlation of 0.816 (0.817 for the fourth). Two of them are drawn below.

Read a correlation matrix in two directions. Feature against target shows which columns carry signal, and whether any looks too good. A feature that predicts the target almost perfectly is often a copy of the answer recorded after the event, which is called target leakage. The TensorFlow Data Validation guide lists labels treated as features (opens in a new tab) among the common data problems for that reason. Feature against feature shows redundancy: a pair near +1 or −1 carries the same information twice, which makes the coefficients of a linear model unstable. In neither direction does correlation show cause. NIST's wording is that causality implies association but association does not imply causality.

Then repeat the important plots within groups and over time. A relationship that holds overall can differ, or reverse, inside each group, and Google's guide to good data analysis (opens in a new tab) advises slicing by subgroup and by time for that reason.

Step 4: what goes in the notebook

Data fixes:

  1. Convert the 689 sq ft entry to 64 m², and ask whether other listings can arrive in square feet.
  2. One distance is missing. pandas left that row out of every correlation involving distance without saying so. Decide whether to look the value up or impute it.

Hypotheses to test on a validation split:

  1. Rent rises roughly in a straight line with area, the main driver.
  2. Rooms adds little once area is in the model. Compare models with and without it.
  3. Distance changes the price per square metre and not the rent directly. Try a model that can multiply the two, or a tree-based model.
  4. Rent is right-skewed (mean 906 against a median of 755). Compare predicting log rent with predicting rent.

Sixteen rows prove nothing about a rental market. The example shows the sequence: summarise, plot, read the flagged rows, correct on a copy, recompute, and write down what to test.

Edge cases and limitations

A histogram's shape depends on the bin width
Wide bins can merge two peaks into one, and narrow bins on a small sample create gaps that look like structure. Recomputing the NIST ceramic strength data from the first real-world example, 25-unit bins show two peaks with a dip between them, while 50-unit bins give counts of 90, 116, 97 and 97 from 550 to 750, a single broad hump. Draw two or three bin widths, and confirm a suspected second peak by splitting the data on a candidate grouping column.
Missing values stored as ordinary numbers
A placeholder such as −1, 0, 9999 or 1970-01-01 is not missing as far as pandas is concerned, so isna() reports nothing while the mean, the standard deviation and every correlation are distorted. In the first exercise a single −1 in the mileage column lowers the correlation between age and mileage from 0.965 to 0.857. Look for round or repeated-digit minimums and maximums and for a lone spike at the edge of a histogram, then convert the code to a real missing value.
Each cell of a correlation matrix can be based on different rows
DataFrame.corr() uses pairwise complete observations: for each pair of columns it drops only the rows in which one of those two values is missing. With many missing values, one coefficient may come from 5,000 rows and its neighbour from 900 rows of a different kind of customer. Before comparing coefficients, count the rows in which both columns are present, or set the min_periods argument so that pairs with too few rows come back empty.
A pattern in the whole dataset that reverses inside each group
When groups differ both in size and in level, the combined data can show a trend that is absent or opposite within every group (Simpson's paradox). Google's good data analysis guide warns about this when slices contain different amounts of data. If the data have an obvious grouping, such as region, product or device, redraw the key scatter plot and box plot per group before trusting the overall picture.
Too many rows to plot one point each
A scatter plot of millions of rows is a solid blob in which neither density nor outliers can be seen. Plot a random sample of a few thousand rows with partly transparent points, or use a two-dimensional histogram, and compute the summary statistics on the full data. A sample will miss rare events, so look at the extreme rows separately by sorting.

When to use it, and when something simpler is enough

Use it when

  • You have a dataset you did not create and are about to train a model on it. Profile it and plot it before choosing features or a model family.
  • A validation score is far better or far worse than expected. Check for a leaked column, duplicated rows across the split, or a feature whose distribution is not what you assumed.
  • The source of the data changes, such as a new upstream system, a new region or a new export. Re-run the same summaries and compare them with the old ones.
  • You must choose a transformation, an encoding or a way to fill missing values. The distribution of the column is the evidence for that choice.

Think twice when

  • You need a yes-or-no answer to a question fixed in advance, such as whether an A/B test moved a metric. Open-ended searching finds patterns by chance, so use a planned test and keep exploration for generating questions.
  • The dataset is a recurring batch you already understand. Replace repeated manual plotting with automated checks against recorded expectations, and return to plots when a check fails.

A simpler alternative. For a small, familiar table, three commands are often enough: the shape, the count of missing values per column and describe(). They take a minute and catch missing data, impossible ranges and constant columns. They stop being enough as soon as the question involves shape or relationships (two mixed groups, a curved relationship, a feature that leaks the target), because none of those can be read from one-column summary numbers. Then you need the plots.

Key takeaways

  • Exploratory data analysis means summarising and plotting the training data before modelling it, and it produces two lists, data fixes and modelling hypotheses.
  • Summary statistics find missing values, impossible ranges and skew quickly, but datasets with identical statistics can look completely different, so every important column and pair gets a plot.
  • A histogram shows the shape of one column, a box plot compares groups and flags values beyond the 1.5 IQR fences, and a scatter plot shows the form of a relationship between two columns.
  • A value outside the fences is a reason to read the row, because the same rule flags both errors and genuine extremes.
  • Pearson correlation measures straight-line association and is easily moved by one bad value, Spearman uses ranks, and a large gap between them means there is a curve or an outlier to find.
  • What exploration suggests is a hypothesis, to be confirmed on data that played no part in suggesting it.

Example 1 of 5

NIST ceramic strength study: a two-peaked histogram exposes an unexpected batch effect

NIST (National Institute of Standards and Technology)Documented in a case study

Section 1.4.2.10 of the NIST/SEMATECH e-Handbook of Statistical Methods is an EDA case study of data collected in 1996 by the NIST Ceramics Division for a NIST/industry consortium on ceramic strength. The cited pages give the background, the analysis of the response, the analysis of the batch factor and the analysis of the machining factors, and the data file is published with them. [14][15][16][17][18]

The problem

The experiment measured the strength of ceramic bars machined under different settings of table speed, down feed rate and wheel grit size. The goals were to find which machining factor affects strength most, to estimate the effects and to choose the best settings. The bars came from two batches of material and were tested in eight labs. Batch and lab were nuisance factors, which ideally would have little effect on the response.

Where this topic fits

The exploration comes before any estimate of the machining effects. The analysts first summarise and plot the response on its own, then split it by the nuisance factors. What they find at that stage changes the structure of everything after it: the analysis of the machining factors is run separately for each batch.

How it is applied, step by step

  1. Compute summary statistics for the 480 strength measurements: mean 650.08, median 646.63, standard deviation 74.64, range 345.29 to 821.65. The mean and median nearly agree, so nothing looks wrong yet.
  2. Draw the handbook's standard set of four plots for the response. The run-sequence and lag plots show no time effect. The histogram is roughly symmetric but has two peaks, and about half a dozen points between 300 and 450 stand out on the low side.
  3. Treat the two peaks as a sign that two populations are mixed, and split the data by the nuisance factors, starting with batch.
  4. Compare the batches with a bihistogram (two histograms back to back), a quantile-quantile plot and box plots. Batch 1 is centred near 700 and batch 2 near 625, with similar spread.
  5. Check with block plots that batch 1 is higher within every lab and factor setting, then confirm with an F-test (variances not significantly different) and a two-sample t-test (means differ).
  6. Carry the finding into the modelling step by analysing the machining factors separately for each batch. The ranking of the factors turns out to differ between the batches.

Why this approach fits

One-column summary numbers could not have found this. Two equal groups with similar spread and shifted centres produce a mean, median and standard deviation that look ordinary. Shape is what a histogram shows, and a level shift between groups is what side-by-side box plots show, so those were the tools that worked.

The case also shows the value of doing this before modelling. A single analysis of all 480 bars would have averaged two different rankings of the machining factors and reported effects that describe neither batch.

Limitation or tradeoff

The two peaks are visible only at a suitable bin width. Recomputing from the published data, 25-unit bins show a dip between the peaks, but 50-unit bins give counts of 90, 116, 97 and 97 across 550 to 750, one broad hump. An analyst who drew only the wider histogram could have missed the signal.

The exploration also shows that the batches differ without showing why. Nothing on the cited pages explains the cause, and an explanation would need knowledge of how the two batches of material were made.

What the sources document

  • The data were collected by Said Jahanmir of the NIST Ceramics Division in 1996 in connection with a NIST/industry ceramics consortium, and the case study uses the half of the data with the longitudinal direction, leaving three primary factors (table speed, down feed rate, wheel grit size) and two nuisance factors (lab and batch). [14]
  • For the response the page reports a sample size of 480, a mean of 650.0773, a median of 646.6275 and a standard deviation of 74.6383, and says the histogram shows a response that appears reasonably symmetric but with a bimodal distribution. [15]
  • The bihistogram shows batch 1 responses centred at 700 and batch 2 responses centred at 625, a batch effect of approximately 75 units. The batch means are 688.9987 and 611.1559 with 240 observations each, and the two-sample t statistic is 13.3806 against a critical value of 1.965. [16]
  • The page states that the batch effect was completely unexpected by the scientific investigators, and that the quantitative tests do not show subtler features of the data such as the outliers and the skewness of the batch 2 data. [16]
  • Because of the significant batch effect, separate plots are generated for batch 1 and batch 2 when the primary factors are analysed, and the page concludes that the most important factors differ from batch to batch: table speed ranks first for batch 1 and down feed for batch 2. [17]

The facts above come from the cited sources. The steps and analysis in this example are our explanation of how they fit together.

Example 2 of 5

Challenger O-ring history: a temperature plot that left out the flights with no damage

NASA and Morton Thiokol, as examined by the Rogers CommissionDocumented in a case study

Chapter VI of the Report of the Presidential Commission on the Space Shuttle Challenger Accident (the Rogers Commission) reviews how NASA and its contractor Thiokol assessed O-ring damage on earlier flights against joint temperature. The chapter reproduces the two plots discussed here as its Figures 6 and 7. [19]

The problem

On the night before the launch of flight 51-L, managers had to judge whether cold weather raised the risk that the O-ring seals in the solid rocket booster joints would fail. The evidence available was the record of earlier flights: for each one, the joint temperature at launch and whether the O-rings had shown thermal distress, defined in the report as erosion, blow-by or excessive heating.

Where this topic fits

This is a two-column exploratory question: is damage related to temperature? The tool is a plot of incidents against temperature. The Commission's criticism concerns a step that comes before the plot is drawn, the choice of which rows go into it.

How it is applied, step by step

  1. The comparison made before the launch plotted only the flights on which O-ring distress had been observed, against joint temperature.
  2. In that plot the damaged flights are spread across the range from 53 to 75 degrees Fahrenheit, so no pattern with temperature appears.
  3. The Commission redrew the plot with the entire flight history, adding the flights with no erosion or blow-by that the first comparison had left out.
  4. Counting by temperature band then gives 3 flights with distress out of 20 at 66 degrees or above, and 4 out of 4 at 63 degrees or below. It follows that all 17 undamaged flights were at the warm end.
  5. With every row included the relationship is plain, and the Commission concluded that distress became almost certain when the joint was colder than 65 degrees.

Why this approach fits

A plot of outcome against condition was the right tool, and it worked as soon as it was given all the rows. The lesson is about what has to be settled before plotting: the population. Rows in which nothing happened are data. Removing them removes the comparison group, and a relationship between a condition and an outcome can be seen only by comparing how often the outcome occurs under each condition.

Limitation or tradeoff

Even the complete plot is thin evidence. It covers 24 flights, only four of them cold, and none colder than 53 degrees, while the decision concerned a launch in conditions more extreme than any in the record. Exploration can show that distress became more frequent as temperature fell within the observed range. It cannot say how large the risk is outside that range. That is extrapolation, and no plot of past flights removes it.

What the sources document

  • The report states that the managers compared, as a function of temperature, the flights for which thermal distress of O-rings had been observed and not the frequency of occurrence based on all flights, and that in such a comparison nothing irregular appears in the distribution of distress between 53 and 75 degrees Fahrenheit. [19]
  • It states that when the entire flight history is considered, including normal flights with no erosion or blow-by, only three incidents of thermal distress occurred in twenty flights at 66 degrees Fahrenheit or above, whereas all four flights at 63 degrees or below experienced distress. [19]
  • Figure 6 is captioned as a plot of flights with incidents of O-ring thermal distress as a function of temperature, and Figure 7 as a plot of flights with and without incidents. [19]
  • Finding 6 of the chapter says that a careful analysis of the flight history of O-ring performance would have revealed the correlation of O-ring damage and low temperature, and that neither NASA nor Thiokol carried out such an analysis. [19]

scikit-learn's wage example: a pair plot decides the target transform and flags collinear features

scikit-learn projectDocumented in official docs

The scikit-learn documentation example "Common pitfalls in the interpretation of coefficients of linear models" builds a wage model on 534 records from the 1985 Current Population Survey, fetched from OpenML. Before fitting anything it explores the training rows, and the cited page shows the code, the plot and the conclusions drawn from it. [20]

The problem

The example sets out to predict hourly wage from education, experience, age and several categorical variables with a linear model, and then to interpret the coefficients. Two things about the data are unknown at the start: whether the target suits a linear model as it stands, and whether any features duplicate each other, which would make their coefficients unreliable.

Where this topic fits

The exploration sits between the train/test split and the definition of the pipeline. A describe(include="all") call summarises every column first. The data are then split, and a pair plot is drawn on the training rows only: a density curve for each variable on the diagonal and a scatter plot with a fitted line for each pair elsewhere. Its two observations become design decisions in the pipeline that follows.

How it is applied, step by step

  1. Summarise all columns with describe(include="all"). Every column has 534 values, three columns are numeric (EDUCATION, EXPERIENCE, AGE) and seven are categorical.
  2. Split into training and test sets before exploring, and plot only the training rows, so that decisions are not shaped by the test data.
  3. Draw a pair plot of WAGE and the numeric features with seaborn.
  4. Read the diagonal. The WAGE distribution has a long right tail, which leads to the hypothesis that the model should predict the logarithm of the wage.
  5. Read the other panels. WAGE rises with EDUCATION, and EXPERIENCE and AGE lie almost on a line, which leads to the hypothesis that those two features are collinear and their coefficients will be hard to separate.
  6. Act on both. The pipeline wraps the regressor so that it is trained on log10 of the wage. Later sections check coefficient stability across cross-validation folds, find AGE and EXPERIENCE unstable, and show the EXPERIENCE coefficient settling once AGE is dropped.

Why this approach fits

With four numeric columns, one figure shows every distribution and every pairwise relationship, so both questions are answered at a glance and before any model exists to be biased by the answers. Each observation maps directly to a modelling decision: a skewed target to a transformed target, and a pair of features on a line to a warning about coefficient interpretation that the rest of the example then verifies.

Limitation or tradeoff

A pair plot shows marginal relationships only. Each panel ignores the other variables, as the example itself notes for WAGE against EDUCATION, so a relationship seen there can shrink or change once other features are in the model. The plot also scales badly, since k numeric columns need k squared panels, and the seven categorical columns do not appear in it at all. Finally, a transformation chosen from the look of one density curve is still a hypothesis. It should be confirmed by comparing validation error with and without it.

Example 4 of 5

TensorFlow Data Validation at Google: summary statistics recomputed for every batch of training data

GoogleDocumented in a paper

TensorFlow Data Validation (TFDV) is the open-source library that implements the core techniques of the data validation system in TFX, Google's machine learning platform. Its documentation describes what it computes, and the paper "Data Validation for Machine Learning" (Breck and others, SysML 2019) describes the design of the system and its use in Google's production pipelines. [23][22][21]

The problem

A pipeline that retrains every day cannot wait for a person to look at a histogram of every feature before each run. The paper describes the kind of failure that only a look at the data would catch. A code change pins an integer feature to −1 for one slice of the serving data. The value is valid for its type, the model keeps predicting at lower accuracy for that slice, and the bad rows flow into the next day's training data.

Where this topic fits

TFDV turns the first pass of exploration into pipeline steps. Statistics are computed over each batch of data. A person explores them once, visually, and records what normal looks like as a schema. From then on, new batches are compared with the schema and with each other automatically, before training.

How it is applied, step by step

  1. Compute descriptive statistics for every feature over the whole dataset: which features are present and the shape of each one's value distribution. TFDV runs this on Apache Beam so that it scales to large datasets.
  2. Explore the statistics visually in a notebook with Facets Overview, looking for suspicious distributions: a feature where one value dominates, a feature spread as evenly as a row number, missing values, and features on very different scales.
  3. Infer a schema from the statistics: which features are expected, their types, how often each is present and the allowed values of categorical features.
  4. Have an engineer review and edit the inferred schema to add domain knowledge, and keep it under version control.
  5. For every later batch, recompute the statistics and validate them against the schema. A mismatch, such as a category value that the schema does not list, is reported as an anomaly before the data are used for training.
  6. Compare distributions between training and serving data (skew) and between consecutive days (drift), with a distance threshold set per feature.

Why this approach fits

The questions asked of a new dataset (which values are missing, what range and categories each column takes, whether its distribution looks right) are the same every day in a production pipeline. They can therefore be computed once per batch and compared with a recorded expectation. The human part of exploration is kept where it is needed: looking at the distributions the first time, and deciding what the schema should say.

Limitation or tradeoff

A schema encodes only what someone thought to check. The paper's own example, a feature pinned to −1 on one slice, passes a type check and a range check. Catching it needs a comparison of distributions with a sensible threshold, and the documentation says that choosing thresholds takes domain knowledge and experimentation. Per-feature statistics also say little about relationships between features. And the paper reports that on-call engineers tend to ignore alerts that are too frequent or not actionable. Automated validation narrows down where to look. It does not replace opening the rows.

What the sources document

  • The paper states that the system is deployed in production as an integral part of TFX, an end-to-end machine learning platform at Google, and is used by hundreds of product teams to continuously monitor and validate several petabytes of production data per day. [23]
  • The paper describes a workflow in which users obtain an initial schema through automatic inference, review and manually edit it, and commit it to a version control system. Its analysis of production use is based on a sample of more than 700 pipelines. [23]
  • In a case study the paper reports that Google Play, using the system, discovered a few features that were always missing from the logs but always present in training, and that an online A/B experiment showed that removing this skew improved the app install rate on the main landing page of the store by 2%. [23]
  • The TFDV documentation says the library computes descriptive statistics that give a quick overview of the features present and the shapes of their value distributions, uses Apache Beam to scale the computation over large datasets, can infer an initial schema, and strongly advises reviewing and refining the inferred schema. [22]
  • The TFX guide says that examining feature distributions in a notebook with Facets can catch common problems with data, and lists unbalanced features, uniformly distributed features, missing data and features that vary widely in scale among the things to look for. [21]

EPA CADDIS: scatter plots and rank correlations before relating stream stressors to biology

U.S. Environmental Protection AgencyDocumented in official docs

CADDIS is the EPA's Causal Analysis/Diagnosis Decision Information System, online guidance for identifying which stressors are responsible when the biology of a stream is in poor condition. Its page on exploratory data analysis describes how monitoring data should be examined before any formal analysis, illustrated with data from the EMAP-West Streams Survey. [24]

The problem

Biological monitoring data record, for each sampled site, measures of stream life such as mayfly richness, and many candidate stressors: nutrients, fine sediment, temperature and others. A site is almost always affected by several stressors at once, and the stressors are correlated with each other. An analysis that relates one stressor to the biological response while ignoring the others is confounded, meaning it credits one cause with an effect that may belong to another.

Where this topic fits

The page calls exploration the first step, before any regression of a biological response on a stressor. Distributions are checked first, then pairwise scatter plots and correlations, then multivariate views of how the stressors group together. The results decide which transformations and which statistical methods the later analysis uses.

How it is applied, step by step

  1. Examine each variable's distribution with histograms, box plots, cumulative distribution functions and Q-Q plots. Total nitrogen is far from normal on its raw scale and much closer after a log transform, so the log scale is used.
  2. Compare groups with side-by-side box plots, for example log total nitrogen in mountain, plains and xeric ecoregions.
  3. Draw scatter plots of response against stressor to see the form of each relationship. The capture probability of one caddisfly against stream temperature is curved, and the spread of mayfly richness narrows as fine sediment increases.
  4. Let those shapes choose the method: a quadratic or other non-linear form for a curve, and quantile regression or a generalised linear model where the variance is not constant.
  5. Compute correlations among the stressors, with Spearman's rank coefficient alongside Pearson's, because Pearson's understates a non-linear association and is affected by outliers.
  6. Use a scatter-plot matrix and clustering of the correlation matrix to find blocks of stressors that move together. Choose predictors that limit collinearity and treat correlated stressors as possible confounders.

Why this approach fits

The task is to attribute a cause from observational data, where the main danger is crediting one stressor with an effect that belongs to another that moves with it. Looking at the relationships among the predictors before relating any of them to the response makes that danger visible. The preference for a rank correlation is practical: environmental measurements are skewed and contain outliers, which are the conditions under which Pearson's coefficient misleads.

Limitation or tradeoff

Pairwise views cannot settle the question they raise. The page says that a scatter plot can examine only two variables at a time and that pairwise correlations may not provide enough insight, and it recommends multivariate methods. A correlation among stressors tells the analyst that their effects cannot be cleanly separated in these data. It does not say which stressor is responsible, and the page presents correlation as an exploratory technique that informs later analyses.

What the sources document

  • The page calls EDA an important first step in any data analysis and says that, because sites in biological monitoring data are likely to be affected by multiple stressors, initial exploration of stressor correlations is critical before attempting to relate stressor variables to biological response variables. [24]
  • It shows a histogram, box plots by ecoregion and Q-Q plots of total nitrogen from the EMAP-West Streams Survey, and states that the log transform greatly increases the degree to which the observed total nitrogen values approximate a normal distribution. [24]
  • It says scatter plots can show that a relationship is non-linear or that the variance is not constant, in which cases simple linear regression may not be appropriate, using capture probability of the caddisfly Calineuria against stream temperature and mayfly richness against percent substrate sand/fines as the examples. [24]
  • It describes Pearson's r as measuring the degree of linear association and Spearman's coefficient as using the ranks of the data and able to provide a more robust estimate, and notes that small Pearson coefficients may be due to a non-linear relationship. [24]
  • It says correlation can indicate possible factors that confound a relationship of interest, and that in regression analysis the study of associations among stressors may help in choosing a set of predictor variables that minimises the problem of collinearity. [24]

4Common mistakes

  1. Reading the correlation matrix and skipping the scatter plots.

    Why it causes problems
    A coefficient hides the shape of the relationship. One wrong value can erase a strong relationship (0.94 down to 0.11 in the worked example), a curve can be scored as a moderate straight line, and a value near zero can sit on top of a strong U-shaped pattern. Features then get dropped or trusted for the wrong reason.
    How to recognise it
    The Pearson and Spearman coefficients for the same pair clearly disagree, or a feature that domain knowledge says should matter shows a correlation near zero.
    How to fix it
    Plot every pair that involves the target, and every pair for which the two coefficients disagree. Use the matrix to decide where to look, not what to conclude.

  2. Deleting every value beyond the 1.5 IQR fences without reading the rows.

    Why it causes problems
    In a skewed column genuine values fall outside the fences. Removing them cuts off the large cases, such as the biggest flats or the highest-value customers, that the model will meet in production. It also hides errors that should have been traced to their source and fixed for every row.
    How to recognise it
    A cleaning step filters on a fence or a z-score with no note explaining what was removed. The row count drops by a few percent and the maximum of a price or duration column falls sharply.
    How to fix it
    Open the flagged rows. Correct the ones that are errors or convert them to missing, keep the ones that are real, and record the reason for each decision. If real extremes hurt the model, handle them with a transformation or clipping inside the modelling pipeline.

  3. Exploring the full dataset, including the rows held back for testing.

    Why it causes problems
    Every choice made after looking, such as which transformation to use, which features to keep and which rows to drop, has been tuned to the test rows as well. The final test score is then optimistic and no longer estimates performance on unseen data.
    How to recognise it
    The exploratory notebook loads the whole file and the train/test split happens further down, or plots are drawn from a DataFrame that still contains every row.
    How to fix it
    Split first and explore the training portion only, as the scikit-learn wage example does. Checks that do not involve the target, such as column types and duplicate rows, can still be run on the whole file.

  4. Filtering rows before plotting and then reading the plot as if it showed everything.

    Why it causes problems
    Dropping the rows in which the outcome did not occur removes the comparison group, so a real relationship disappears. This is the error the Rogers Commission identified in the comparison of O-ring damage and temperature made before the Challenger launch.
    How to recognise it
    A plot has fewer points than the table has rows and nobody can say which rows were excluded or why. Rows with a zero count or no event are absent.
    How to fix it
    State the population in the plot title, count the rows before and after every filter, and keep the rows in which nothing happened. A rate needs a denominator.

  5. Presenting a pattern found during exploration as an established result.

    Why it causes problems
    Exploration looks at many columns, pairs and subgroups, and some patterns appear by chance, especially in small samples. A feature or a business conclusion built on one of them fails to reproduce on new data.
    How to recognise it
    A claim rests on a single plot from the same data that suggested it, with no held-out check, or the subgroup it concerns was chosen after the result was seen.
    How to fix it
    Label exploratory findings as hypotheses and test each on data that played no part in finding it: a validation split for a modelling choice, a fresh sample or an experiment for a factual claim.

A good answer finds seven or eight issues: 650 missing loan amounts, an impossible maximum age, a placeholder of 9,999,999 in about 60 income rows, a −1 placeholder in months employed, a constant branch code, a column that leaks the target, and a target with only 3.7 % positives. It explains that a constant column has zero variance, so the correlation formula divides by zero, and that small correlations with a rare yes/no target do not rule a feature out.

Hint 1

Go through the rows of the table in order. Count first, then minimum and maximum, then compare the mean with the median.

Hint 2

A mean far above the 75th percentile means a few enormous values. Assume the ordinary rows average about the median and work out how many rows at the maximum would produce the reported mean.

Hint 3

For each column ask at what moment its value becomes known. Is that before or after the outcome you are predicting?

Hint 4

The mean of a column of zeros and ones is the share of ones.

How many placeholder incomes? Suppose the ordinary rows average about the median, 40,600, and kkk rows hold 9,999,999. The total must match the reported mean:

k≈(163714−40600)×50009999999−40600≈62k \approx \frac{(163714 - 40600) \times 5000}{9999999 - 40600} \approx 62k≈9999999−40600(163714−40600)×5000​≈62

So roughly 60 rows, a little over 1 % of the table, are enough to quadruple the mean. (The simulation planted exactly 60.) The median barely moves, which is why the 50% row is the one to trust here.

Why is the correlation for branch_code not defined? Pearson's formula divides by the spread of each column. A constant column has a spread of zero, so the result is 0 divided by 0. pandas shows it as NaN.

Are the weakly correlated columns useless? No. A target that is 1 in only 3.7 % of rows varies very little, so correlations with it are small even for features that matter, and Pearson's coefficient sees only straight-line effects on top of that. The income and months_employed coefficients were also computed with the placeholders still in the data. Better checks are the default rate within quartiles of each feature, box plots of each feature split by the target, and derived quantities such as loan amount divided by income.

What happens if nothing is fixed? A model trained on this table would lean on days_since_default_notice and report a near-perfect validation score. In production that column is always zero at the moment a prediction is needed, so the model would predict "no default" for everyone and still be 96.3 % accurate, which is why accuracy is the wrong measure here.

Check your answer

  • Did you notice the missing loan amounts from the count row alone, and compute 650 and 13 %?
  • Did you flag the income column because of the gap between its mean and median, and estimate about 60 placeholder rows?
  • Did you identify days_since_default_notice as leakage because of when it is recorded, not only because its correlation is high?
  • Can you explain why a constant column has no defined correlation with anything?
  • Did you state the share of defaults (3.7 %) and the accuracy a model would reach by always predicting no default (96.3 %)?
