Backpropagation

Backpropagation is the method that computes how a network's loss changes with every one of its weights. It applies the chain rule backwards, from the loss to the first layer, and reuses the values saved during the forward pass. Gradient descent then uses these slopes to update the weights.

1Overview

Why it matters

Training a network means nudging every weight in the direction that lowers the loss, and that direction is the gradient. A network can have millions or billions of weights. Estimating each slope by trying a small change costs about one extra evaluation of the model per weight; the automatic differentiation survey by Baydin and colleagues puts this at O(n) evaluations for n parameters. Backpropagation returns all the slopes from one backward pass. The survey says that computing the gradient this way costs a small constant multiple of evaluating the function once (the constant is below 6 and typically between 2 and 3). Training at current model sizes is practical because of that gap.

Many training problems that look mysterious are backpropagation problems. A loss stops moving because the signal reaching the early layers has shrunk to almost nothing. A loss turns into NaN because that signal grew without bound. A GPU runs out of memory because the forward values must be kept until the backward pass needs them. Half-precision gradients underflow to zero. A custom layer has a hand-written gradient that is slightly wrong. Anyone who trains models, debugs training runs or writes custom layers and losses needs the mechanism in this lesson, and the framework lessons that follow assume it.

Key terms

Gradient
The vector of partial derivatives of the loss with respect to every parameter; it points in the direction in which the loss rises fastest.
Chain rule
The rule that the derivative of a composed function is the product of the derivatives of its steps, each evaluated at the value that step received.
Computation graph
A directed graph in which each node is one operation or value and each arrow shows which values an operation used.
Forward pass
Evaluating the graph from inputs to loss, keeping the intermediate values that the backward pass will need.
Backward pass
Walking the graph from the loss back to the parameters, multiplying local derivatives to obtain the gradient of every parameter.
Error signal (delta)
The derivative of the loss with respect to a layer's pre-activation values, written as delta; it is the quantity that is passed backwards from layer to layer.
Reverse-mode automatic differentiation
The general technique of recording a program's operations and differentiating them in reverse order; backpropagation is its use on a neural network.
Vanishing gradient
A gradient that shrinks towards zero as it is passed back through many layers, so the early layers barely learn.
Exploding gradient
A gradient that grows exponentially as it is passed back through many layers, which can throw the weights far off or overflow to infinity.
Gradient clipping
Rescaling the gradient whenever its norm exceeds a threshold, so that one oversized gradient cannot cause an oversized update.

2Explanation

Introduction

You already know that a neural network is a stack of simple steps. Each layer multiplies its input by a weight matrix, adds a bias and passes the result through an activation function. The last step compares the output with the target and produces one number, the loss. Training means lowering that number, and the direction that lowers it fastest is the gradient: for every weight, how much the loss changes if that weight is nudged upwards by a tiny amount.

The difficulty is that most weights are not connected to the loss directly. A weight in the first layer changes the first layer's output, which changes the second layer's input, and so on until the loss. The chain rule from calculus (see calculus for ML) says that the effect of a chain of steps is the product of the effects of its links. Think of a row of gears: the speed of the last gear per turn of the first is the product of the ratios of each pair. Backpropagation is the bookkeeping that applies this product to every weight at once, without repeating work.

It runs in two passes. The forward pass computes the layers in order, from the input to the loss, and keeps the intermediate values. The backward pass starts at the loss with the trivial fact that the loss changes by one unit per unit change in itself, then walks back one step at a time. At each step it multiplies the sensitivity it is carrying by that step's local derivative, which is cheap because the forward pass already stored the values that derivative needs. Wherever a step has weights, the sensitivity arriving there, combined with the stored input, is the weight's gradient.

The rest of the lesson covers the layer-by-layer equations, how frameworks generalise them into automatic differentiation, why repeated multiplication makes gradients vanish or explode in deep networks, and what the backward pass costs in memory and numerical precision. The chain rule, run backwards

From layers to computation graphs

Real models are not tidy stacks, so frameworks work on a computation graph: one node per operation, arrows from the values an operation read to the value it produced. During the forward pass the framework records, for each operation, what it needs to turn a gradient on its output into gradients on its inputs. The backward pass then visits the nodes in reverse order. Two rules cover every graph shape.

  • Locality. A node needs only its own derivative and the gradient handed back by the nodes that used its output. It knows nothing about the rest of the network (CS231n).
  • Branches add. If a value is used by two later operations, the gradients arriving along the two paths are summed. In the example from the Calculus on Computational Graphs (opens in a new tab) post, e=(a+b)(b+1)e = (a + b)(b + 1)e=(a+b)(b+1) at a=2a = 2a=2, b=1b = 1b=1, the value bbb feeds both c=a+b=3c = a + b = 3c=a+b=3 and d=b+1=2d = b + 1 = 2d=b+1=2, so ∂e/∂b=2⋅1+3⋅1=5\partial e / \partial b = 2 \cdot 1 + 3 \cdot 1 = 5∂e/∂b=2⋅1+3⋅1=5. In code this is grad += ..., never grad = ....

This is reverse-mode automatic differentiation. PyTorch records operations as the code runs and rebuilds the graph on every iteration. TensorFlow's tf.GradientTape records operations on a tape and replays it in reverse. JAX's jax.grad turns a Python function that returns a scalar into a function that returns its gradient. Backpropagation is the special case in which the function is a network's error as a function of its weights.

Reverse mode is chosen because of the shape of the problem. Forward mode carries the derivative of every value with respect to one input, so a gradient over nnn parameters needs nnn passes. Reverse mode carries the derivative of one output with respect to every value, so a scalar loss needs one. The JAX documentation states the rule of thumb: forward mode suits Jacobians with few inputs and many outputs, reverse mode suits many inputs and few outputs, which is the training case. The price is storage, because reverse mode must keep the intermediate values, in the worst case in proportion to the number of operations.

Why gradients vanish or explode

Unrolling the second equation shows that the signal reaching layer lll is a product with one factor per layer it has crossed. Take the simplest picture: every layer contributes about the same factor r=w f′(z)r = w\,f'(z)r=wf′(z). Then the signal kkk layers back from the output has size about rkr^krk, which is exponential in depth.

The sigmoid's slope is σ′(z)=σ(z) (1−σ(z))\sigma'(z) = \sigma(z)\,(1 - \sigma(z))σ′(z)=σ(z)(1−σ(z)), which never exceeds 1/41/41/4. A stack of sigmoid layers with weights of size about 1 therefore has r≤0.25r \le 0.25r≤0.25, and ten layers shrink the signal by 4−10≈10−64^{-10} \approx 10^{-6}4−10≈10−6. The layers near the input then receive almost no signal and learn very slowly: a vanishing gradient. When the weights are large enough that r>1r > 1r>1 the signal grows instead: an exploding gradient, where one update can throw the weights far away or overflow to infinity. In a real layer the scalar rrr becomes the size of a matrix. For recurrent networks, Pascanu, Mikolov and Bengio show that the matter is governed by the largest eigenvalue λ1\lambda_1λ1​ of the recurrent weight matrix compared with 1/γ1/\gamma1/γ, where γ\gammaγ bounds the activation's slope (1 for tanh, 1/4 for the sigmoid): λ1<1/γ\lambda_1 < 1/\gammaλ1​<1/γ is sufficient for vanishing, and λ1>1/γ\lambda_1 > 1/\gammaλ1​>1/γ is necessary for exploding.

The standard remedies each get a lesson of their own; here is what each does to the product.

  • Activations with a healthy slope. The slope of ReLU is 1 for positive inputs, so it does not shrink the signal on the units that are active (and passes nothing on the others).
  • Scale-aware initialisation. Glorot and Bengio, and He and colleagues, choose the initial weight variance from the layer's width so that the signal keeps its size from layer to layer. For ReLU networks He et al. derive a variance of 2/n2/n2/n for fan-in nnn.
  • Skip connections and normalisation. For y=x+F(x)y = x + F(x)y=x+F(x) the derivative is I+∂F/∂xI + \partial F / \partial xI+∂F/∂x, so the identity path keeps a factor of 1 in the product. Normalisation layers rescale the values at every layer, which helps keep the per-layer factor from drifting far from 1. See training deep networks.
  • Gradient clipping for explosions: if the gradient's norm exceeds a threshold, rescale it to the threshold, keeping its direction.

What the backward pass costs

Because the weight gradients need the forward activations, a training step keeps every layer's activations in memory until the backward pass reaches that layer, so activation memory grows with depth and batch size. Checkpointing trades recomputation for this memory (example 2 below). PyTorch also accumulates gradients into each parameter's .grad rather than overwriting them, so a training loop must clear them every step. When a custom layer or loss is involved, compare its gradient with a finite difference once, as the worked example does.

python
import math

def sigmoid(z):
    return 1.0 / (1.0 + math.exp(-z))

x, t = [1.0, 0.5], 1.0
W1, b1 = [[0.2, -0.3], [0.4, 0.1]], [0.1, -0.2]
W2, b2 = [0.5, -0.6], 0.3

def forward(W1, b1, W2, b2):
    a1 = [sigmoid(sum(W1[j][i] * x[i] for i in range(2)) + b1[j]) for j in range(2)]
    a2 = sigmoid(sum(W2[j] * a1[j] for j in range(2)) + b2)
    return a1, a2, 0.5 * (a2 - t) ** 2

a1, a2, loss = forward(W1, b1, W2, b2)

# backward pass, following the tables
delta2 = (a2 - t) * a2 * (1 - a2)
gW2 = [delta2 * a1[j] for j in range(2)]

print(f"loss {loss:.4f}  delta2 {delta2:.4f}  delta1 {delta1[0]:.5f} {delta1[1]:.5f}")
print("gW2", [round(g, 4) for g in gW2], " gW1", [[round(g, 5) for g in row] for row in gW1])

Edge cases and limitations

Activation memory grows with depth and batch size
The backward pass needs the forward values, so a training step stores the activations of every layer until the gradient reaches them. PyTorch frees the graph's buffers after backward() unless retain_graph=True is passed. Memory is the first limit on depth and batch size; checkpointing recomputes activations instead of storing them, at the price of an extra forward pass.
Some operations pass back zero or no gradient
A max operation routes the gradient only to the input that was largest, and a ReLU unit whose input is negative passes nothing back, so a unit that stays negative for every example stops learning. Rounding, argmax and integer-valued operations have no useful derivative at all. TensorFlow returns None for a gradient through integer types or through code that runs outside the framework. If a parameter's gradient is None or exactly zero, look for a break in the graph before touching the learning rate.
Shared values collect gradients from every use
A weight used at several positions (a convolution filter, a recurrent weight matrix) or a value that feeds a skip connection receives one contribution per use, and the contributions are summed. This is correct, but it is why recurrent networks multiply the same matrix many times in the backward pass and are especially prone to vanishing and exploding gradients.
Saturated units and half precision shrink the signal numerically
When a sigmoid or tanh input is large in magnitude the slope is close to zero, so almost nothing flows back through that unit even though the mathematics is exact. In float16 the problem is sharper: values below about 6e-8 are not representable and become zero. A mathematically correct backward pass can therefore lose gradients to rounding; loss scaling (example 3) exists for this reason.
A correct backward pass can still differentiate the wrong loss
Backpropagation returns the exact gradient of whatever loss the code computes. If the loss uses the wrong target, a bug in a custom layer, or an operation applied outside the graph, the gradients are faithfully wrong and nothing raises an error. A finite-difference check on a few parameters, using float64 and a small input, catches a wrong custom gradient. It cannot catch a wrong loss definition.

When to use it, and when something simpler is enough

Use it when

  • You need the gradient of one scalar loss with respect to a large number of parameters, from thousands to billions. Reverse mode returns them in one backward pass at a small constant multiple of the forward cost.
  • The model is built from operations that are differentiable almost everywhere (matrix products, smooth activations, ReLU, normalisation) and is trained with a gradient-based optimiser such as SGD or Adam.
  • You are debugging training. Per-layer gradient norms are the first diagnostic for a loss that stalls, oscillates or turns NaN, because they show where the signal dies or blows up.

Think twice when

  • The objective is not differentiable with respect to the parameters, for example it depends on a discrete choice, a simulator or an argmax. Use a gradient-free method, or a reformulation such as a policy-gradient estimator.
  • The function has few inputs and many outputs. Forward mode needs one pass per input, so it costs less than reverse mode when inputs are fewer than outputs.
  • Activation memory does not fit even at batch size one. Add checkpointing, or shrink the model, before concluding that backpropagation cannot be used.

A simpler alternative. You rarely write backpropagation yourself: PyTorch, TensorFlow and JAX derive it from the forward code, so the choice is between those and hand-written derivatives. Hand-derived gradients, or finite differences with about n function evaluations, are enough for models with a handful of parameters and for gradient checks. A closed-form solution such as the normal equations of linear regression needs no gradient at all.

Key takeaways

  • Backpropagation is the chain rule applied in reverse order. It starts with a derivative of 1 at the loss, multiplies by each step's local derivative while moving back, and reads off each parameter's gradient where it enters.
  • One backward pass yields the gradient for every parameter at a small constant multiple of the forward cost, whereas finite differences need about one extra evaluation per parameter.
  • The price of the backward pass is memory, because forward activations are kept until they are needed; checkpointing trades recomputation for that memory.
  • Frameworks generalise backpropagation to automatic differentiation over a computation graph, in which each operation supplies its own local derivative and gradients are summed wherever a value is used twice.
  • The backward signal is a product with one factor per layer, so it shrinks or grows exponentially with depth. A sigmoid's slope is at most 0.25, which makes shrinking the default, and initialisation, activation choice and clipping are the standard remedies.
  • Check a hand-written gradient against a finite difference, and treat a gradient that is None, zero or NaN as a sign of a broken graph, a dead unit or a numerical limit.

PyTorch autograd: a graph recorded on every forward pass and replayed by backward()

PyTorchDocumented in official docs

PyTorch's "Autograd mechanics" note (documentation version 2.14) and its tutorial "Automatic Differentiation with torch.autograd" describe how each PyTorch training step records operations and then runs backpropagation with a single call. [1][2][4]

The problem

A deep learning framework has to give researchers the gradient of an arbitrary program, including programs with Python loops and if statements whose shape differs from one step to the next, without asking them to write derivative code, and without holding more in memory than the backward pass needs.

Where this topic fits

Between the forward computation and the optimiser. Parameters are leaf tensors with requires_grad=True. The forward pass is ordinary Python, and each tensor operation that touches a tracked tensor records a graph node. loss.backward() walks that graph from the loss to the leaves, applying the chain rule, and accumulates the results in each leaf's .grad. The optimiser then reads .grad.

How it is applied, step by step

  1. Mark the parameters as leaf tensors that need gradients with `requires_grad=True`, which `nn.Parameter` sets for you. Only leaf tensors with this flag end up with a value in `.grad`.
  2. Run the forward pass as plain Python. Every operation with at least one tracked input records a node, and its output carries a `grad_fn`, the entry point into the graph. Operations also save what their backward formula needs; for x squared the saved tensor is x.
  3. Because the graph is built while the code runs, an `if` or a loop that behaves differently on the next iteration simply produces a different graph.
  4. Call `loss.backward()`. Autograd evaluates the graph from the loss (the root) to the leaves with the chain rule, one vector-Jacobian product per node, and adds each leaf's gradient into its `.grad`.
  5. After `backward()` the graph's buffers are freed by default, and `retain_graph=True` keeps them for a second backward call. Because `.grad` accumulates, a typical training loop calls `optimizer.zero_grad()` before the next backward pass, as the loops in PyTorch's mixed-precision examples do.

Why this approach fits

Recording during execution makes the framework differentiate exactly the program that ran, so models with data-dependent control flow, such as variable-length sequences, need no special handling. Reverse mode matches the training case of one scalar loss and a very large number of parameters, where it returns every gradient in one sweep.

Limitation or tradeoff

The recorded graph and the saved tensors stay in memory until backward() consumes them, so deep models are limited by activation memory (see the next example). In-place operations can overwrite a value that the backward pass needs; PyTorch tracks this with a version counter on each tensor and raises an error when the saved version no longer matches. Gradients accumulate, so a missing reset silently sums gradients across steps.

What the sources document

  • The autograd mechanics note says the graph is recreated from scratch at every iteration, which is what allows arbitrary Python control flow that changes the shape and size of the graph from one iteration to the next. [1]
  • The backward pass evaluates the recorded graph with the chain rule. Each tensor that requires gradients has a grad_fn that is an entry point into the graph, and during backward only leaf tensors with requires_grad=True have gradients accumulated into their .grad fields. [1]
  • Some operations save tensors for the backward pass (the note's example is that squaring saves its input), and every tensor has a version counter that in-place changes increment, so a mismatch between saved and current versions raises an error. [1]

Activation checkpointing: recomputing activations to train deeper networks in the same memory

Chen et al. (2016) and PyTorchDocumented in a paper

The paper "Training Deep Nets with Sublinear Memory Cost" (Chen, Xu, Zhang and Guestrin, 2016) and PyTorch's torch.utils.checkpoint documentation describe dropping activations during the forward pass and recomputing them during the backward pass. [11][5][13]

The problem

Backpropagation needs each layer's forward activations at the moment the gradient reaches that layer. For an n-layer network, keeping all of them costs memory proportional to n, and on a GPU that memory often limits how deep a model or how large a batch can be, before parameter count or compute does.

Where this topic fits

Inside the forward and backward passes, wherever stored activations would otherwise pile up. The network is cut into segments. The forward pass keeps only the input of each segment, and the backward pass re-runs one segment's forward computation just before backpropagating through it.

How it is applied, step by step

  1. Split the n layers into segments, for example about the square root of n segments of about the square root of n layers each.
  2. Run the forward pass but keep only each segment's input, called a checkpoint, and free the activations inside the segments.
  3. In the backward pass take the last segment first. Re-run its forward computation from its checkpoint with gradient tracking, backpropagate through it, then free those activations.
  4. Repeat for the earlier segments, handing the gradient on each segment's input to the segment before it.
  5. A typical implementation holds only the checkpoints plus one segment's activations at a time, roughly n/k + k stored layer outputs for segments of k layers, which is smallest at k equal to the square root of n. Every layer is computed twice, which is about one extra forward pass.

Why this approach fits

The backward pass visits layers in strict reverse order and needs each layer's activations only briefly, so they can be rebuilt from a nearby checkpoint when their turn comes. The cost is bounded, about one extra forward pass, and in exchange memory grows with the square root of depth instead of linearly.

Limitation or tradeoff

The extra forward pass is real time; the authors report about 30 percent more running time in their ImageNet experiment. The recomputation must reproduce the original values, so PyTorch preserves the random-number state by default so that operations such as dropout behave identically, at a performance cost. The documentation recommends the non-reentrant variant, and the older reentrant variant has restrictions such as needing at least one input that requires gradients. Checkpointing only helps when activations are what fills the memory.

What the sources document

  • The paper's algorithm needs O(sqrt(n)) memory to train an n-layer network at the cost of one extra forward pass per mini-batch, and in an extreme case memory can fall to O(log n) with O(n log n) extra forward computation. [11]
  • The abstract reports that on ImageNet with a 1,000-layer deep residual network, memory use fell from 48G to 7G with about 30 percent additional running time. [11]
  • PyTorch's documentation says activation checkpointing trades compute for memory: intermediate activations are not kept alive during the forward pass, the inputs are saved, and the activations are recomputed during backward as needed. [5]
  • The PyTorch documentation recommends use_reentrant=False and asks for the argument to be passed explicitly. By default checkpointing preserves the random-number state, which has a performance cost, and preserve_rng_state=False turns that off. [5]
  • The automatic differentiation survey notes that reverse-mode storage grows, in the worst case, in proportion to the number of operations, and names checkpointing as a way to balance time against space by not storing the full tape of intermediate variables. [13]

Loss scaling: keeping small gradients representable in float16 training

NVIDIA and PyTorchDocumented in official docs

NVIDIA's "Train With Mixed Precision" guide, the paper "Mixed Precision Training" (Micikevicius et al.) and PyTorch's automatic mixed precision documentation describe scaling the loss so that the backward pass does not lose small gradients in half precision. [15][14][3][4]

The problem

Float16 cannot represent very small magnitudes. NVIDIA's guide gives the smallest normalised value as 2^-14 (about 6.1e-5) and the smallest denormal as 2^-24 (about 6e-8). In a deep network many gradients computed in the backward pass fall below that and become exactly zero, so part of the gradient disappears and training can stall or diverge, although the mathematics of backpropagation is intact.

Where this topic fits

Around the backward pass. The loss is multiplied by a factor S before backward(), which scales every gradient by S because the backward pass is linear in the gradient it starts from. The weight gradients are divided by S again before gradient clipping and the optimiser update.

How it is applied, step by step

  1. Run the forward pass in float16 where that is safe (autocast) and keep float32 master copies of the weights, as Micikevicius et al. recommend.
  2. Multiply the loss by S and call `backward()`. S starts large; the PyTorch GradScaler constructor shows 65,536 as its initial scale. By the chain rule every gradient on the way back is S times larger, which lifts small values into float16's representable range.
  3. Check the weight gradients for inf or NaN. If any appear, S was too large, so reduce S and skip this weight update (NVIDIA's dynamic algorithm).
  4. Otherwise divide the gradients by S so that clipping, the learning rate and weight decay act on the true gradient. In PyTorch `scaler.unscale_(optimizer)` does this explicitly before `clip_grad_norm_`.
  5. Take the optimiser step. After a run of steps without overflow, increase S again; NVIDIA reports success with doubling after N = 2000 clean iterations and halving on overflow.

Why this approach fits

Backpropagation is linear in the gradient it starts from, so replacing the starting 1 by S multiplies every downstream gradient by S, and dividing by S afterwards restores them. With S a power of two the scaling only changes exponents, so it adds no rounding error unless a value overflows. A dynamic S finds the largest safe factor during training, so it does not have to be tuned per network.

Limitation or tradeoff

S has to be large enough to prevent underflow and small enough that the largest gradient does not overflow float16, whose maximum is 65,504. Steps with overflow are skipped, so the first iterations of a dynamic scaler can waste updates while S settles. Scaling shifts the whole range but cannot widen it: a model whose gradients span more than float16's range of about 40 powers of two will still lose some values at the small end.

What the sources document

  • NVIDIA's guide says float16 represents normalised magnitudes down to 2^-14 and denormals down to 2^-24. For activation gradients of the Multibox SSD detector it reports that, converted to float16, 31% of the values become zeros and only 5.3% remain nonzero, and that the remaining values lead to divergence during training for this network. [15]
  • For that network, shifting the gradients by three exponent values (multiplying by 8) was enough to match float32 accuracy, and the guide says that shifting by 15 (multiplying by 32K) would recover all but 0.1% of the values lost to zero and still avoid overflow. [15]
  • The guide's dynamic loss scaling starts with a large S, scales the loss before backpropagation, checks the weight gradients for inf or NaN, reduces S and skips the update on overflow, and raises S after N iterations without overflow; it reports success with N = 2000, a factor 2 up and a factor 0.5 down. The weight gradient is multiplied by 1/S before the update. [15]
  • The paper by Micikevicius et al. stores weights, activations and gradients in half precision, keeps a single-precision copy of the weights that accumulates the gradients after each optimiser step, and scales the loss to handle the loss of information in half-precision gradients. [14]
  • PyTorch's documentation says small gradient values may not be representable in float16, and that GradScaler multiplies the loss by a scale factor, unscales before the optimiser step and adjusts the factor dynamically. The examples page says gradients must be unscaled with scaler.unscale_(optimizer) before clip_grad_norm_, because otherwise the clipping threshold would apply to scaled values. [3][4]

Gradient norm clipping: stopping exploding gradients in recurrent networks

Pascanu, Mikolov and Bengio (2013), and PyTorchDocumented in a paper

Pascanu, Mikolov and Bengio analyse the vanishing and exploding gradient problems of recurrent neural networks and propose clipping the gradient's norm. PyTorch documents torch.nn.utils.clip_grad_norm_, a standard implementation of the same idea. [12][6]

The problem

A recurrent network applies the same weights at every time step, so backpropagation through time multiplies one Jacobian per step, each built from the same recurrent matrix. When their effective size exceeds 1 the gradient grows exponentially with the sequence length, and one update can move the parameters far outside the region where the model works.

Where this topic fits

Between the backward pass and the optimiser step. Backpropagation through time produces gradients for all parameters. Clipping then measures the norm of the whole gradient and, only if it exceeds a threshold, scales it down to that norm without changing its direction. The normal update follows.

How it is applied, step by step

  1. Unroll the recurrent network over T time steps, run the forward pass and compute the loss.
  2. Run backpropagation through time. The gradient reaching an early time step is a product with one Jacobian per intervening step, so its size can grow exponentially with the distance.
  3. Treat all parameter gradients as one vector and compute its norm.
  4. If the norm is at least the threshold, multiply the gradient by the threshold divided by the norm. Otherwise leave it unchanged. This is Algorithm 1 of the paper.
  5. Apply the usual SGD or Adam update with the clipped gradient. The direction is preserved and the length of the step is bounded.
  6. Choose the threshold from data. The authors suggest looking at the average gradient norm over a large number of updates.

Why this approach fits

Near a place where the gradient explodes, its direction is still informative but its length is not. Clipping keeps the direction and caps the step. The paper's geometric picture is a valley with a steep wall: a small step along the gradient pushes back into the smoother region beside the wall, while an unclipped step would jump far away.

Limitation or tradeoff

Clipping addresses explosions only. It does nothing for vanishing gradients, which the paper handles with a separate soft constraint, a regulariser that penalises the backpropagated error for changing its norm from one time step to the next. It adds a threshold hyperparameter, and too small a threshold makes every step the same length and slows learning, although the authors say training is not very sensitive to it. Under mixed precision the gradients must be unscaled before clipping, as in the previous example.

What the sources document

  • Pascanu and colleagues call the vanishing and exploding gradient problems two widely known issues in training recurrent networks, and analyse them from analytical, geometrical and dynamical systems viewpoints. [12]
  • They show that the gradient is a product of Jacobians. With gamma bounding the activation's slope (1 for tanh, 1/4 for the sigmoid), a largest absolute eigenvalue of the recurrent matrix below 1/gamma is sufficient for the gradient to vanish, and above 1/gamma is necessary for it to explode. [12]
  • Algorithm 1 replaces the gradient by threshold divided by its norm, times the gradient, when the norm is at least the threshold. The authors say that for a given task and model size training is not very sensitive to the threshold and suggest looking at the average norm over many updates. [12]
  • They report experiments on a synthetic temporal order task, polyphonic music prediction and character-level language modelling. On the temporal order task, plain SGD and SGD with clipping alone could not solve sequences longer than 20 steps, while clipping together with their regulariser for vanishing gradients solved them up to 200 steps. On the music and language tasks, clipping improved on plain SGD. [12]
  • PyTorch's clip_grad_norm_(parameters, max_norm, norm_type=2.0, ...) computes the norm over the gradients of all parameters as if they were concatenated into one vector, rescales them in place and returns the total norm. [6]

Variance-preserving initialisation: training a 30-layer rectifier network from scratch

He et al. (2015) and PyTorchDocumented in a paper

He, Zhang, Ren and Sun's paper "Delving Deep into Rectifiers" (2015) derives an initialisation for ReLU networks and tests it against Glorot and Bengio's earlier scheme on very deep models. PyTorch's torch.nn.init documentation provides both as xavier and kaiming functions. [16][7][17]

The problem

Before any learning, the random weights decide whether the signal, and the gradient on its way back, shrinks or grows by a roughly constant factor per layer. Over 30 layers a factor of 0.9 per layer compounds to about 0.04 and a factor of 1.1 to about 17 (our arithmetic). With gradients that small or large at the start, training may never get going.

Where this topic fits

At model construction, before the first forward pass. Each layer's weights are drawn from a zero-mean Gaussian whose variance is set from the layer's width: fan-in for the forward signal, fan-out for the backward one. The aim is a signal of the same size in every layer.

How it is applied, step by step

  1. For each layer take its fan-in n, the number of inputs each unit receives.
  2. Note that a ReLU zeroes about half of its inputs, which roughly halves the variance of the signal. To compensate the weights need variance 2/n, the result the paper derives for rectifier networks. Glorot's rule, which assumes linear units, uses 1/n.
  3. Draw the weights from a zero-mean Gaussian with standard deviation sqrt(2/n). In PyTorch this is `kaiming_normal_` with `mode='fan_in'`.
  4. To keep the magnitudes of the backward pass instead, use `mode='fan_out'`; the paper shows that either condition alone is sufficient.
  5. Train as usual. In the paper's 30-layer experiment this initialisation converged while Xavier initialisation stalled completely.

Why this approach fits

The vanishing and exploding behaviour in this lesson comes from a product with one factor per layer. At the start of training, initialisation is the only lever that sets the average size of those factors, and it costs nothing at run time. Setting it from the layer width keeps the factor near 1 whatever the width is.

Limitation or tradeoff

The derivation assumes rectifier units and independent weights, and it fixes only the starting point, because training moves the weights away from it. In the paper the 22-layer model converged under both schemes, so the difference grows with depth. Modern architectures add normalisation layers and skip connections, discussed in the training-deep-networks lesson, that change how much depends on the initial scale.

What the sources document

  • The paper derives, for rectifier networks, a zero-mean Gaussian initialisation with standard deviation sqrt(2/n_l), and contrasts it with the Xavier rule, which assumes linear activations. [16]
  • The authors state that it is sufficient to use either the forward-propagation condition or the backward-propagation condition alone. [16]
  • In the very deep experiments both initialisations converge for a 22-layer model, with the proposed one faster, while for a 30-layer model the proposed initialisation converges and Xavier initialisation completely stalls, with diminishing gradients observed. [16]
  • PyTorch's kaiming_normal_ draws from a normal distribution with standard deviation gain/sqrt(fan_mode); mode 'fan_in' preserves the magnitude of the variance of the weights in the forward pass and 'fan_out' preserves the magnitudes in the backward pass. xavier_normal_ uses a standard deviation of gain times sqrt(2/(fan_in + fan_out)). [7]
  • The Glorot and Bengio abstract says the logistic sigmoid is unsuited to deep networks with random initialisation because of its mean value, that it can drive the top hidden layer into saturation, and that they propose an initialisation scheme with substantially faster convergence. [17]

4Common mistakes

  1. Not clearing gradients between training steps

    Why it causes problems
    PyTorch adds every backward pass into each parameter's .grad instead of overwriting it, so unreset gradients sum across mini-batches. The effective step grows with every iteration and mixes old batches into the new one, so the loss behaves erratically or diverges although each line of the loop looks right.
    How to recognise it
    The gradient norm of a parameter grows from step to step with no relation to the loss. Printing .grad.norm() at the start of each step shows a non-zero value left over from the previous step.
    How to fix it
    Call optimizer.zero_grad() (or set the gradients to None) before each backward pass. If you want to accumulate on purpose over several micro-batches, do it for a fixed number of micro-batches, then step once and reset.

  2. Clipping or logging gradients that are still multiplied by the loss scale

    Why it causes problems
    With mixed precision the gradients after backward() are S times their true size. A clipping threshold meant for true gradients then clips almost every step to the threshold, and the later division by S shrinks the update by roughly the scale factor, so training barely moves after AMP is switched on.
    How to recognise it
    Training stalls only when the scaler is enabled alongside clipping, and the gradient norm that clip_grad_norm_ returns is in the thousands and tracks the scale value.
    How to fix it
    Call scaler.unscale_(optimizer) before clip_grad_norm_ and before logging gradient norms, then scaler.step(optimizer) and scaler.update(), as in PyTorch's mixed-precision examples.

  3. Trusting a hand-written backward pass without a numerical check

    Why it causes problems
    A missing transpose, a wrong sign, or forgetting that a value is used twice does not raise an error. The loss may still decrease slowly on easy data, and the bug shows up much later as a model that underperforms for no obvious reason.
    How to recognise it
    Compare the analytic gradient with a central finite difference on a tiny input in float64. A correct implementation agrees to a relative error around 1e-6 or better; a bug typically shows errors of 1e-2 or worse. torch.autograd.gradcheck automates this for custom autograd functions.
    How to fix it
    Write a gradient check as a unit test for every custom layer or loss, using float64, small shapes and a step near 1e-6, and run it whenever the layer changes.

  4. Stacking many sigmoid or tanh layers and judging only by the loss curve

    Why it causes problems
    Each sigmoid layer multiplies the backward signal by at most 0.25 times the weight size, so the layers near the input receive almost nothing. The network then behaves like a shallower one with a nearly frozen front end, and adding depth makes results no better or worse.
    How to recognise it
    Log the mean absolute gradient or the norm per layer after the first few steps. A ratio of many orders of magnitude between the last and the first layer, such as the 1e-6 in exercise 2, is the vanishing-gradient signature.
    How to fix it
    Prefer ReLU-family activations with variance-scaled initialisation (He for ReLU), add skip connections or normalisation, and look at per-layer gradient norms. Use gradient clipping when the norms grow instead of shrinking.

  5. Leaving the framework inside the differentiable path

    Why it causes problems
    Converting a tensor to NumPy, calling .item(), writing a result into an array, or detaching in the middle of the forward pass cuts the graph. The loss still computes, but the parameters upstream of the cut get no gradient (None in TensorFlow and PyTorch) and silently stay at their initial values.
    How to recognise it
    After backward(), some parameters have .grad equal to None, or tape.gradient returns None for them. Training improves only the layers after the cut.
    How to fix it
    Keep every operation between the parameters and the loss on framework tensors. Use detach() or stop-gradient only where you mean to block the gradient, and add a test that asserts every trainable parameter has a gradient after one step.

Hint 1

When you create a result, compute and store the local derivatives immediately. For a product z = x * y they are y.data for x and x.data for y. For a sum they are 1.0 and 1.0.

Hint 2

A depth-first walk that appends a value to a list only after visiting all of its parents produces an order in which every value comes after the values it depends on. Walk that list backwards.

Hint 3

For the sigmoid, the local derivative is s * (1 - s), where s is the output of the sigmoid and so is already known.

Hint 4

If your de/db comes out as 2 or 3 instead of 5, you are assigning to grad instead of adding to it.

Show solution

A complete solution. The grad of each parent receives node.grad * local from every node that used it, which is the "branches add" rule.

python
import math


class Value:
    """A scalar that remembers how it was computed, so gradients can flow back to its inputs."""

    def __init__(self, data, parents=(), local_grads=()):
        self.data = data
        self.grad = 0.0
        self._parents = parents            # the Values this one was computed from
        self._local_grads = local_grads    # d(this)/d(parent) for each parent

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data + other.data, (self, other), (1.0, 1.0))

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data * other.data, (self, other), (other.data, self.data))

    def __neg__(self):
        return self * -1.0

    def __sub__(self, other):
        return self + (-other if isinstance(other, Value) else Value(-other))

    def sigmoid(self):
        s = 1.0 / (1.0 + math.exp(-self.data))
        return Value(s, (self,), (s * (1.0 - s),))

    def backward(self):
        order, seen = [], set()

        def visit(node):                   # depth-first search gives a topological order
            if id(node) not in seen:
                seen.add(id(node))
                for parent in node._parents:
                    visit(parent)
                order.append(node)

        visit(self)
        self.grad = 1.0                    # dL/dL = 1
        for node in reversed(order):       # outputs before inputs
            for parent, local in zip(node._parents, node._local_grads):
                parent.grad += node.grad * local   # += because a Value can feed several later steps


x = [Value(1.0), Value(0.5)]
W1 = [[Value(0.2), Value(-0.3)], [Value(0.4), Value(0.1)]]
b1 = [Value(0.1), Value(-0.2)]
W2 = [Value(0.5), Value(-0.6)]
b2 = Value(0.3)

a1 = [(W1[j][0] * x[0] + W1[j][1] * x[1] + b1[j]).sigmoid() for j in range(2)]
a2 = (W2[0] * a1[0] + W2[1] * a1[1] + b2).sigmoid()
error = a2 - 1.0
loss = error * error * 0.5

Expected behaviour

The sigmoid network and the ReLU network with standard deviation 0.10 both show a layer-1 signal about six orders of magnitude below layer 10. The ReLU network with standard deviation 0.50 stays within about one order of magnitude from layer to layer. The ReLU network with standard deviation 1.00 shows a layer-1 signal thousands of times larger than layer 10. Exact numbers depend on the random generator.

Hint 1

For ReLU the derivative is 1 where z is positive and 0 otherwise. For the sigmoid it is a * (1 - a), where a is the output.

Hint 2

Backward step - first compute back = W transposed times delta, then multiply by the derivative of the layer below. W[j][i] connects input i to unit j, so back[i] is the sum over j of W[j][i] * delta[j].

Hint 3

A random ReLU layer with weight standard deviation s and width 8 scales the norm of the backward signal by about 2 * s per layer, because the transpose multiplies the squared norm by 8 * s^2 and about half the units are active.

Show solution

One way to do it, in plain Python.

python
import math
import random

DEPTH, WIDTH, BATCH = 10, 8, 16

def sigmoid(z):
    return 1.0 / (1.0 + math.exp(-z))

ACTIVATIONS = {
    "sigmoid": (sigmoid, lambda z, a: a * (1.0 - a)),
    "relu": (lambda z: z if z > 0 else 0.0, lambda z, a: 1.0 if z > 0 else 0.0),
}

def layer_delta_sizes(activation, std, seed=0):
    """Mean |dLoss/dz| of each layer (index 0 = first layer) for one random batch of 16."""
    rng = random.Random(seed)
    f, df = ACTIVATIONS[activation]
    weights = [[[rng.gauss(0.0, std) for _ in range(WIDTH)] for _ in range(WIDTH)] for _ in range(DEPTH)]
    xs = [[rng.gauss(0.0, 1.0) for _ in range(WIDTH)] for _ in range(BATCH)]
    ts = [[rng.gauss(0.0, 1.0) for _ in range(WIDTH)] for _ in range(BATCH)]
    totals = [0.0] * DEPTH
    for x, t in zip(xs, ts):
        a_prev, zs, acts = x, [], [x]
        for W in weights:                                   # forward: keep z and a of every layer
            z = [sum(W[j][i] * a_prev[i] for i in range(WIDTH)) for j in range(WIDTH)]
            a_prev = [f(v) for v in z]
            zs.append(z)
            acts.append(a_prev)
        delta = [(acts[-1][j] - t[j]) * df(zs[-1][j], acts[-1][j]) for j in range(WIDTH)]
        for l in range(DEPTH - 1, -1, -1):                  # backward: last layer first
            totals[l] += sum(abs(d) for d in delta) / WIDTH
            if l > 0:
                back = [sum(weights[l][j][i] * delta[j] for j in range(WIDTH)) for i in range(WIDTH)]
                delta = [back[i] * df(zs[l - 1][i], acts[l][i]) for i in range(WIDTH)]
    return [v / BATCH for v in totals]

settings = [
    ("sigmoid, std 0.35 (Glorot)", "sigmoid", math.sqrt(2 / (2 * WIDTH))),
    ("relu, std 0.10 (too small)", "relu", 0.10),
    ("relu, std 0.50 (He)", "relu", math.sqrt(2 / WIDTH)),
    ("relu, std 1.00 (too large)", "relu", 1.0),
]
for name, act, std in settings:
    d = layer_delta_sizes(act, std)
    print(f"{name:30s} layer1 {d[0]:.1e}  layer10 {d[-1]:.1e}  layer1/layer10 {d[0]/d[-1]:.1e}")
