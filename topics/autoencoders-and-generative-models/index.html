Autoencoders and Generative Models (VAE, GAN)

An autoencoder is a neural network trained to rebuild its own input after squeezing it through a narrow internal code. Variational autoencoders (VAEs) and generative adversarial networks (GANs) are two ways to build a generative model, a network that can produce new, realistic samples.

1Overview

Why it matters

Networks that compress, denoise and generate show up in places you might not expect. A ray-tracing renderer cleans up a half-finished image with a denoising autoencoder. A neural audio codec squeezes speech through a quantised bottleneck to a few kilobits per second. A particle-physics trigger scores collisions arriving at 40 million per second with the encoder of a variational autoencoder, inside a 50-nanosecond latency budget. A speech synthesiser turns a spectrogram into a waveform with a GAN. The same two ideas, a learned compact code and a learned judge of realism, sit underneath modern image generators, so this lesson is the base for diffusion models.

Most of the practical difficulty is in recognising how each model fails. An autoencoder with too wide a code copies its input and learns nothing. A VAE trained with squared error gives blurry output, and with a strong decoder it can ignore its latent code altogether. A GAN can produce sharp output yet collapse to a handful of samples, or stop learning because the discriminator wins too early. Engineers who train, evaluate or choose between these models need to read the symptoms (a KL term stuck at zero, a repetitive grid of samples, a discriminator loss near zero) and know the first remedy for each.

Key terms

Bottleneck (code, latent vector)
The short vector in the middle of an autoencoder. Everything the decoder knows about the input has to pass through it.
Reconstruction loss
A measure of the distance between the original input and the decoder's rebuild of it, most often the mean squared error or a cross-entropy.
Denoising autoencoder
An autoencoder that receives a corrupted copy of the input but is scored against the clean original.
Generative model
A model of how data is produced that can be sampled to create new examples resembling the training data.
Prior
The fixed distribution, usually a standard normal, that a VAE wants its latent codes to follow so that new codes can be drawn from it.
KL divergence
A non-negative number that measures how different one probability distribution is from another. It is zero only when the two are identical.
ELBO (evidence lower bound)
The quantity a VAE maximises, equal to the expected reconstruction log-likelihood minus the KL divergence from the encoder's distribution to the prior.
Reparameterization trick
Writing a random code as z = mean + standard deviation x noise, so that gradients can flow through the sampling step into the encoder.
Generator and discriminator
The two networks of a GAN. The generator turns random noise into samples, and the discriminator estimates the probability that a sample is real.
Mode collapse
A GAN failure in which the generator produces only one or a few kinds of output instead of the full variety of the training data.

2Explanation

Introduction

You have used compression before. A ZIP file shrinks a document and a program rebuilds it exactly. A JPEG shrinks a photo and the viewer rebuilds an approximation. Now imagine that the compressor and the rebuilder are both neural networks and nobody tells them how to compress. You give them one rule: whatever comes out must look like what went in. That is an autoencoder.

It has two halves. The encoder reads an input (a 784-pixel image, 140 ECG samples) and writes a short list of numbers, the code or latent vector. The decoder reads only that code and tries to rebuild the input. The loss is the reconstruction error, the distance between the original and the rebuild. Because the code is much shorter than the input, the network cannot memorise every value. It has to discover what the data has in common, and the code ends up holding the main ways one example differs from another. No labels are needed, so this is unsupervised learning, closely related to embeddings and to PCA, which a nonlinear autoencoder generalises.

An autoencoder is not yet a way to make new data. A generative model is a model of how data is produced that you can sample from, to get new examples that look like the training set. The two best-known neural recipes are the subject of this lesson. A variational autoencoder (VAE) keeps the encoder-decoder shape but trains the codes to follow a known distribution, so that decoding a random draw from that distribution gives a plausible new example. A generative adversarial network (GAN) drops the encoder and the reconstruction loss. A generator invents samples from random noise while a second network, the discriminator, learns to tell them from real data, and each improves because of the other.

Each recipe has a signature way of going wrong: blurry output and ignored codes for VAEs, lost variety and unstable training for GANs. Knowing them is what lets you diagnose a run that is not working. The lesson builds the autoencoder and its denoising variant first, then the VAE and the GAN, then the failure modes. The worked example puts numbers on a VAE loss, on blur and on a collapsed generator, and five documented systems show where each idea is used in practice. It assumes you can already train a network, as covered in training deep networks.

How it works

Autoencoders: squeeze, then rebuild

The encoder fff maps an input xxx to a code z=f(x)z = f(x)z=f(x) that is much shorter than xxx. The decoder ggg maps the code back to a reconstruction x^=g(z)\hat{x} = g(z)x^=g(z). Training minimises a reconstruction loss, most often the squared error, averaged over the training set:

L(x)=∥x−g(f(x))∥2\mathcal{L}(x) = \lVert x - g(f(x)) \rVert^2L(x)=∥x−g(f(x))∥2

The input is its own target, so no labels are needed. The first model in the TensorFlow autoencoder tutorial (opens in a new tab) squeezes a 784-pixel Fashion-MNIST image into a 64-number code with one dense layer on each side and trains with mean squared error.

The narrow code is the point. When the code is as wide as the input or wider, the Wikipedia article (opens in a new tab) notes, the network can learn the identity function, which is useless, although the article adds that overcomplete autoencoders sometimes still learn useful features, so a wide code is a risk rather than a certainty. A narrower bottleneck forces the network to keep only what helps rebuild the input. With linear activations, the same article reports, the weights of a single-hidden-layer autoencoder span the same subspace as the leading principal components, so a linear autoencoder is PCA up to a change of basis inside the code. Nonlinear layers let the code follow curved structure that PCA cannot. Exercise 1 reproduces the linear case in plain Python.

Denoising autoencoders

A denoising autoencoder changes the training pair. The encoder sees a corrupted input x~\tilde{x}x~ (noise added, or some values masked), but the loss compares the output with the clean xxx:

L(x)=∥x−g(f(x~))∥2\mathcal{L}(x) = \lVert x - g(f(\tilde{x})) \rVert^2L(x)=∥x−g(f(x~))∥2

Copying can no longer win, because the input and the target differ. Even a wide code has to learn what real data looks like in order to undo the damage. Vincent et al. (opens in a new tab) report that denoising autoencoders learn Gabor-like edge detectors from image patches and stroke detectors from digits. The TensorFlow tutorial adds Gaussian noise (factor 0.2) to Fashion-MNIST images and trains a small convolutional autoencoder to remove it.

Why a plain autoencoder is not a generator

Pick a random code and decode it. Nothing in the training asked the codes of real examples to fill the code space smoothly, so a random code often lands in a gap the decoder has never seen and decodes to garbage. There is also no agreed distribution to draw codes from. The VAE repairs exactly this.

The two terms pull against each other. Reconstruction wants each q(z∣x)q(z \mid x)q(z∣x) narrow and distinct so the decoder knows exactly what to draw. The compromise is a smooth latent space where nearby codes decode to similar outputs and codes drawn from the prior land where the decoder has been trained.

How each model fails

Blur. With a fixed-variance Gaussian decoder the reconstruction term is squared error, and when several sharp outputs fit one code the squared-error-optimal answer is their average, a smear. Goodfellow's GAN tutorial (opens in a new tab) says variational methods often reach good likelihood but are regarded as giving lower-quality samples, and stresses that this is a subjective opinion and not a measured fact; Larsen et al. (opens in a new tab) replace element-wise errors with feature-wise errors from a GAN discriminator. The worked example gives numbers.

Posterior collapse. If the decoder can model the data without the code, the cheapest way to lower the loss is q(z∣x)=p(z)q(z \mid x) = p(z)q(z∣x)=p(z), which makes the KL term zero and the code useless. Bowman et al. (opens in a new tab) describe it for text VAEs and respond with KL cost annealing (the KL weight rises from 0 to 1) and word dropout.

Mode collapse. The generator maps many noise values to one or a few outputs. Google's common problems page (opens in a new tab) describes the cycle: the discriminator learns to reject the repeated output, but the generator over-optimises for that discriminator and hops to another single output. Goodfellow's tutorial calls full collapse rare and partial collapse common, and suggests minibatch features and unrolled GANs.

Vanishing gradients and non-convergence. A discriminator that is too good starves the generator of gradient, and the two networks can oscillate instead of settling. Google lists Wasserstein loss, the modified minimax loss, noise on discriminator inputs and penalising discriminator weights as remedies.

The ideas also combine. Larsen et al. train a VAE whose reconstruction is judged in the discriminator's feature space, SoundStream (Example 2) pairs an autoencoder with an adversarial loss, and latent diffusion models run diffusion inside the latent space of a pretrained autoencoder, as Rombach et al. (opens in a new tab) describe. That autoencoder is itself trained with a perceptual loss and a patch-based adversarial objective, which the paper says avoids the blurriness of relying on pixel-space losses alone.

import math

X_OBS, GAIN = 2.6, 3.0          # data point; decoder is Gaussian with mean 3*z and standard deviation 1
HALF_LOG_2PI = 0.5 * math.log(2 * math.pi)


def kl_term(mu, log_var):
    return 0.5 * (mu**2 + math.exp(log_var) - 1 - log_var)


def one_draw(mu, log_var, eps):
    z = mu + math.exp(0.5 * log_var) * eps              # reparameterization trick
    x_hat = GAIN * z
    recon = 0.5 * (X_OBS - x_hat) ** 2 + HALF_LOG_2PI
    return z, x_hat, recon, kl_term(mu, log_var)

    return recon, kl_term(mu, log_var)

Edge cases and limitations

A code as wide as the input can learn nothing
If the code has as many dimensions as the input, a plain autoencoder can reach near-zero error by copying. The Wikipedia article notes that overcomplete autoencoders sometimes still learn useful features, so treat this as a risk to test for, not a certainty. Exercise 1 shows the copying case: a two-unit code on two-dimensional data reaches zero reconstruction error with no knowledge of the data's structure, while a one-unit code is stuck at the variance of the discarded direction. Low reconstruction error on training data is not evidence that the code is useful.
Random codes decode to garbage in a plain autoencoder
A plain autoencoder is trained only to rebuild real inputs, so nothing keeps the space between the codes of real examples meaningful, and nothing says how to sample a code. Decoding the code of a real example works; drawing a code from a standard normal usually does not. The VAE's KL term is what turns the latent space into something you can sample.
Posterior collapse hides behind a falling loss
A VAE with a powerful decoder, such as an LSTM over words, can lower its loss by ignoring the code, which makes q(z|x) equal to the prior and the KL term zero. Bowman et al. describe this for text. The total loss still falls, so the symptom is a KL term near zero and samples that barely change with z. Look at the two loss terms separately, per epoch, instead of only at their sum.
GAN losses do not measure sample quality
The two networks are scored against each other, so both losses can hover near their equilibrium values while the generator has collapsed to a few outputs. The original GAN paper evaluated samples with a Gaussian Parzen-window likelihood and warns that this estimate has high variance and works poorly in high dimensions. Inspect large grids of fresh samples at a fixed seed and measure variety directly.
Reconstruction error as an anomaly score can fail in both directions
The TensorFlow tutorial trains on normal ECGs only and flags a trace whose reconstruction error exceeds the mean plus one standard deviation of the training errors. That works when anomalies are unlike the training data and the model is not too flexible. A model with a wide code or enough capacity reconstructs anomalies too, and a threshold copied from one dataset does not transfer to another.

When to use it, and when something simpler is enough

Use it when

  • You have plenty of unlabeled data of one kind (images, signals, expression profiles) and want a compact learned representation for visualisation, search or a downstream model.
  • You can collect mostly normal examples and need to flag inputs unlike them, so an autoencoder trained on normal data with a reconstruction-error threshold is a reasonable baseline.
  • You have paired noisy and clean examples, or can corrupt clean data yourself, and want a learned denoiser or codec, as in the rendering and audio examples in this lesson.
  • You need to sample new data and also want an encoder, a smooth latent space and a loss you can monitor, which points to a VAE.
  • You need sharp samples, do not need likelihoods or an encoder, and can afford careful tuning of two networks, which points to a GAN.

Think twice when

  • You have labels and the goal is prediction. A supervised model is usually more accurate than classifying on top of unsupervised codes.
  • You need calibrated likelihoods of new data or stable, repeatable training. A GAN gives neither, because it has no explicit density for generated samples and its training is a game.
  • Your goal is text-to-image or video generation. Start from the diffusion-models lesson, where autoencoders appear as a component rather than as the generator.

A simpler alternative. For linear structure, PCA gives the same subspace as a linear autoencoder with no training loop, and for simple tabular anomaly detection a z-score, an isolation forest or a Gaussian mixture is often enough. Move to an autoencoder when the structure is nonlinear and you have enough data to train a network, and to a VAE or GAN only when you must generate new samples.

Key takeaways

  • An autoencoder learns by rebuilding its input through a bottleneck, and the bottleneck, or input corruption, is what stops it from learning the identity function.
  • A denoising autoencoder scores its output against the clean input rather than the corrupted one, so it must learn what real data looks like instead of copying.
  • A VAE minimises reconstruction loss plus a KL penalty towards a standard normal and writes z = μ + σ ⊙ ε so gradients reach the encoder; the prior is what lets you sample new data.
  • A GAN replaces the reconstruction loss with a discriminator in a minimax game, which gives sharp samples but no likelihood and a delicate balance between two networks.
  • Squared-error reconstruction averages the plausible answers, so plain autoencoders and VAEs blur, and posterior collapse, mode collapse and vanishing generator gradients each have a recognisable symptom and a known first remedy.

NVIDIA's developer page says it is based on NVIDIA research on a recurrent denoising autoencoder, and a 2017 developer blog post gives the training set and a speed test. The blog describes OptiX 5.0, the first release with the denoiser, while the developer page now refers to OptiX 8. [13][14][15]

The problem

Path tracing estimates each pixel by averaging random light paths. A few paths per pixel give a speckled image, and waiting for the average to converge costs minutes or hours per frame. The goal is a clean-looking image from a frame that is still noisy, for many different scenes without per-scene tuning, and for animation, where neighbouring frames must not flicker.

Where this topic fits

The autoencoder sits between the renderer and the display. The renderer hands over a noisy frame together with auxiliary per-pixel channels, and the network returns a cleaned frame. This is the denoising autoencoder of this lesson: its input is a corrupted image, its target is a cleaner one, and the compression inside the network is what makes it learn the structure of rendered images instead of copying the noise.

How it is applied, step by step

  1. The renderer stops early and produces a frame whose pixels are averages over too few light paths, so every pixel carries sampling noise.
  2. Per-pixel auxiliary channels such as depth and normals come with the colour image. The research paper reports that its network models relationships with those channels automatically.
  3. To train, many scenes are rendered to several completion levels. NVIDIA's 2017 post describes 1,000 scenes at 15 levels (15,000 images), and the developer page gives the count more loosely as tens of thousands of images from one thousand scenes. In a denoising autoencoder the target is a cleaner version of the same view; the cited pages do not say which image was used.
  4. The network has recurrent connections, so what it learned from earlier frames of a sequence is carried forward. The paper's abstract says this greatly improves temporal stability for sparsely sampled sequences.
  5. At render time the trained network runs on the GPU on each noisy frame and returns the denoised frame, so the artist sees a nearly noise-free image long before the renderer has converged.

Why this approach fits

Monte Carlo noise is a corruption you can manufacture on demand: render the same view with few and with many samples. That supplies unlimited noisy and clean pairs, which is exactly what a denoising autoencoder needs. A learned denoiser also adapts to noise patterns and scene content that a hand-designed filter would need tuning for.

Limitation or tradeoff

A learned denoiser can only be as general as the scenes and noise it was trained on, and the same averaging effect that causes blur in VAEs can smooth away genuine fine detail. NVIDIA's speed figures come from one test scene at one quality target, so they show the size of the effect, not a guarantee for every scene. The 2017 post itself says AI denoising then struggled with low sample counts and with textures seen behind glass.

What the sources document

  • NVIDIA's OptiX AI-accelerated denoiser page says the denoiser is based on the NVIDIA research paper on interactive reconstruction of Monte Carlo image sequences using a recurrent denoising autoencoder, and that it was trained on tens of thousands of images from one thousand 3D scenes on a DGX-1 using an autoencoder similar to the paper's. Google SoundStream: an autoencoder with a quantised bottleneck as an audio codec

Google ResearchDocumented in an engineering article

SoundStream is a neural audio codec from Google Research. A 2021 Google Research blog post and an arXiv paper describe an encoder, a quantiser and a decoder trained end to end, with a discriminator adding an adversarial loss, to compress speech, music and general audio to a few kilobits per second. [16][17]

The problem

Sending audio over a weak connection needs bitrates of a few kilobits per second while still sounding natural. Classical codecs such as Opus and EVS are hand-designed. The question is whether a learned encoder-decoder can match them at a much lower bitrate and still run in real time on a phone.

Where this topic fits

Here the bottleneck is literal: the code vectors are quantised to a few bits each, and those bits are what gets transmitted. The encoder turns audio into code vectors, the quantiser picks codebook entries, and the decoder rebuilds audio from the quantised vectors. Training combines this lesson's autoencoder reconstruction loss with a GAN-style discriminator.

How it is applied, step by step

  1. The encoder converts the incoming audio into a coded signal, a sequence of vectors at a much lower rate than the audio samples.
  2. A residual vector quantiser replaces each vector by entries from several codebooks. The first layer quantises the vector, and each later layer quantises the error left by the layers before it.
  3. The chosen codebook indices, a few bits per vector, are the transmitted signal. Fewer layers mean fewer bits per second.
  4. The decoder rebuilds audio from the quantised vectors on the receiving side.
  5. During training a discriminator contributes an adversarial loss next to the reconstruction loss, so the output is pushed to sound like real audio and not only to match the waveform on average.
  6. Randomly dropping quantiser layers during training (quantiser dropout) lets one model serve several bitrates without retraining.

Why this approach fits

Compression is the autoencoder's original job, and quantisation turns the bottleneck into a countable number of bits. A pure squared-error decoder would average over plausible waveforms and sound dull, as the blur argument in this lesson predicts, so the adversarial loss is a natural addition. Training the encoder and decoder on audio lets the codec spend its few bits on what matters for listening.

Limitation or tradeoff

A learned codec is trained on particular kinds of audio and its quality outside that material is not guaranteed by a bitrate comparison. Sender and receiver must also run compatible neural networks, which costs more compute and coordination than a standard codec. The post's quality comparisons come from its own listening tests, and it describes SoundStream as still experimental in 2021, unlike the already-deployed Lyra codec.

What the sources document

  • The Google Research post describes four components: an encoder, a residual vector quantiser, a decoder, and a discriminator that computes the training losses, which combine adversarial and reconstruction terms so that the output sounds like the uncompressed input. [16]
  • At 3 kbps the post reports that SoundStream outperforms Opus at 12 kbps and approaches EVS at 9.6 kbps, using 3.2 to 4 times fewer bits. [16]
  • The post calls SoundStream the first neural codec to work on speech and music while running in real time on a smartphone CPU, and says Lyra would incorporate its components. [16]
  • The paper's abstract describes a fully convolutional encoder and decoder with a residual vector quantiser trained jointly end to end, structured dropout on the quantiser layers so one model covers 3 kbps to 18 kbps, and joint compression and enhancement such as background-noise suppression. [17]
  • The post's example is that with 100 vectors per second at 3 kbps and five quantiser layers, the codebook size falls from 1 billion to 320. [16]

CMS AXOL1TL: a variational autoencoder picks collision events in 50 nanoseconds

CMS ExperimentDocumented in a paper

At the Large Hadron Collider the CMS experiment must decide in hardware which collisions to keep. AXOL1TL is an anomaly detection algorithm built on a variational autoencoder, described in a 2024 ICHEP conference paper by A. Gandrakota on behalf of the CMS collaboration and a Fast Machine Learning page. A 2022 Nature Machine Intelligence paper by Govorkova and colleagues studies autoencoder anomaly detection on FPGAs at the same 40 MHz rate. [18][19][20][21]

The problem

Collisions arrive at 40 MHz and only a tiny fraction can be recorded. Standard triggers keep events that match known physics signatures, so they cannot select a signature nobody has predicted. The need is a score that says how unlike usual events a collision is, computed for every event within nanoseconds on an FPGA, and trained without examples of the unknown signal.

Where this topic fits

The VAE is trained on ordinary events only. In deployment the decoder is dropped: just the encoder runs on the chip, and the anomaly score is computed from the encoder's means. This uses the VAE for its encoder and its prior-regularised latent space, not for generating samples.

How it is applied, step by step

  1. Train the VAE on ZeroBias data, a trigger-less sample of CMS collisions recorded in 2023, which is almost entirely ordinary background and so defines what normal looks like.
  2. The inputs are the trigger objects of each event: 10 jets, 4 electron or photon objects, 4 muons and the missing transverse energy, each as transverse momentum, pseudorapidity and azimuth.
  3. The encoder maps an event to a latent vector of size 8 whose entries are Gaussian distributions, and training pulls them towards the standard normal as in any VAE.
  4. At inference only the encoder runs. The anomaly score is approximated by the sum of the squared latent means, so no decoding or sampling is needed on the chip.
  5. An event whose score exceeds a threshold is flagged. During 2024 data-taking the trigger was run at five different thresholds, from very tight to very loose, without interrupting normal readout.

Why this approach fits

Reconstruction error would need the decoder on the chip as well. The KL term already pulls typical events towards the origin of the latent space, so the distance of the mean from the origin is a cheap measure of unusualness. Govorkova et al. report that for a VAE the KL divergence can serve as the anomaly metric, which avoids sampling.

Limitation or tradeoff

The score means unlike the training data, not interesting physics: detector faults and rare but known processes also score high, so flagged events need analysis afterwards. The trigger rate depends on the threshold, and a model trained on 2023 conditions can drift as running conditions change. The paper reports the test-crate stage, a copy of the Global Trigger whose output did not drive readout, and the Fast Machine Learning page says later model versions changed the design (a contrastive embedding and a deeper model), so these steps describe the first model only.

What the sources document

  • The CMS paper describes AXOL1TL as a variational autoencoder with dense encoder and decoder layers and a latent vector of size 8. Only the encoder is used for real-time inference, and the anomaly score is approximated by the sum of the squared latent means. [18]
  • It was trained on ZeroBias data collected by CMS in 2023, takes jets, electron or photon objects, muons and missing transverse energy as input, and is deployed on Xilinx Virtex-7 FPGAs in the Global Trigger test crate, where the Global Trigger's decision latency is 50 ns. [18]
  • In June 2024 data-taking the trigger was tested at five different thresholds on the live collision stream without interrupting the standard readout. [18]
  • The Fast Machine Learning page says the anomaly score is computed in the latent space rather than through full reconstruction to meet hardware constraints, and that AXOL1TL has taken data at CMS since 2024. [19]
  • Govorkova et al. (Nature Machine Intelligence, 2022) report autoencoder anomaly detection at 40 MHz on an FPGA in as little as 80 ns using less than 3 % of the logic of a Xilinx Virtex VU9P, and that the KL divergence can be used as the anomaly metric for a VAE. [20][21]

scVI: a variational autoencoder for single-cell RNA-seq counts

scvi-toolsDocumented in official docs

scvi-tools is an open-source Python library for probabilistic models of single-cell data. Its scVI user-guide page documents a VAE for single-cell RNA sequencing counts: the generative process, the inference network and the tasks the latent space supports. Its introductory tutorial shows the workflow. [22][23]

The problem

A single-cell RNA-seq experiment produces a matrix of integer gene counts for thousands to millions of cells, with technical variation from batch and sequencing depth on top of the biology. Analysts want a short description of each cell that reflects its type and state, normalised expression for comparing groups, and a way to combine datasets. Counts are not Gaussian, so the decoder of an image-style VAE does not fit.

Where this topic fits

The VAE is the whole model. By default the encoder maps a cell's counts alone, without its batch label, to a distribution over a short latent vector (the documentation offers an option to feed covariates to the encoder as well). The decoder maps that vector, together with the batch label, back to the parameters of a count distribution for every gene. The posterior mean of the latent vector is the cell's low-dimensional representation, the decoder gives normalised expression, and sampling from the model's posterior predictive distribution simulates data.

How it is applied, step by step

  1. The input is a raw-count matrix of N cells by G genes, with optional covariates such as batch, donor or day stored in a design matrix.
  2. Each cell has a latent vector with a standard normal prior. This is the prior of Kingma and Welling's VAE, and training keeps the KL term to it.
  3. The decoder produces, for each gene, the parameters of a count distribution, a zero-inflated negative binomial by default, with the batch as a categorical covariate. Only the output distribution differs from an image VAE.
  4. Inference networks (encoders) define the approximate posterior over each cell's latent vector, the encoder role the lesson describes for any VAE. By default they see the counts only.
  5. After training, the posterior mean serves as the cell's embedding for clustering and dataset integration, the decoder yields denoised expression for differential-expression testing, and feeding a cell through the model and sampling from its likelihood simulates data.

Why this approach fits

The VAE framework separates the pieces that must change from the pieces that need not. The decoder's output distribution can be swapped for one that suits counts, while the encoder, the Gaussian prior and the KL regularisation stay as they are. A probabilistic latent space also gives a principled way to treat batch as a covariate rather than as a feature of the biology.

Limitation or tradeoff

The documentation lists limits itself: fast inference needs a GPU, and the latent space is not interpretable in the way a linear method's components are. As with any VAE, the learned embedding depends on the chosen likelihood, code size and training settings.

What the sources document

  • The scVI page describes it as a flexible generative model of scRNA-seq count data that supports many downstream tasks. [22]
  • In the documented generative process each cell has a latent variable with a standard normal prior, counts follow a zero-inflated negative binomial by default (with the negative binomial as an alternative), and batch is a categorical covariate. [22]
  • scVI uses auto-encoding variational Bayes: inference networks (encoders) define an approximate posterior over each cell's latent representation, and by default only the expression data, not the cell-level covariates, goes into the encoder. The listed tasks are dimensionality reduction through the posterior mean, transfer learning, normalisation and imputation, differential expression, and data simulation. [22]
  • The page lists scalability to over a million cells as an advantage, and the need for a GPU for fast inference and a latent space that is not interpretable as limitations. [22]
  • The introductory tutorial sets up the data with a counts layer, builds the model with scvi.model.SCVI(adata), trains it, and gets a latent representation with one row per cell and 10 dimensions. [23]

HiFi-GAN in NVIDIA Riva: a GAN vocoder turns spectrograms into speech

NVIDIADocumented in official docs

NVIDIA Riva's text-to-speech documentation describes a two-stage pipeline in which a model such as FastPitch produces a mel spectrogram and a HiFi-GAN model then produces speech. HiFi-GAN is described in a NeurIPS 2020 paper by Kong, Kim and Bae. The same Riva page says its MagpieTTS Multilingual model takes a different route, generating tokens and decoding them with an audio codec model. [24][25][26]

The problem

A spectrogram says which frequencies occur when, but a listener needs the raw waveform with all its fine structure. The second stage of a speech synthesiser must produce that waveform so that it sounds natural, and quickly enough for interactive use. The paper measures HiFi-GAN against WaveNet and WaveGlow on exactly this task.

Where this topic fits

HiFi-GAN is a conditional GAN. Its generator takes the mel spectrogram as its only input (the paper says noise is not given to the generator as an additional input) and returns a waveform, and its discriminators judge whether a waveform is a real recording or generated. The discriminators are only needed during training, so a deployed service typically needs just the generator.

How it is applied, step by step

  1. Stage one (FastPitch or a similar model) converts text to a mel spectrogram, as Riva's overview describes.
  2. The HiFi-GAN generator takes that spectrogram as its condition and outputs a raw waveform at 22.05 kHz in the paper's setup.
  3. In training, two kinds of discriminator judge the waveform. The multi-period discriminator has five sub-discriminators over samples spaced 2, 3, 5, 7 and 11 apart, and the multi-scale discriminator has three that look at the waveform at different resolutions.
  4. The generator's loss adds an adversarial term (a least-squares loss, which the paper chose to keep gradients from vanishing), a feature-matching term over the discriminators' internal features weighted 2, and an L1 distance between the mel spectrograms of generated and real audio weighted 45.
  5. In a typical deployment only the trained generator is needed at inference time, turning each spectrogram into audio. The Riva page itself does not describe this detail.

Why this approach fits

A distance between mel spectrograms alone would reward the average of many plausible waveforms, the same pull towards blur as in the worked example. The discriminators supply the demand for realistic fine structure, while the mel term ties each output to the content of its input spectrogram. A generator-only deployment is also small and fast, which suits a service.

Limitation or tradeoff

GAN training stays delicate; the loss combines three terms with hand-chosen weights. The paper's headline quality result uses a single-speaker dataset (LJSpeech), and it adds a separate test on nine unseen VCTK speakers, so behaviour on other voices or recording conditions in a production service needs its own evidence. The paper describes the research model. The Riva overview names the pipeline but gives no quality figures or training settings of its own, so the loss weights above should not be assumed to be Riva's.

What the sources document

  • Riva's TTS overview says that models such as FastPitch and RadTTS++ first generate a mel spectrogram and that speech is then generated by the HifiGAN model. [24]
  • The HiFi-GAN abstract reports generating 22.05 kHz audio 167.9 times faster than real time on a single V100 GPU, a small version running 13.4 times faster than real time on CPU, and subjective quality close to human on a single-speaker dataset. [25]
  • The paper's generator loss is an adversarial term plus a feature-matching term weighted 2 plus a mel-spectrogram L1 term weighted 45, and the discriminator loss is the adversarial term. The adversarial terms are least-squares losses, chosen for non-vanishing gradient flow, and the paper says the mel-spectrogram loss also stabilises adversarial training from the early stages. [26]
  • The paper uses a multi-period discriminator with periods 2, 3, 5, 7 and 11 and a multi-scale discriminator with three sub-discriminators, is trained on LJSpeech (13,100 clips from one speaker), and is compared with WaveNet and WaveGlow. [26]

4Common mistakes

  1. Making the code as wide as the input and treating a near-zero reconstruction error as success.

    Why it causes problems
    The network can learn the identity function, so the code holds no structure and is useless for compression, anomaly scoring or features.
    How to recognise it
    Reconstruction error is tiny on training data and just as tiny on inputs that look nothing like it, such as random noise or another class.
    How to fix it
    Narrow the code, corrupt the input (denoising), or add a penalty on the code, and always test reconstruction on deliberately unfamiliar inputs.

  2. Sampling codes from a standard normal to generate with a plain, non-variational autoencoder.

    Why it causes problems
    Nothing trained the codes of real data to follow a standard normal, so the sampled codes fall in gaps and the decoder produces garbage.
    How to recognise it
    Reconstructions of real inputs look fine while images decoded from random codes look unlike the data.
    How to fix it
    Use a VAE, whose KL term ties the codes to the prior, or fit a simple density model to the encoded training codes and sample from that.

  3. Averaging the VAE reconstruction term over pixels but summing the KL term over code dimensions, or the reverse.

    Why it causes problems
    The relative weight of the two terms is off by roughly the number of pixels, so the KL term either dominates and the code collapses, or is negligible and the latent space keeps its gaps.
    How to recognise it
    KL near zero and samples that ignore the code, or sharp reconstructions but poor samples from the prior.
    How to fix it
    Sum the reconstruction over all values of one example and the KL over its code dimensions, then average over the batch. The TensorFlow VAE tutorial does this, although it estimates the KL term by sampling instead of using the closed form. Treat any extra KL weight as a deliberate setting.

  4. Training the discriminator until it is nearly perfect before giving the generator a turn.

    Why it causes problems
    When the discriminator is too good, the generator receives almost no useful gradient and stops improving.
    How to recognise it
    Discriminator loss close to zero, generator loss rising or flat, and a sample grid that no longer changes.
    How to fix it
    Update the two networks about equally often, use the non-saturating generator loss, and if it persists try Wasserstein loss or noise on the discriminator inputs.

  5. Judging a GAN by its loss curves instead of by looking at its samples.

    Why it causes problems
    The losses are scored against a moving opponent, so a generator that has collapsed to a few outputs can show healthy-looking losses.
    How to recognise it
    Loss values near their equilibrium numbers while a grid of fresh samples shows near-duplicates.
    How to fix it
    Save fixed-noise sample grids every few epochs, count how many distinct classes or styles appear among a thousand samples, and compare them with the training data.

Show solution

A complete listing. Run it with python3.

python
import math
import random

RAW = [(-4, -1.2), (-3, -2.0), (-2, -0.4), (-1, -1.1), (1, 0.9), (2, 0.5), (3, 2.1), (4, 1.3)]
MEAN_Y = sum(y for _, y in RAW) / len(RAW)
X = [(x, y - MEAN_Y) for x, y in RAW]              # centred: the mean of x is already 0


def matvec(matrix, vector):
    return [sum(m * v for m, v in zip(row, vector)) for row in matrix]


def train(k, steps=3000, lr=0.01, noise=0.0, draws=1, seed=0):
    """Linear autoencoder x_hat = D (E x) with a k-unit code, fitted by gradient descent."""
    rnd = random.Random(seed)
    enc = [[rnd.uniform(-0.5, 0.5) for _ in range(2)] for _ in range(k)]   # k x 2
    dec = [[rnd.uniform(-0.5, 0.5) for _ in range(k)] for _ in range(2)]   # 2 x k
    for _ in range(steps):
        g_enc = [[0.0] * 2 for _ in range(k)]
        g_dec = [[0.0] * k for _ in range(2)]
        for target in X:
            for _ in range(draws):
                inp = [t + rnd.gauss(0, noise) for t in target] if noise else list(target)
                code = matvec(enc, inp)
                err = [a - t for a, t in zip(matvec(dec, code), target)]    # x_hat - x
                for i in range(2):
                    for j in range(k):
                        g_dec[i][j] += 2 * err[i] * code[j]
                for j in range(k):
                    back = sum(dec[i][j] * err[i] for i in range(2))
                    for c in range(2):
                        g_enc[j][c] += 2 * back * inp[c]
        scale = lr / (len(X) * draws)
        dec = [[dec[i][j] - scale * g_dec[i][j] for j in range(k)] for i in range(2)]
        enc = [[enc[j][c] - scale * g_enc[j][c] for c in range(2)] for j in range(k)]
    return enc, dec


def clean_loss(enc, dec):
    return sum(sum((a - t) ** 2 for a, t in zip(matvec(dec, matvec(enc, p)), p)) for p in X) / len(X)


n = len(X)
cxx = sum(p[0] ** 2 for p in X) / n
cyy = sum(p[1] ** 2 for p in X) / n
cxy = sum(p[0] * p[1] for p in X) / n
half = (cxx + cyy) / 2
gap = math.sqrt(half**2 - (cxx * cyy - cxy**2))
print(f"PCA eigenvalues: {half + gap:.4f} and {half - gap:.4f}")

for k in (1, 2):
    enc, dec = train(k)
    print(f"k={k}: reconstruction loss {clean_loss(enc, dec):.4f}")

enc, dec = train(2, steps=6000, noise=1.0, draws=16)
learned = [[sum(dec[i][j] * enc[j][c] for j in range(2)) for c in range(2)] for i in range(2)]
a, b, d = cxx + 1.0, cxy, cyy + 1.0
det = a * d - b * b
inv = [[d / det, -b / det], [-b / det, a / det]]
cov = [[cxx, cxy], [cxy, cyy]]
closed = [[sum(cov[i][m] * inv[m][j] for m in range(2)) for j in range(2)] for i in range(2)]
print("learned map  ", [[round(v, 3) for v in row] for row in learned])
print("closed form  ", [[round(v, 3) for v in row] for row in closed])

A one-unit code can carry only one direction of the data, so its best possible error is the variance in the direction it throws away, the smaller eigenvalue 0.2732. Gradient descent finds exactly that, and the decoder's column points along the first principal component, about (0.91, 0.41). That is the equivalence between a linear autoencoder and PCA. A two-unit code on two-dimensional data has no bottleneck, so the product DEDEDE drifts to the identity and the error to zero: the model copies and learns nothing about the data.

Noise changes the answer even without a bottleneck. For a linear model the expected loss with noise of variance σ2\sigma^2σ2 is the clean loss plus σ2∥M∥F2\sigma^2 \lVert M \rVert_F^2σ2∥M∥F2​, and its minimiser is M=C(C+σ2I)−1M = C(C + \sigma^2 I)^{-1}M=C(C+σ2I)−1, a shrinkage matrix. Along the first principal component the variance 8.978.978.97 is large compared with the noise, so that direction is kept almost intact (about 8.97/9.97≈0.908.97 / 9.97 \approx 0.908.97/9.97≈0.90). Along the weak direction the variance 0.27 is small compared with the noise, so that direction is shrunk to about 0.27/1.27≈0.210.27 / 1.27 \approx 0.210.27/1.27≈0.21. The denoising autoencoder learns to discard the part of the input that the noise swamps, which is the idea behind every denoiser in this lesson. The learned map differs from the closed form by about 0.01 because the noise draws are random.

Check your answer

  • Does your one-unit loss match the smaller covariance eigenvalue to three decimals (0.273)?
  • Does the two-unit loss fall below 0.001, and can you say why the network is allowed to copy?
  • Is every entry of your learned map within about 0.02 of the closed-form matrix?
  • Can you explain in one sentence why the noisy two-unit model does not simply learn the identity?

Requirements

  • Name the failure mode for each run, using the lesson's terms.
  • Give one confirming check for each run that does not require retraining.
  • Give one first change for each run and say which part of the log motivates it.
  • State which run could be diagnosed from a summed loss curve alone and which could not.

Expected behaviour

Run A is posterior collapse, Run B is a discriminator that has overpowered the generator (vanishing gradients), and Run C is mode collapse in which the generator hops from one output to another while the losses look balanced. Only Run B shows its problem in the loss values; Run A needs the two terms logged separately, and Run C needs the samples.

Hint 1

In Run A, what value does the KL term take when the encoder returns exactly the prior, and what does the decoder have to be able to do for that to be cheap?

Hint 2

In Run B, a generator loss of 9 under the loss -log D(G(z)) means D(G(z)) is about e^-9. How confident is the discriminator that the samples are fake?

Hint 3

In Run C, a discriminator that is guessing gives a loss near the natural log of 2. Does that tell you the samples are diverse?

Show solution

Run A: posterior collapse. The KL term falls from 4.10 to 0.00 while the reconstruction term keeps improving, so the encoder's distribution has become the prior and carries no information about the sentence. A strong LSTM decoder can model the text on its own, which makes ignoring the code the cheapest way to lower the loss. Confirming checks: print the KL per code dimension (all near zero), decode the same input with different codes and see that the output does not change, or replace the code with random noise and see that the reconstruction loss stays the same. First change: KL cost annealing, so the KL weight rises from 0 to 1 over the first epochs and the model learns to use the code before it is penalised for it. Word dropout on the decoder's inputs, which makes the decoder depend on the code, is the second option. Both come from Bowman et al.

Run B: vanishing gradients from a dominant discriminator. A discriminator loss of 0.02 means it separates real from fake almost perfectly, and a generator loss of 9 under −log⁡D(G(z))-\log D(G(z))−logD(G(z)) means D(G(z))≈e−9≈0.0001D(G(z)) \approx e^{-9} \approx 0.0001D(G(z))≈e−9≈0.0001: the discriminator is nearly certain every sample is fake, so it gives the generator little to follow. The non-saturating loss keeps the loss value large in this situation, so the symptom is a generator loss that climbs while the samples stop improving, not a loss that falls to zero. Confirming checks: the discriminator's accuracy on a real batch and on a fake batch (both near 100 %), and the size of the gradient that reaches the generator's weights (small or erratic). First change: give the generator more turns, for example one discriminator update per generator update as in the original paper (which used k=1k = 1k=1), or a lower discriminator learning rate. If that does not help, Google's course suggests Wasserstein loss and noise on the discriminator's inputs.

Run C: mode collapse with hopping. At each snapshot the generator makes one digit in many thicknesses, then moves to another digit. This matches the cycle on Google's common-problems page, where the discriminator learns to reject the repeated output and the generator moves to a new single output. The losses stay near 0.69 because the discriminator is guessing about each snapshot's output; the loss does not measure variety. Confirming checks: classify 1,000 fresh samples with a digit classifier and look at the class histogram, and compare with the training data's histogram. First change: a loss that keeps discriminator gradients useful, such as Wasserstein loss. Two alternatives are minibatch features, which let the discriminator compare a sample with the rest of its batch and so notice repetition, and unrolled GANs, which let the generator account for the discriminator's next updates. Goodfellow's tutorial describes both, and Google's page describes unrolled GANs.

Which run shows in a summed curve? Run B, through its loss values. Run A's summed loss falls smoothly, so you must log reconstruction and KL separately. Run C's losses look healthy, so only the samples reveal it.

  • Is each confirming check something you could do without retraining the model?
  • Did you explain why Run C's loss near 0.69 does not show that the samples are diverse?
  • Did you tie each first change to a specific number or symptom in that run's log?
