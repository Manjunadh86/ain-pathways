The Python Data Stack (NumPy, pandas, scikit-learn)

The Python data stack is a group of libraries that share one way of holding data. NumPy stores numbers in typed arrays and computes on whole arrays at once, pandas adds labelled tables called DataFrames, Matplotlib and Seaborn draw charts from them, and scikit-learn trains models through the same few methods: fit, transform and predict.

1Overview

Why it matters

Almost every machine learning lesson after this one assumes you can read three lines without stopping: X.mean(axis=0), df.groupby("region")["sales"].mean() and model.fit(X_train, y_train). They are the working vocabulary of tabular machine learning. Without them, an explanation of any algorithm is hard to follow and impossible to try out.

The mistakes that matter here rarely crash. An array of shape (n, 1) minus an array of shape (n,) gives an n-by-n grid, and the error metric computed from it is wrong without any warning. A preprocessing step fitted on every row before the data is split lets the test rows influence training, and the reported score comes out too good. A loop over the rows of a large table can take minutes where a column expression takes milliseconds. Analysts, ML engineers and anyone who reviews a notebook need to know the stack well enough to spot these on sight.

Key terms

ndarray
NumPy's array type. A fixed-size grid of values that all have the same data type, stored as one block of memory.
dtype
The data type of the values in an array or a column, such as int64 for whole numbers, float64 for decimals or str for text.
Shape and axis
Shape is the size of an array along each dimension, such as (12, 2) for 12 rows and 2 columns. An axis is one of those dimensions, and axis 0 runs down the rows.
Vectorization
Writing an operation on whole arrays, with no explicit Python loop, so that the loop runs inside compiled code.
Broadcasting
NumPy's rule for combining arrays of different shapes by treating the smaller one as if it were repeated to match the larger.
Series and DataFrame
A Series is one labelled column of values. A DataFrame is a table made of Series that share the same row labels, where each column can have its own dtype.
Index
The row labels of a Series or DataFrame. pandas uses these labels, not row positions, to match rows when it combines data.
Estimator
Any scikit-learn object that learns from data through a fit method. Models and preprocessing steps are both estimators.
Transformer
An estimator with a transform method that returns a changed version of the features, such as a scaler or an encoder.
Pipeline
A chain of transformers that ends in a final estimator and behaves as one estimator with its own fit and predict.

2Explanation

Introduction

If you have used a spreadsheet, you already know the four jobs this lesson is about: keep numbers in a grid, apply one formula to a whole column, draw a chart, and fit a trend to the data. The Python data stack gives each job to a library, and the libraries are built to pass data to one another.

Start with the smallest possible case. In plain Python, [1, 2, 3] * 2 gives [1, 2, 3, 1, 2, 3]. A list is a general container, and multiplying it repeats it. With NumPy, np.array([1, 2, 3]) * 2 gives [2 4 6]. An array is a block of numbers of one type, and arithmetic applies to every element at once. Doing the same thing to all the numbers without writing a loop is the idea the rest of the stack is built on.

  • NumPy stores numbers in typed, fixed-size arrays and computes on whole arrays in compiled code.
  • pandas wraps arrays into a DataFrame, a table whose columns have names and whose rows have labels, and reads and writes files such as CSV.
  • Matplotlib draws charts from arrays, and Seaborn sits on top of it to draw statistical charts straight from a DataFrame.
  • scikit-learn learns from a table of features through one small interface: fit to learn, transform to change data and predict to produce answers.

A typical piece of work passes through all four. You load a file into a DataFrame, check and summarise it, plot it to see what is there, and hand the columns to a scikit-learn model, which returns its predictions as a NumPy array. What machine learning is described features, targets and training in words. This lesson shows the objects that hold them.

The sections below take the libraries in that order and then run one small dataset through all of them. The code was run with NumPy 2.5, pandas 3.0, Matplotlib 3.11 and scikit-learn 1.9, and the Seaborn calls follow the Seaborn 0.13 documentation. Later lessons use these tools constantly, starting with data collection and cleaning, exploratory data analysis, feature engineering and train/test splits and cross-validation.

How it works

NumPy: one block of numbers, one type

A NumPy array (ndarray) is a grid of values that all share one dtype (data type, such as int64 or float64) and has a fixed shape. Because every element is the same size, the grid sits in one block of memory and loops over it run in compiled C. Writing an operation on whole arrays, with no explicit loop, is what the NumPy documentation (opens in a new tab) calls vectorization.

python
import numpy as np

X = np.array([[3, 100], [13, 420], [5, 250]])   # 3 trails: distance (km), climb (m)
print(X.shape, X.dtype)       # (3, 2) int64
print(X.mean(axis=0))         # [  7.         256.66666667]   one mean per column
print(X.mean(axis=1))         # [ 51.5 216.5 127.5]           one mean per row
hours = X[:, 0] / 5 + X[:, 1] / 600
print(hours.round(2))         # [0.77 3.3  1.42]
print(X[hours > 3])           # [[ 13 420]]   a boolean mask selects rows

An axis is one dimension of the array. axis=0 runs down the rows, so mean(axis=0) collapses the rows and leaves one value per column. None of the lines above contains a loop, and that is where the speed comes from: on the machine used to check this lesson, summing the squares of one million numbers took about 15 ms with a Python loop and about 0.3 ms as (x * x).sum().

Broadcasting is the rule for combining arrays whose shapes differ. NumPy lines the shapes up from the right. Two dimensions are compatible when they are equal or one of them is 1, and a missing dimension counts as 1 (broadcasting rules (opens in a new tab)). The smaller array behaves as if it were repeated, without being copied. So X - X.mean(axis=0) subtracts a (2,) array of column means from every row of a (3, 2) array.

Slicing, as in X[:2], returns a view that shares memory with X, so assigning into the slice changes X. Selecting with a mask returns a copy. Call .copy() when you need independent data.

pandas: a table whose columns have names and types

A Series is a one-dimensional array with a label for every element. A DataFrame is a table made of Series that share the same row labels, the index. Each column keeps its own dtype, which is how one table holds text next to numbers (data structures guide (opens in a new tab)).

python
import pandas as pd

df = pd.DataFrame({
    "trail": ["T01", "T02", "T03", "T04"],
    "distance_km": [3, 13, 5, 15],
    "climb_m": [100, 420, 250, 180],
    "difficulty": ["easy", "hard", "easy", "hard"],
})
df["hours"] = df["distance_km"] / 5 + df["climb_m"] / 600     # whole-column arithmetic
print(df.loc[df["climb_m"] > 150, ["trail", "climb_m"]])       # rows T02, T03 and T04
print(df.groupby("difficulty")["hours"].mean().round(2))       # easy 1.09, hard 3.30

Four ideas cover most day-to-day pandas:

  • Selection. df["climb_m"] returns one column as a Series. df.loc[rows, columns] selects by label or by a boolean mask, and df.iloc[rows, columns] selects by integer position.
  • Columns are arrays. Arithmetic on a column is vectorized like NumPy, and df[["distance_km", "climb_m"]].to_numpy() hands the values over as an array.
  • Split, apply, combine. groupby splits the rows into groups, applies a function such as mean to each group and combines the results into a new table.
  • Alignment by label. When two Series are added, pandas matches index labels, not positions. A label present on only one side produces NaN, the marker for a missing value.

pandas 3.0 changed two defaults (release notes (opens in a new tab)). Text columns now have the dtype str instead of object. And every selection behaves as a copy (Copy-on-Write), so df[mask]["col"] = value never changes df. Write df.loc[mask, "col"] = value instead.

Matplotlib and Seaborn: look before you model

Matplotlib draws on a Figure, the whole image, which contains one or more Axes, each a single plot with its own x and y axis. The explicit interface creates both and then calls methods on them:

python
import matplotlib.pyplot as plt

fig, ax = plt.subplots()
ax.scatter(df["distance_km"], df["climb_m"])
ax.set_xlabel("Distance (km)")
ax.set_ylabel("Climb (m)")
fig.savefig("trails.png")

The implicit interface (plt.scatter(...), plt.xlabel(...)) acts on whichever Axes was created last. It is convenient for a quick look. The Matplotlib quick start (opens in a new tab) recommends the explicit style for complicated plots and for code you will reuse.

Seaborn (opens in a new tab) is built on Matplotlib and works directly with DataFrames. You pass the table and say which column plays which role:

python
import seaborn as sns

ax = sns.scatterplot(data=df, x="distance_km", y="climb_m", hue="difficulty")

Seaborn picks a colour for each difficulty, adds the legend and labels the axes with the column names. Functions such as scatterplot and histplot draw on one Matplotlib Axes and return it, so ax.set_title(...) still works. Functions such as relplot, displot and catplot create a whole figure and can split it into small plots by a column with col=.

scikit-learn: fit, transform, predict

Every model and every preprocessing step in scikit-learn is an estimator, and all estimators share the same few methods (getting started guide (opens in a new tab)).

MethodWhat it doesWho has it
fit(X, y)Learns from data and stores the result in attributes ending in an underscoreEvery estimator
transform(X)Applies what was learned and returns changed featuresTransformers: scalers, encoders, imputers
predict(X)Applies what was learned and returns one prediction per rowClassifiers and regressors

X is a table of shape (n_samples, n_features): one row per sample, one column per feature. y holds one target per row. Settings you choose yourself, called hyperparameters, go into the constructor, as in KNeighborsClassifier(n_neighbors=3).

python
from sklearn.preprocessing import StandardScaler

X_train = np.array([[3.0, 100.0], [13.0, 420.0], [5.0, 250.0], [15.0, 180.0]])
scaler = StandardScaler().fit(X_train)             # learns each column's mean and standard deviation
print(scaler.mean_, scaler.scale_.round(1))        # [  9.  237.5] [  5.1 118. ]
print(scaler.transform([[14.0, 300.0]]).round(2))  # [[0.98 0.53]]

Only fit learns. Honest evaluation depends on one rule that follows from this: call fit, or the shortcut fit_transform, on training rows only, and call transform on every row. Breaking the rule causes data leakage: information that will not exist at prediction time, such as the mean of the test rows, shapes the model and makes its test score look better than it is (common pitfalls (opens in a new tab)).

A Pipeline applies the rule for you by chaining transformers and a final model into one estimator:

python
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline

y_train = ["easy", "hard", "easy", "hard"]
model = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=3))
model.fit(X_train, y_train)             # scaler: fit_transform, then classifier: fit
print(model.predict([[14.0, 300.0]]))   # scaler: transform only, then classifier: predict -> ['hard']

Because a pipeline is itself an estimator, cross-validation refits all of its steps on each training fold, and a step's setting is reachable by name, as in model.set_params(kneighborsclassifier__n_neighbors=5). For tables with mixed column types, ColumnTransformer sends each group of columns to its own transformer, for example scaling the numeric columns and one-hot encoding the text ones, and serves as the first step of a pipeline (pipeline guide (opens in a new tab)).

Worked example: Is a 14 km trail with 300 m of climb easy or hard? From a CSV file to a prediction

Twelve hiking trails, each with a distance, a total climb and a difficulty label. The numbers are invented. The labels follow a rule made up for this example: estimated walking time is distance_km / 5 + climb_m / 600 hours, and a trail is "hard" when that exceeds 3 hours. Real data never arrives with its rule attached. Knowing it here lets us check the model's answer. The new trail is 14 km long with 300 m of climb, which the rule puts at 14 / 5 + 300 / 600 = 3.3 hours, so the right answer is "hard".

Twelve rows, four columns, two of them numeric. Hard trails are on average about twice as long and climb more than twice as much. The two features also live on very different scales: distances run from 3 to 18, climbs from 100 to 1,100.

Step 2: nearest neighbours with NumPy, on the raw numbers

A simple model: find the three trails most similar to the new one and take the majority label. This is k-nearest neighbours with k = 3, where "similar" means a small straight-line distance between two rows of features.

python
X = df[["distance_km", "climb_m"]].to_numpy(dtype=float)   # shape (12, 2)
y = df["difficulty"].to_numpy()
new = np.array([14.0, 300.0])                              # shape (2,)

raw = np.sqrt(((X - new) ** 2).sum(axis=1))                # 12 distances, no loop
nearest = np.argsort(raw)[:3]
print(df["trail"].to_numpy()[nearest], y[nearest], raw[nearest].round(1))
text
['T12' 'T06' 'T08'] ['easy' 'easy' 'easy'] [ 4.  22.4 50.6]

X - new broadcasts a (2,) array against a (12, 2) array, and sum(axis=1) adds across the two columns to leave one number per trail. The vote is three to nil for "easy", which is wrong. T06 is a 4 km walk, 10 km shorter than the new trail, yet it counts as close because its climb differs by only 20 m: the distance is the square root of 10² + 20², or 22.4. T02, at 13 km and 420 m, is a far more similar day out, but its 120 m of extra climb puts it at a distance of 120. Metres swamp kilometres simply because the numbers are bigger.

Step 3: standardise the columns, again by broadcasting

python
mean, std = X.mean(axis=0), X.std(axis=0)
Z = (X - mean) / std                                       # every column: mean 0, std 1
z_new = (new - mean) / std
scaled = np.sqrt(((Z - z_new) ** 2).sum(axis=1))
nearest = np.argsort(scaled)[:3]
print(mean.round(2), std.round(2), z_new.round(3))
print(df["trail"].to_numpy()[nearest], y[nearest], scaled[nearest].round(2))
text
[  9.17 439.17] [  4.41 297.81] [ 1.095 -0.467]
['T04' 'T02' 'T12'] ['hard' 'hard' 'easy'] [0.46 0.46 0.91]

Each column is now measured in standard deviations from its own mean, so one unit of distance and one unit of climb count equally. The new trail sits 1.1 standard deviations above the average distance and 0.5 below the average climb. Its neighbours are now T04, T02 and T12, and the vote is two to one for "hard", the right answer.

Step 4: the same computation as a scikit-learn pipeline

python
from sklearn.model_selection import LeaveOneOut, cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

features, target = df[["distance_km", "climb_m"]], df["difficulty"]
new_trail = pd.DataFrame({"distance_km": [14], "climb_m": [300]})

plain = KNeighborsClassifier(n_neighbors=3)
model = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=3))

print(plain.fit(features, target).predict(new_trail))
print(model.fit(features, target).predict(new_trail))
print(model[0].mean_.round(2), model[0].scale_.round(2))
for name, estimator in [("plain", plain), ("pipeline", model)]:
    scores = cross_val_score(estimator, features, target, cv=LeaveOneOut())
    print(name, scores.mean())

Step 5: read the result

  • The two libraries agree. The plain classifier repeats Step 2 and the pipeline repeats Step 3. The mean_ and scale_ that fit stored in the scaler are the mean and standard deviation NumPy computed by hand.
  • fit took DataFrames directly. scikit-learn read the two feature columns from the DataFrame, and predict returned a NumPy array of labels.
  • Cross-validation shows the gap on more than one trail. LeaveOneOut predicts each trail from the other eleven. The plain model gets 9 of 12 right and the pipeline gets 12 of 12.
  • The pipeline kept the evaluation honest. In each of the twelve rounds, cross_val_score refitted the scaler on the eleven training trails only. The trail being predicted never contributed to the mean or the standard deviation.

Twelve rows whose labels come from a clean rule are enough to show the mechanics and nothing more. A perfect score here says nothing about how the model would do on real trails.

Edge cases and limitations

An (n, 1) array minus an (n,) array gives an n-by-n grid
Broadcasting stretches both arrays instead of raising an error. With predictions of shape (3, 1) holding 1, 2, 3 and targets of shape (3,) holding 1, 2, 5, the difference has shape (3, 3) and its mean squared value is 4.0, where the correct mean squared error is 1.33. This happens when a model returns a column and the targets are a flat array. Print the shapes of both arrays before subtracting, and flatten the column with ravel() or reshape(-1).
A NumPy slice shares memory, while a pandas selection behaves as a copy
Assigning into a NumPy slice such as X[:2] changes X, because the slice is a view of the same memory. In pandas 3.0 the opposite holds: with Copy-on-Write every selection behaves as a copy, so changing a column you pulled out of a DataFrame leaves the DataFrame untouched, and a chained assignment such as df[mask]["col"] = value changes nothing and raises a ChainedAssignmentError warning. Use .copy() in NumPy when you want independence, and a single df.loc[mask, "col"] = value in pandas when you want to modify the table.
One missing value turns a column of whole numbers into decimals
NaN, the default marker for a missing number, is a floating-point value. When read_csv meets an empty cell in a column of integers, the column becomes float64 and 100 is shown as 100.0. NaN is also not equal to itself, so df["col"] == np.nan is False on every row, and missing values have to be found with isna(). Reductions such as mean() skip NaN by default, which changes how many rows the result is based on. If the values must stay integers, request the nullable dtype "Int64", which shows a missing entry as <NA>.
A filtered DataFrame keeps its original row labels
After hard = df[df["difficulty"] == "hard"] on the four-row table, the index of hard is [1, 3], not [0, 1]. hard.loc[0] raises a KeyError, while hard.iloc[0] returns the first remaining row. Adding a new two-element Series, whose labels are 0 and 1, matches only label 1 and gives NaN for the others. Use iloc for positions, call reset_index(drop=True) after filtering when the old labels no longer mean anything, or convert to NumPy when you want purely positional arithmetic.
Integer arrays truncate decimals and small integer types wrap around
An array keeps its dtype when you assign into it. Writing 2.9 into an int64 array stores 2, with no warning. Arithmetic stays within the dtype too: adding 100 to a uint8 value of 200 gives 44, because uint8 holds only 0 to 255. Image data is commonly stored as uint8, so this appears as soon as you brighten or add images. Check dtype after loading, and convert with astype(float) before arithmetic that can leave the range.
scikit-learn expects a two-dimensional X even for a single feature
X must have shape (n_samples, n_features). With scikit-learn 1.9, passing a flat NumPy array raises a ValueError that begins "Expected 2D array, got 1D array instead", and passing a single pandas Series raises one that begins "Expected a 2-dimensional container". Use X.reshape(-1, 1) for one feature in NumPy, or select with double brackets in pandas, df[["climb_m"]], which returns a one-column DataFrame instead of a Series. The target y is the opposite: it is expected to be flat, and a one-column y produces a DataConversionWarning.

When to use it, and when something simpler is enough

Use it when

  • The data is a table or a grid of numbers that fits in the memory of one machine, and you need to clean, summarise, plot or model it.
  • You are training classic models on rows and columns, such as linear models, nearest neighbours, trees or boosted ensembles, and want to compare several with the same code.
  • The same preprocessing has to be applied when training and when predicting, which is what a Pipeline guarantees.
  • You want an analysis someone else can rerun, because a script or notebook records every step from file to chart in a way a hand-edited spreadsheet does not.

Think twice when

  • The data does not fit in memory. Aggregate it first in a database or data warehouse with SQL, or use a tool built for larger-than-memory data, and bring only the result into pandas.
  • You are training deep neural networks on a GPU. scikit-learn targets classic models on the CPU, so a framework such as PyTorch is the tool, although its tensors work much like NumPy arrays.
  • The job handles one record at a time with many branches, as in a request handler. A DataFrame adds overhead and nothing else for single rows, and plain Python objects are simpler.

A simpler alternative. For a one-off look at a few hundred rows, a spreadsheet or a few lines of plain Python with the built-in csv module is enough. That stops being enough when the same steps must run again on next month's file, when you want to train and evaluate a model, or when the table outgrows what a spreadsheet handles comfortably.

Key takeaways

  • A NumPy array holds values of one type in one block of memory, so an expression on whole arrays runs its loop in compiled code and replaces a Python loop.
  • Broadcasting compares shapes from the right and stretches dimensions of size 1, so check shapes whenever two different shapes meet, because the result can be the wrong shape without an error.
  • A DataFrame is a set of named, typed columns that share an index. Select with loc and boolean masks, summarise with groupby, and remember that pandas matches rows by label.
  • Matplotlib builds a chart from a Figure and its Axes, method by method, and Seaborn draws statistical charts on top of it from a DataFrame and column names.
  • In scikit-learn, fit learns from data while transform and predict apply what was learned, and only training rows may be passed to fit.
  • A Pipeline joins preprocessing and model into one estimator, which keeps test rows out of fitting during cross-validation and applies identical steps at prediction time.

Example 1 of 5

Event Horizon Telescope: NumPy arrays at every step of imaging a black hole

Event Horizon Telescope collaboration (eht-imaging library)Documented in a case study

The NumPy project's case study "First Image of a Black Hole" and the Nature paper "Array programming with NumPy" (Harris and co-authors, 2020) both describe the Python software the Event Horizon Telescope collaboration used to produce the first image of the black hole at the centre of the galaxy M87. The README of the eht-imaging repository lists the libraries that software depends on. [18][19][23]

The problem

The Event Horizon Telescope is an array of eight ground-based radio telescopes that together act as one computational telescope the size of the Earth. The case study lists the data-processing difficulties: rapid atmospheric phase fluctuations, a large recording bandwidth, telescopes that are dissimilar and far apart, and more than 350 terabytes of observations a day. It also poses a question of trust: when the goal is to see something nobody has seen, how can the scientists be confident the image is correct?

Where this topic fits

The NumPy array is the common data structure between the stages of the analysis and between the libraries used in it. Calibration and image reconstruction work on arrays, and the specialised libraries for image processing, optimisation, astronomy file formats and plotting all accept and return them.

How it is applied, step by step

  1. The recordings, which the case study puts at more than 350 terabytes a day, first have to be reduced in volume and complexity before they can be analysed.
  2. From there the numerical data are held in NumPy arrays through calibration and image reconstruction. In array code of this kind, a correction is written as one operation on a whole array instead of a loop over single measurements, which is the vectorized style from this lesson.
  3. Specialised libraries take the same arrays as input: SciPy for filtering and image alignment, scikit-image for edge filters and Hough transforms, and scipy.optimize for mathematical optimisation.
  4. Astropy reads and writes the standard astronomical file formats and converts between time and coordinate systems.
  5. Independent teams reconstruct images with different techniques, and the results are combined once they prove consistent. NetworkX is used to verify that the image comparisons are consistent.
  6. Matplotlib plots the data throughout the analysis and renders the final image.

Why this approach fits

Radio-telescope data are large grids of numbers of one kind, which is exactly the case typed arrays are designed for: compact storage and arithmetic on whole arrays in compiled code. The second benefit is the shared format. Because every library in the chain speaks NumPy arrays, a filter from SciPy, an optimiser, a file reader from Astropy and a plotting call from Matplotlib can be combined without conversion code, and independent teams can build different reconstruction methods from the same parts.

Limitation or tradeoff

NumPy arrays live in the memory of one machine and are computed on the CPU. A day of recordings at the scale the case study reports cannot be loaded as arrays, so the volume has to be reduced first. The Nature paper states the limit itself: because of its in-memory data model, NumPy cannot directly use storage spread over several machines or accelerator hardware such as GPUs. It points to other array libraries for those cases, among them Dask, CuPy, PyTorch and JAX, which often mimic NumPy's interface.

What the sources document

  • The Event Horizon Telescope is an array of eight ground-based radio telescopes forming a computational telescope the size of the Earth, and it generates over 350 terabytes of observations each day. [18]
  • The collaboration had independent teams evaluate the data with both established and cutting-edge image reconstruction techniques, and combined the results when they proved consistent. [18]

The problem

The documentation states the starting point directly: to use data from a wide variety of sources, it has to be brought into a common format. Each indicator also has to keep its metadata, such as its unit, description, sources and licences, while the table it belongs to is filtered, joined and reshaped on the way to publication.

Where this topic fits

The DataFrame is the in-memory form of a table in the processing steps. The project's Table class is a pandas DataFrame extended with metadata, and a Variable is the equivalent of a pandas Series. The step before takes a snapshot of the upstream file, and the step after adapts the result to the project's MySQL database.

How it is applied, step by step

  1. A snapshot step stores a copy of the upstream data, so the source file stays available even if the provider changes or removes it.
  2. A meadow step brings the data into the common format: a table with a primary key, for example country and year, and one column per indicator.
  3. In Python that table is a Table object. Because it is a DataFrame, the usual pandas operations apply to it: boolean masks, loc, sorting and arithmetic on columns.
  4. A garden step harmonises names such as countries and does the processing. Slicing, filtering and sorting keep the metadata, and joins go through the library's own merge function so that the metadata of both inputs is combined.
  5. The table is saved as a Feather or Parquet file with a JSON metadata file beside it. Those file formats keep the column dtypes, so types do not have to be described again in the metadata.
  6. A grapher step adapts the data to the internal MySQL database, after which it is available for publication on the site.

Why this approach fits

The data model, a table with a primary key and typed indicator columns, is what a DataFrame with an index already is. Extending the DataFrame, instead of inventing a new container, gives every data manager the pandas vocabulary they already know and keeps all of its operations available. The only thing added is what pandas lacks: descriptive metadata attached to the table and to each column.

Limitation or tradeoff

Plain pandas functions know nothing about the added metadata. The library therefore ships its own processing module of metadata-aware replacements for functions such as merge, concat and pivot, and code has to call those versions to be sure the metadata survives. Tables are also held in memory like any DataFrame, and a class that extends pandas is exposed to behaviour changes between pandas versions, such as the new text dtype and copy rules in pandas 3.0.

Hunter had written an EEG analysis application in MATLAB. As it grew to talk to databases and HTTP servers and to handle complex data structures, he ran into MATLAB's limits as a programming language and started again in Python. Where this topic fits

Matplotlib is the plotting layer of the stack. It receives arrays, and the history page notes that it makes heavy use of NumPy. In the EEG application it draws inside the program's own window. The same plotting code can instead write a file for a paper, because drawing is separated from output.

How it is applied, step by step

  1. The data to be plotted, such as a signal over time, is held in arrays.
  2. A set of plotting functions modelled on MATLAB's commands, the pylab interface that today's pyplot continues, lets a simple plot be made in a few calls.
  3. Those functions drive the frontend: classes that create and manage figures, text and lines, and that know nothing about where the result will be shown.
  4. A backend turns that description into output. Agg produces PNG, PS produces PostScript, SVG produces vector graphics, and the GTK backends embed the figure in a Gtk+ application.
  5. The EEG application uses the embedding backend, and the same figure can be written to a file for a publication by choosing a different one.
  6. The two layers of user code survive as the implicit pyplot interface and the explicit Axes interface used in this lesson.

Why this approach fits

Separating what is drawn from how it is rendered let one library meet requirements that pull in different directions: interactive plots inside an application and print-quality files for publication. Limitation or tradeoff

The pyplot functions act on a hidden current Figure and Axes, which is convenient for one plot and error-prone with several, and examples mix the two styles. XGBoost: a separate library that plugs into scikit-learn by implementing fit and predict

XGBoost projectDocumented in official docs

XGBoost is a gradient boosting library with its own native training interface. Its documentation page on the scikit-learn estimator interface describes a second interface written to scikit-learn's estimator guideline, and scikit-learn's developer guide defines that guideline. [25][14]

The problem

A model that lives in another library cannot be used with scikit-learn's evaluation and selection tools unless it behaves like a scikit-learn estimator. XGBoost's native interface has its own data and model objects, so without an adapter a user who wanted to cross-validate an XGBoost model next to a scikit-learn model would need separate code for each.

Where this topic fits

The estimator interface is the contract between the two libraries. XGBoost supplies classes such as XGBClassifier that take hyperparameters in the constructor and expose fit and predict. scikit-learn's utilities call only those methods, so they need no knowledge of XGBoost.

How it is applied, step by step

  1. Hyperparameters are passed to the constructor, for example the tree construction method. Following scikit-learn's convention, the constructor only stores them.
  2. fit(X_train, y_train) trains the boosted trees on the feature table and the targets.
  3. A utility such as cross_validate copies the unfitted estimator for each fold, calls fit on the training part and scores the held-out part. It contains no XGBoost-specific code.
  4. predict returns one prediction per row, as any scikit-learn classifier or regressor does, so the output feeds the same metrics.
  5. When a feature exists only in the native interface, get_booster() returns the underlying native model object from the fitted estimator.

Why this approach fits

A small shared interface lets an ecosystem grow without central coordination. scikit-learn does not have to include or even know about every algorithm, and a new library gets cross-validation, parameter search and pipelines by implementing a handful of methods. For the user, swapping one model for another becomes a one-line change, which makes fair comparisons cheap.

Limitation or tradeoff

The adapter does not expose everything. The XGBoost page says the scikit-learn interface mainly supports training and lacks some native features, and that survival training through it is unfinished. Early stopping needs an evaluation set passed to fit, which generic cross-validation tools do not supply, and the page calls early stopping during cross-validation an imperfect approach. Two libraries that each use every CPU thread can also slow each other down, so the thread settings need attention.

What the sources document

  • In addition to its native interface, XGBoost has a scikit-learn estimator interface that conforms to the scikit-learn estimator guideline and supports regression, classification and learning to rank. [25]
  • The page gives as the main advantage of this interface that it works with most of the utilities provided by scikit-learn, such as cross_validate, and adds that many other libraries recognise the scikit-learn estimator interface. [25]
  • The scikit-learn interface primarily facilitates training and does not implement all features available in XGBoost; the native booster object can be obtained from it with get_booster. [25]
  • scikit-learn's developer guide says that fit should return the estimator itself, that the constructor should contain no logic, and that attributes learned from data must have names ending with an underscore. It gives use with tools such as GridSearchCV and Pipeline as the main motivation for making a class compatible. [14]
  • When XGBoost and scikit-learn are both set to use all threads, the computer may slow down significantly because of thread thrashing, and the page advises setting the n_jobs parameters so that only one of them parallelises. [25]

The press release describes a Data Lab whose algorithms automate tasks such as checking certain insurance policy clauses, processing supporting documents and settling claims. It does not say which library each of those tools uses. In the testimonial, the company says that several of its machine learning models run in production on scikit-learn and that its internal model risk governance names two risks to reduce: operational risk and overfitting risk. Read in model-building terms (our interpretation), the first is the chance that the system in production does something different from what was validated, and the second is the chance that the validated score was too optimistic.

Where this topic fits

The Pipeline is the unit that gets validated and deployed. Preprocessing and model are one estimator, so the thing whose score is reviewed is the same thing that later produces predictions.

How it is applied, step by step

  1. The testimonial names the practice and not its implementation, so these steps describe how a pipeline-based workflow typically satisfies such a rule. Every preprocessing step that learns from data, such as imputation, scaling, encoding or feature selection, is a transformer inside one Pipeline together with the model.
  2. Validation runs cross-validation on the whole pipeline. In every fold all steps are fitted on the training part only, so the held-out part never influences a mean, a list of categories or a choice of features.
  3. The reported score therefore describes the whole procedure on unseen rows, which is the defence against an over-optimistic estimate.
  4. The fitted pipeline is saved and deployed as a single object. Production code calls predict on raw rows and the pipeline applies the stored transformations in the stored order, so there is no hand-copied preprocessing that can drift from the validated version.
  5. A reviewer can list every step and every parameter of the pipeline with get_params, which gives a governance review something concrete to inspect.

Why this approach fits

The two risks in the testimonial line up with two failure modes the scikit-learn documentation demonstrates. Its page on common pitfalls shows a model whose test error is far worse when the test data is not transformed the way the training data was, which is an operational failure, and a model that appears to predict random labels when feature selection has seen the test rows, which is an inflated estimate. A rule that says "use a pipeline" removes both by construction, and it is easy to audit because the pipeline's presence can be checked in code review.

Limitation or tradeoff

A pipeline protects only what is inside it. Rows filtered, values filled or features built in pandas before the split are outside its reach and can still leak or differ in production. It also cannot tell whether the training data represent future cases. And a saved pipeline has to be loaded with library versions compatible with the ones that saved it, so the environment must be recorded with the file.

4Common mistakes

  1. Looping over the rows of a DataFrame, with iterrows or apply(axis=1), to do arithmetic.

    Why it causes problems
    Each row is turned into a Python object and handled by the interpreter, so the advantage of compiled code is lost. On a 100,000-row table in our check, a column expression took about 0.1 ms, apply with axis=1 about 200 ms and iterrows about 700 ms. On a real table the same pattern turns a one-second job into many minutes.
    How to recognise it
    A for loop that contains iterrows(), or apply(..., axis=1) with a lambda that only adds, multiplies or compares columns. A notebook cell that takes seconds on a table of modest size.
    How to fix it
    Write the arithmetic on whole columns, as in df["distance_km"] / 5 + df["climb_m"] / 600. Use boolean masks or numpy.where for conditions and groupby for per-group calculations. Keep explicit loops for the rare logic that cannot be expressed on columns.

  2. Fitting a scaler, imputer, encoder or feature selector on all rows before splitting or cross-validating.

    Why it causes problems
    The preprocessing step has learned from rows that are later used to test the model, so the score is biased upwards. The scikit-learn documentation shows feature selection done this way reaching 0.76 accuracy on random data, where the honest figure is 0.5. A model chosen on such a score disappoints once it meets new data.
    How to recognise it
    A call to fit or fit_transform on the full X appears above train_test_split or cross_val_score. The cross-validated score is clearly better than the performance on data collected later.
    How to fix it
    Split first. Put every step that learns from data into a Pipeline, and pass the pipeline, not the model alone, to cross_val_score or to a parameter search.

  3. Calling fit_transform on the test set, or forgetting to transform the test set at all.

    Why it causes problems
    fit_transform on the test rows relearns the mean and scale from them, so training and test rows are measured with different rulers. Skipping the transformation feeds raw values to a model trained on scaled ones. In the scikit-learn documentation's example of the second case, the mean squared error is 62.80 where the correct procedure gives 0.90.
    How to recognise it
    The text scaler.fit_transform(X_test) appears in the code, or predict receives X_test although the model was fitted on a transformed X_train.
    How to fix it
    Call fit_transform on the training rows and transform on everything else, or let a Pipeline do both, so that the right method is called on the right rows automatically.

  4. Using pyplot calls such as plt.xlabel on a figure that has several Axes.

    Why it causes problems
    The pyplot functions act on the Axes that was created last. After fig, axs = plt.subplots(1, 2), a call to plt.xlabel labels only the second plot and leaves the first one bare, and the same happens with titles and axis limits. The chart looks finished and is partly unlabelled or mislabelled.
    How to recognise it
    A script mixes plt.subplots with plt.xlabel, plt.title or plt.ylim. In the output only the last panel carries the labels.
    How to fix it
    Keep the objects that plt.subplots returns and call methods on the one you mean, such as axs[0].set_xlabel(...) and axs[1].set_title(...). Reserve the plt functions for a single quick plot.

  5. Computing on a freshly loaded table without checking df.dtypes and the number of missing values.

    Why it causes problems
    One stray text entry, such as the word unknown in a numeric column, makes pandas read the whole column as text. Multiplying that column by 2 then repeats the text, so "100" becomes "100100", sum joins the strings end to end, and mean raises a TypeError. A missing value in a column of whole numbers turns it into floats without a message.
    How to recognise it
    df.dtypes shows str or object for a column that should be numeric, or float64 for a column of counts. Results look like long strings of digits, or an error message mentions the string dtype.
    How to fix it
    Print df.dtypes and df.isna().sum() straight after loading. Convert a dirty column with pd.to_numeric(df["col"], errors="coerce"), which turns entries that cannot be parsed into NaN, and then decide what to do with those rows.

  5. Print the names of the pipeline's steps, change k to 5 through set_params, refit, and confirm that the selector now passes 5 columns to the classifier.
  6. Say which of the four accuracy figures you would report, and why.

Requirements

  • Use the starting code unchanged, so that your numbers can be compared with the expected ones.
  • In part 1, call the selector's fit_transform on all rows before cross-validation. In part 3, the selector must only ever be fitted inside the pipeline.
  • Build the pipeline with make_pipeline and address the selector's parameter by its step name in set_params.
  • Report accuracies to three decimals and state the NumPy and scikit-learn versions you used.

Expected behaviour

With NumPy 2.5.3 and scikit-learn 1.9.1 the four figures are:

  • leaky cross-validated accuracy: 0.795
  • pipeline cross-validated accuracy: 0.510
  • training accuracy of the fitted pipeline: 0.875
  • accuracy on the 2,000 fresh rows: 0.504

Other versions can differ in the last digits. The pattern does not change: the leaky and training figures are far above 0.5, and the two honest figures are close to it. The step names are selectkbest and logisticregression, and after set_params(selectkbest__k=5) the selector outputs an array of shape (200, 5).

Hint 1

With 5,000 random columns and only 200 rows, some columns line up with the labels by chance. On which rows was that chance alignment measured?

Hint 2

make_pipeline names each step after its class in lower case, and a step's parameter is addressed as stepname__parameter with two underscores.

Hint 3

model[:-1] is the pipeline without its last step, so model[:-1].transform(X) shows what the classifier receives.

Show solution
python
import numpy as np
from sklearn.feature_selection import SelectKBest
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(0)
X = rng.normal(size=(200, 5000))          # 200 rows, 5,000 columns of pure noise
y = rng.integers(0, 2, size=200)          # labels unrelated to X
X_fresh = rng.normal(size=(2000, 5000))   # rows the model will never train on
y_fresh = rng.integers(0, 2, size=2000)

# 1. Leaky: the selector is fitted on every row before cross-validation
X_selected = SelectKBest(k=20).fit_transform(X, y)
leaky = cross_val_score(LogisticRegression(), X_selected, y, cv=5)
print(f"leaky CV accuracy:    {leaky.mean():.3f}")

# 3. Honest: the selector is a pipeline step, refitted inside each training fold
model = make_pipeline(SelectKBest(k=20), LogisticRegression())
honest = cross_val_score(model, X, y, cv=5)
print(f"pipeline CV accuracy: {honest.mean():.3f}")

# 4. Reality check
model.fit(X, y)
print(f"training accuracy:    {model.score(X, y):.3f}")
print(f"fresh-data accuracy:  {model.score(X_fresh, y_fresh):.3f}")

# 5. Inspect and reconfigure the pipeline
print([name for name, step in model.steps])
model.set_params(selectkbest__k=5)
print(model[0].k, model.fit(X, y)[:-1].transform(X).shape)

Part 2. SelectKBest.fit_transform(X, y) scored all 5,000 columns against the labels of all 200 rows and kept the 20 that happened to line up best. With that many random columns, some line up well by chance. Cross-validation then held out 40 rows at a time, but those rows had already helped to choose the columns, so the chance alignment holds on them too. The call to fit on rows that later serve as test rows is the leak. The classifier is not at fault.

Part 3. Inside the pipeline, cross_val_score refits the selector on the 160 training rows of each fold. The 20 columns it picks line up with those 160 labels by chance and have no relation to the 40 held-out labels, so accuracy falls to 0.510, which is what guessing gives.

Part 4. The training accuracy of 0.875 shows how well 20 chance-selected columns can describe the very rows they were selected on. The 2,000 fresh rows give 0.504. The pipeline's cross-validated figure predicted that almost exactly, and the leaky figure was wrong by about 29 percentage points.

Part 5. make_pipeline named the steps after their classes. selectkbest__k reaches the k parameter of the selectkbest step, which is the same naming a parameter search uses. model[:-1] is the pipeline without the classifier, and its output has 5 columns after the change.

Part 6. Report the pipeline's cross-validated accuracy, 0.510, and say plainly that it is indistinguishable from guessing. It is the only figure produced without the scored rows taking part in any fitting, and the fresh-data result confirms it. The colleague's 80 % came from the procedure and would have been the same on any random data of this shape.
