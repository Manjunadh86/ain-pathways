Decision Trees

A decision tree is a model that predicts by asking a sequence of yes/no questions about the input features, such as "is the distance at most 6.75 km?", and returning the answer stored at the end of the path. Training picks the questions one at a time so that each one leaves groups whose target values are as alike as possible.

1Overview

Why it matters

A decision tree is one of the few machine learning models that can be printed on a page and checked by someone who has never trained a model. That is why trees turn up where a prediction has to be explained or executed by hand: a bedside risk rule a clinician can apply from three admission measurements, a classifier small enough to run inside a motion sensor, a flowchart that summarises what a more complex model is doing. Trees are also the building block of random forests and gradient boosting, so their behaviour carries over to those methods.

The trouble is that the same algorithm that produces a tidy three-question tree will, with default settings, keep asking questions until it has memorised every training row, and it will produce a visibly different tree when a handful of rows change. Analysts and ML engineers who use trees need to know how splits are chosen, how to limit and prune a tree using held-out data, and how much weight a printed tree and its feature ranking can bear before they present either as a finding.

Key terms

Node
A point in the tree that holds a subset of the training rows. An internal node asks a question and passes each row to one of its two children.
Root
The first node, which holds all the training rows and asks the first question.
Leaf
A node with no question. It stores the prediction, which is the majority class or the mean target of the training rows that reached it.
Split
The question at an internal node, written as one feature compared with one threshold, for example visits <= 2.5.
Impurity
A number that measures how mixed the target values in a node are. It is zero when every row in the node has the same target.
Gini impurity
One minus the sum of the squared class fractions in a node. A 50/50 two-class node scores 0.5 and a pure node scores 0.
Entropy and information gain
Entropy is another impurity measure, in bits; a 50/50 two-class node scores 1. Information gain is the drop in entropy that a split achieves.
Variance reduction
The drop in the variance of a numeric target that a split achieves. Regression trees choose the split with the largest drop.
Depth
The number of questions on the longest path from the root to a leaf. A tree of depth 3 asks at most three questions per prediction.
Pruning
Removing branches from a grown tree and replacing each with a single leaf, to make the tree smaller and less fitted to noise.

Introduction

You have followed a decision tree before: a troubleshooting flowchart ("Is the light green? If not, restart the router"), a key for identifying a plant, the questions a support agent works through. Each answer narrows the possibilities, and after a few of them you reach a conclusion. A decision tree in machine learning is the same structure with one difference: nobody writes the questions. A training algorithm picks them from labelled examples.

Take a gym that offers a one-week free trial. For twelve past trial members it knows two features, the number of visits during the trial week and the distance from home to the gym, and the target it wants to predict: whether the person bought a membership. A tree trained on those twelve rows and pruned to three leaves (the worked example below shows how) looks like this:

To predict for a new person, start at the top (the root), answer the question, follow the matching branch, and repeat until you reach a box with no question in it (a leaf). The leaf holds the prediction: the majority class of the training rows that ended up there, or their average when the target is a number. Someone who lives 9 km away answers "no" at the root and lands in "did not join" after one question. Someone 3 km away who came four times answers two questions and lands in "joined".

Each question is a split: one feature compared with one threshold. Taken together, the splits cut the space of possible inputs into rectangles and give every rectangle one answer. That structure explains the model's strengths. It needs no feature scaling, it picks up thresholds and "this only matters when that is high" interactions without being told about them, and it can be read. It also explains the weaknesses. Left alone, the algorithm keeps cutting until every rectangle holds rows of one class only, which can mean a rectangle built for a single odd row, and a few changed rows can produce a different set of questions.

The rest of this lesson covers how the questions are chosen (recursive splitting guided by an impurity measure), how the same idea predicts numbers (variance reduction), how to stop a tree from memorising its training data (depth limits and pruning), and how far to trust what a printed tree says (interpretability and instability). It relies on train/test splits and cross-validation for choosing the size of a tree, and it prepares the ground for random forests and gradient boosting, which combine many trees.

How it works

Growing a tree: greedy recursive splitting

Training starts with every row in one node and repeats a single step:

  1. For every feature and every candidate threshold, divide the node's rows into a left group (feature at most the threshold) and a right group.
  2. Score each candidate by how mixed the two groups are.
  3. Keep the best one, create two child nodes, and run the same step on each child.

A node stops splitting when it is pure, when a limit such as maximum depth is reached, or when no split improves the score. For a numeric feature the candidate thresholds are the midpoints between neighbouring distinct values, so a feature with the values 2, 4 and 9 offers 3 and 6.5. Only the order of the values matters, which is why, as Google's course (opens in a new tab) points out, the search works the same whatever the scale or distribution of a feature.

The procedure is greedy: it takes the best split available now and never revisits the choice. Finding the best possible tree is NP-hard, so practical libraries use this heuristic, as the scikit-learn user guide (opens in a new tab) and the course page on growing trees (opens in a new tab) both note. scikit-learn implements an optimised version of CART (classification and regression trees), which always splits a node in two.

where HHH is the impurity measure, and nLn_LnL​ and nRn_RnR​ count the rows sent left and right. The tree keeps the split with the lowest GGG. The drop from the parent's impurity, H(parent)−GH(\text{parent}) - GH(parent)−G, is the impurity decrease; with entropy it is called information gain. The search fits in a few lines of Python:

python
def gini(labels):
    n = len(labels)
    return 1.0 - sum((labels.count(c) / n) ** 2 for c in set(labels))

def best_split(rows, labels):
    """Return (weighted_gini, feature_index, threshold) of the best split."""
    best = None
    for j in range(len(rows[0])):                  # every feature
        values = sorted({row[j] for row in rows})
        for low, high in zip(values, values[1:]):  # every midpoint
            t = (low + high) / 2
            left = [y for row, y in zip(rows, labels) if row[j] <= t]
            right = [y for row, y in zip(rows, labels) if row[j] > t]
            score = (len(left) * gini(left) + len(right) * gini(right)) / len(labels)
            if best is None or score < best[0]:
                best = (score, j, t)
    return best

On the twelve rows of the worked example below it returns (0.25, 1, 6.75): feature 1, threshold 6.75, weighted Gini 0.25.

Why not score splits by the error rate? Because the error rate cannot see some useful splits. Take a node with 80 rows of class A and 20 of class B, and a split that sends 30 A and 20 B left and 50 A right. Before the split, predicting A is wrong for 20 rows. After it, both children still predict A and 20 rows are still wrong, so the error rate reports no progress. Yet the right child is now pure and all the uncertainty sits in the left child, where the next split can work on it. Gini registers this (0.32 falls to 0.24), and so does entropy (0.722 falls to 0.485), because both curves bend while the error rate is a straight line on each side of 0.5. Therneau and Atkinson (opens in a new tab) give the same argument for the rpart library and add that, for two classes, Gini and entropy nearly always choose the same split point. In the depth experiment below, switching between them moved test accuracy by at most 2.6 points at any depth; depth itself moved it by about 8.

Regression trees: variance reduction

When the target is a number, a leaf predicts the mean of its training rows, and the impurity of a node is the mean squared distance from that mean, which is the variance of the node's targets:

H(node)=1n∑i∈node(yi−yˉ)2H(\text{node}) = \frac{1}{n} \sum_{i \in \text{node}} (y_i - \bar{y})^2H(node)=n1​i∈node∑​(yi​−yˉ​)2

Splits are scored with the same weighted average, and the improvement is called variance reduction. Here are eight illustrative load-test readings for an API: 10, 20, 30, 40, 50, 60, 70 and 80 concurrent users gave median latencies of 120, 126, 118, 132, 210, 222, 204 and 396 ms.

All eight readings have a mean of 191 ms and a variance of 7,699. Splitting at 45 users gives group means of 124 and 258 and a weighted variance of 3,210. Splitting at 75 users isolates the single 396 ms reading and gives 1,695, the lowest of the seven candidates, so the root split is users <= 75. The left child is then split at 45.

The fitted model is a staircase: 124 ms up to 45 users, 212 ms up to 75, and 396 ms beyond. Two things follow. A tree can only output averages of training targets, so it cannot extrapolate: at 200 users it still answers 396 ms. And squared error makes one extreme value worth isolating; with min_samples_leaf=2 the root split moves to 45. scikit-learn's DecisionTreeRegressor (opens in a new tab) uses criterion="squared_error" by default and also offers absolute_error, where a leaf predicts the median, and poisson for counts.

Depth, leaf size and pruning

With scikit-learn's default settings a tree grows until every leaf is pure; the DecisionTreeClassifier (opens in a new tab) notes describe the result as fully grown and unpruned. On noisy data that means memorising noise. The plot below comes from 1,000 points generated with make_moons(noise=0.4, random_state=1), half used for training and half for testing.

Training accuracy climbs to 100% at depth 15, where the tree has 91 leaves. Test accuracy peaks at 84% around depth 3 and then drifts down to 77%. There are two ways to stop short of that.

Stop early (pre-pruning). max_depth caps the number of questions, min_samples_leaf refuses any split that would leave a child with fewer rows than the given number, and max_leaf_nodes and min_impurity_decrease limit growth in other ways. The scikit-learn guide suggests looking at a tree with max_depth=3 first and trying min_samples_leaf=5 as an initial value.

Grow, then cut back (post-pruning). Minimal cost-complexity pruning scores a whole tree TTT as

where R(T)R(T)R(T) is the total impurity of the leaves, each weighted by its share of the training rows, ∣T∣\lvert T \rvert∣T∣ is the number of leaves, and α\alphaα is a price charged per leaf. For an internal node ttt with the branch TtT_tTt​ below it, the price at which collapsing the branch into one leaf breaks even is

The node with the smallest effective alpha is the weakest link and is pruned first. Repeating this gives a nested series of smaller trees, ending with the root alone. cost_complexity_pruning_path returns the alphas, and the ccp_alpha parameter selects a tree from the series; scikit-learn's pruning example (opens in a new tab) walks through it. Choose ccp_alpha, or the depth, by cross-validation on the training data. For the data in the plot, 5-fold cross-validation picks an alpha of 0.0074: a tree with 6 leaves that scores 84% on the test half, against 77% for the full tree. Libraries differ: Google's YDF, for example, holds back part of the training data and removes a branch (opens in a new tab) when doing so improves quality on the held-back part.

Interpretability and instability

A fitted tree is a list of if-then rules, one per leaf. Each leaf also gives a probability, which in scikit-learn is the fraction of the leaf's training rows that belong to each class. A domain expert can check a tree with a handful of leaves line by line. One with hundreds of leaves is transparent in principle and unreadable in practice.

The greedy procedure also makes trees unstable. Every split depends on the splits above it, and when two features carry similar information a few rows decide which one wins. To measure this, we split the breast cancer dataset bundled with scikit-learn into 426 training and 143 test rows and refitted a default tree on 100 bootstrap resamples of the training rows (the same number of rows, drawn with replacement):

Averaging away the instability in this way is the idea behind random forests, and it is why bias and variance is the next concept to study. For a single tree the working rule is to treat the printed structure as one reasonable description of the data, and to check that its top splits survive resampling before reporting them as findings.

Edge cases and limitations

Patterns where no single split helps (XOR)
If the class depends on two features jointly and on neither alone, every first split looks useless to a greedy search. On 400 points drawn with `RandomState(0).uniform(-1, 1, (400, 2))` and labelled by whether exactly one coordinate is positive, scikit-learn chose a root split at 0.96 on the first feature, slicing off a sliver, and trees of depth 1 and 2 scored 53% on their own training data. The unrestricted tree needed 11 leaves for a pattern that four rectangles describe. The scikit-learn guide lists XOR and parity among the concepts trees express poorly. If you suspect such an interaction, build the product or difference of the two features yourself.
Requests outside the range of the training data
A tree returns the value of the leaf a row falls into, and the outermost leaves extend to infinity. The latency tree in this lesson answers 396 ms for 80 users and for 200 users, because both satisfy users > 75. The scikit-learn guide states that tree predictions are piecewise constant and therefore poor at extrapolation. Record the minimum and maximum of each feature at training time, flag requests outside them, and use a model with a trend term when the target keeps growing.
Boundaries that run diagonally
Splits test one feature at a time, so a tree can only draw boundaries parallel to the axes. For 500 training points drawn uniformly from the unit square (`RandomState(0).uniform(0, 1, (500, 2))`, then 500 test points from the same generator) and labelled by whether the first feature exceeds the second, a default tree needed 20 leaves to approximate the diagonal as a staircase and scored 95.8% on the test points. Given the single engineered feature "first minus second", a two-leaf tree scored 100%. When a domain suggests ratios or differences, add them as columns before blaming the model.
Different trees from the same data and code
scikit-learn permutes the features at every split, even with splitter="best". When several candidate splits improve the criterion by exactly the same amount, the API documentation says one of them is selected at random, so the best split found can vary between runs even when all features are considered, and different random_state values can return different trees and slightly different scores. Set random_state for reproducible results, and read a tie as a sign that the data cannot tell the splits apart.
Categorical features and missing values in scikit-learn
The CART algorithm can split on categories directly, but the scikit-learn guide says its implementation does not support categorical variables for now, so they must be encoded as numbers first. One-hot encoding a column with hundreds of categories spreads its signal over hundreds of weak yes/no splits. Missing values are different: according to the guide, DecisionTreeClassifier and DecisionTreeRegressor with splitter="best" accept NaN and learn at each split which side the missing rows should go to.

When to use it, and when something simpler is enough

Use it when

  • The model must be read, audited or applied by hand, and a tree with roughly a dozen leaves or fewer is accurate enough for the decision.
  • The data are tabular with features on different scales and the target depends on thresholds and on combinations of conditions.
  • Prediction has to be extremely cheap, a few comparisons per row, for example in firmware or inside a database query.
  • You want a quick first look at which features and cut points separate the classes before building a stronger model.
  • You need a simple approximate description of what a complex model does, with its fidelity reported next to it.

Think twice when

  • Accuracy on tabular data matters more than having one readable model. A random forest or gradient boosting model built from many trees will usually score higher.
  • The target changes smoothly or linearly with the features, or you must predict beyond the range seen in training. A linear model fits a trend and a tree cannot.
  • You have few rows and many features. The tree will find splits that fit by chance and change from sample to sample.
  • The rules must stay the same from one retraining to the next. A single tree can change its top split when a small share of the rows changes.

A simpler alternative. A single threshold on one feature, chosen from a plot or from domain knowledge, which is a tree of depth one. If one cut-off already separates the outcomes about as well as a deeper tree does on held-out data, keep the cut-off. When several features each add a steady amount to the outcome and do not interact, logistic or linear regression is simpler to fit and gives smoother predictions; a tree starts to earn its place once the effect of one feature depends on the value of another.

Key takeaways

  • A decision tree is grown greedily, at each node choosing the one feature and threshold that leave the two child groups least mixed, and then repeating the search inside each child.
  • Gini impurity and entropy measure how mixed the classes in a node are, regression trees use the variance of the target in the same way, and a split is scored by the size-weighted impurity of its children.
  • A regression tree predicts the mean of a leaf, so its output is a staircase that cannot extrapolate beyond the training data.
  • With default settings a tree grows until it has memorised the training rows, so limit its depth or leaf size or prune it with ccp_alpha, and choose the setting by cross-validation.
  • A small tree is a readable set of rules, and each leaf's probability is only the class share among the training rows that reached it.
  • Trees are unstable because a few changed rows can change the top split, which is why single trees are checked by resampling and why ensembles of trees usually predict better.

ADHERE risk tree: three admission measurements sort heart-failure patients by risk of death

Fonarow et al. and the ADHERE Scientific Advisory Committee (JAMA)Documented in a paper

A 2005 paper in JAMA by Fonarow and colleagues applied classification and regression tree (CART) analysis to the Acute Decompensated Heart Failure National Registry (ADHERE) to derive and validate a bedside rule for in-hospital mortality. The paper's methods and results describe how the tree was grown, limited and tested. [10]

The problem

A clinician admitting a patient with acutely decompensated heart failure has to judge quickly how likely the patient is to die in hospital, using only what is known at admission. The registry collected 80 variables. A regression equation can combine many of them, but it has to be calculated. The authors wanted a rule that sorts patients into low, intermediate and high risk in two or three steps.

Where this topic fits

The tree is the entire model. It was grown once on a derivation cohort, applied unchanged to later admissions as a validation cohort, and is meant to be used at admission with three numbers from routine tests. Its output is a risk group, which can inform how closely a patient is monitored; it does not choose a treatment.

How it is applied, step by step

  1. Select 39 candidate predictors from the registry's variables and take the first 33,046 hospitalisations as the derivation cohort, with death in hospital as the outcome.
  2. Grow the tree with CART. At each node every value of every predictor is tried as a binary split, and the split that most reduces the residual sum of squares of the died/survived outcome is kept. For a 0/1 outcome a node's variance is p(1 - p), half its Gini impurity, so this criterion ranks splits exactly as Gini does.
  3. Keep leaves large: a node needs at least 800 records to be split, and each child must keep at least 400. This is pre-pruning by leaf size, so every reported mortality rate rests on hundreds of patients.
  4. Read off the result. The root split is blood urea nitrogen (BUN) of 43 mg/dL or more, both children split on systolic blood pressure below 115 mm Hg, and the high-BUN, low-pressure node splits once more on serum creatinine of 2.75 mg/dL or more. Further splits added little, leaving five leaves.
  5. Label the leaves as one low-risk group, three intermediate-risk groups and one high-risk group, and report the share of patients who died in each.
  6. Apply the same tree to the 32,229 later hospitalisations of the validation cohort, and compare its discrimination with a logistic regression model.

Why this approach fits

The deliverable is a rule a person can carry out, and a three-question tree is exactly that. Skewed laboratory values do not disturb a tree, because a split depends only on the order of the values; the paper makes the related point that CART needs no parametric assumptions. The tree also expresses an interaction that nobody had to specify: creatinine is consulted only for patients who already have high BUN and low blood pressure. Two safeguards from this lesson are visible as well. Minimum node sizes keep every rule from resting on a few patients, and the tree was tested on admissions it had never seen.

Limitation or tradeoff

Readability was paid for in accuracy. By area under the ROC curve the tree scored 68.7% on the derivation cohort against 75.9% for the authors' logistic regression model. A likely reason is that the tree reduces three measurements to five groups: patients with a BUN of 42 and 44 mg/dL fall into different groups although they are clinically almost identical, which is the piecewise-constant behaviour of every tree.

The authors add limits of their own. The method favours variables recorded for most patients, and some possible risk factors, such as B-type natriuretic peptide, were measured in fewer than a quarter of them. The registry holds no information after discharge, and the cohorts may contain repeat admissions of the same patient. They describe the model as something that enhances physician assessment and does not replace it.

USGS National Land Cover Database: tree models label every 30-metre pixel of a country

The problem

Every 30-metre pixel of the conterminous United States needs a land cover class (forest, cropland, water, developed land and so on) and an estimate of how much of it is covered by impervious surfaces such as roads and roofs, consistently for seven target years. Labelled examples exist only for a sample of pixels. The inputs are of very different kinds: Landsat imagery, the year a pixel was last disturbed, shape measures from image segmentation, and terrain elevation.

Where this topic fits

The trees sit in the middle of the pipeline. Before them come scene selection, change detection and the assembly of training samples. A decision tree turns the training samples into rules, the rules are applied to every pixel, and a refinement stage then corrects errors and enforces consistency over time. A separate regression-tree step predicts percent impervious surface, the layer from which the urban classes are taken.

How it is applied, step by step

  1. Select the satellite imagery, approximately 3,608 Landsat scenes for the seven target years, and assemble a training dataset for each land cover class and target year from Landsat images and derived indices, spectral change products, trajectory analysis and ancillary data.
  2. Run the C5 decision tree software on the training samples. Its predictors come in four sets: the disturbance year, the Landsat images, compactness indices from image segmentation, and a digital elevation model with its derivatives. The output is a set of decision rules.
  3. Apply the rules to every pixel for each target year to obtain a classified map. The classifier is run a second time without the Urban and Water classes and without the disturbance data.
  4. Separately, fit regression trees that predict percent impervious surface, a number from 0 to 100, from Landsat imagery, using training pixels derived from an earlier impervious layer and night-time lights imagery. Compare the resulting maps to remove false estimates.
  5. Refine the classified maps to correct errors, keep labels consistent across years and improve spatial coherence, taking the urban classes from the impervious layer.

Why this approach fits

The output format matters as much. Rules made of threshold comparisons are cheap to apply to a number of pixels that, by our arithmetic from the land area, runs into the billions. The project also shows both kinds of tree side by side: a classification tree for the class label and regression trees for a percentage.

Limitation or tradeoff

Accuracy depends on the training samples and varies by region: the design paper reports agreement with reference data between 71% and 97% across its test areas, and the 2016 metadata state that no formal accuracy assessment had yet been carried out. Apache Spark MLlib: growing one decision tree on data spread across a cluster

Apache Spark projectDocumented in an open-source project

MLlib, the machine learning library of the open-source Apache Spark engine, includes decision trees for classification and regression. The Spark 4.2.0 documentation describes the algorithm and its parameters, and a 2014 Databricks engineering post by two of its developers explains how the implementation was made to scale. [15][17][16]

The problem

The textbook procedure sorts each feature's values to list candidate thresholds and visits one node at a time. When the rows are partitioned across many machines, sorting is expensive and every extra pass over the data costs network communication. The goal is to train the same kind of tree on datasets that do not fit on one machine.

Where this topic fits

The model and the scoring are unchanged: greedy binary splits chosen by information gain, with Gini, entropy or variance as the impurity. What changes is the split search. Candidate thresholds are fixed in advance as bin edges, and the statistics needed to score them are gathered for a whole level of the tree in one pass.

How it is applied, step by step

  1. Before any splitting, compute approximate quantiles of each continuous feature on a sample of the data. They divide the feature into at most maxBins bins, 32 by default, and the bin edges are the only thresholds that will be considered.
  2. Grow the tree level by level. For all nodes at the current depth, the bins are used to accumulate the statistics a split needs, such as class counts per node, feature and bin, in a single pass over the data.
  3. For each node, turn the merged statistics into an impurity for every bin edge and keep the split with the largest information gain.
  4. Stop splitting a node when it reaches maxDepth, when no candidate gains more than minInfoGain, or when no candidate leaves at least minInstancesPerNode rows on both sides.
  5. Move to the next level and repeat, so the number of passes over the data grows with the depth of the tree and not with its number of nodes.

Why this approach fits

A split only needs to know how many rows of each class fall on each side, and those counts can be added up independently on each machine and then merged. Fixing the thresholds in advance turns the search into counting, which is the operation a distributed engine does best. Because a tree cares only about the order of feature values, replacing exact values by a few dozen quantile bins loses little: a threshold between two neighbouring quantiles sends almost the same rows left and right.

Limitation or tradeoff

The tree can only split at bin edges, so the result is an approximation of what an exact search would find, and the documentation notes that raising maxBins allows finer splits at the cost of more computation and communication. The number of nodes can double with every level, so deep trees need far more memory for statistics. The documentation also states that the implementation is not optimised for sparse input. None of this changes the statistical behaviour of a single tree: at any data size it still overfits when grown deep and is still sensitive to its top splits, which is why the same library also provides ensembles.

The page cited here documents the RDD-based spark.mllib API. The Spark ML main guide (opens in a new tab) says that API has been in maintenance mode since Spark 2.0, with the DataFrame-based spark.ml API now the primary one, so new code would normally start from spark.ml.

What the sources document

  • The decision tree is described as a greedy algorithm that performs recursive binary partitioning of the feature space and chooses, at each node, the split that maximises information gain. The impurity measures are Gini impurity and entropy for classification and variance for regression. [15]
  • Because sorting feature values is expensive for large distributed datasets, the implementation computes an approximate set of split candidates with a quantile calculation over a sampled fraction of the data. The ordered splits create bins, and the maxBins parameter, 32 by default, sets their maximum number. [15]
  • Tree construction stops at a node when its depth equals maxDepth, when no split candidate leads to an information gain greater than minInfoGain, or when no split candidate produces child nodes that each have at least minInstancesPerNode training instances. [15]
  • The developers write that splits for all nodes at the same level are selected simultaneously, so the algorithm makes one pass over the dataset for each level instead of one for each node, and that features are discretised into bins that are used to compute sufficient statistics for splitting. [17]
  • The post reports scaling tests on an EC2 cluster with 15 r3.2xlarge worker nodes, with trees built to 6 levels, and says the Spark 1.1 implementation is 4 to 5 times faster than the 1.0 version on many datasets. The documentation states that computation scales approximately linearly in the number of training instances, the number of features and maxBins. [17][15]

STMicroelectronics Machine Learning Core: a decision tree that runs inside a motion sensor

STMicroelectronicsDocumented in an open-source project

STMicroelectronics builds motion sensors that contain a Machine Learning Core (MLC). The company's public GitHub repository documents the core, ships ready-to-use configurations such as activity recognition for the LSM6DSOX sensor, and includes tools for designing the decision tree. [18][19][20]

The problem

Recognising whether the person carrying a phone is still, walking, jogging, cycling or driving means processing accelerometer data continuously. If the main application processor does it, that processor has to stay awake, which costs battery life. ST's approach is to classify inside the sensor and let it signal the processor when the result changes, which means the classifier has to be very small.

Where this topic fits

Inside the sensor the chain is: filters, statistical features computed over a fixed window, then a decision tree that maps the features to a class code. The tree is trained offline on a computer from labelled recordings. Only the finished tree, its features and its thresholds, is loaded into the sensor as configuration.

How it is applied, step by step

  1. Record labelled accelerometer logs for each activity. For this example the logs were collected with a smartphone carried in the user's pocket.
  2. Fix the features the sensor will compute: mean, variance, peak-to-peak and zero-crossing values of filtered accelerometer signals over windows of 75 samples at 26 Hz, which is almost 3 seconds.
  3. Build a table with one row per window and train a classification tree on it offline. ST's Python utilities accept a scikit-learn DecisionTreeClassifier and export it as a text file for ST's tools.
  4. Convert the tree into a sensor configuration with ST's tools and load it into the device.
  5. In operation, the sensor computes the features for each window and walks the tree, a short chain of comparisons of one feature against one threshold, ending in a class code written to a register.
  6. The sensor raises an interrupt when the register is updated, so the application processor can stay idle until there is something to act on.

Why this approach fits

Evaluating a tree is a handful of "is this number above that threshold" tests. It needs no multiplications, no floating-point matrix arithmetic and almost no memory, so it can be built into the sensor's own logic. The features are on unrelated scales, acceleration in g, a variance and a count of zero crossings, which a tree accepts without normalisation.

The model is also easy to debug. An engineer can read which feature and threshold separate walking from jogging, replay a recorded log, and see which comparison sent a window down the wrong branch.

Limitation or tradeoff

The tree sees only the features chosen in advance and decides once per window, so the result lags the motion by about a window length and can flip between classes at activity boundaries; the README notes that no meta-classifier is used in this configuration. The thresholds reflect how the training logs were collected. A tree trained with the phone in a pocket has no reason to work on a wrist, and the repository carries a separate wrist variant of the example. Activities that look alike in these four statistics cannot be separated by adding nodes; they need different features.

What the sources document

  • The MLC is described as a dedicated core for machine learning processing that executes algorithms directly inside the sensor, and moving algorithms from the application processor to the MEMS sensor is said to enable a consistent reduction of power consumption. [18]
  • The processing capability is obtained through decision tree logic: each node is an if-then-else condition in which an input signal, represented by statistical parameters calculated from the sensor data, is evaluated against a threshold. The result can be read at any time, and an interrupt can be generated for every change in the result. [18]
  • The LSM6DSOX example recognises stationary, walking, jogging, biking and driving from logs acquired with a smartphone in the user's pocket. 4Common mistakes

  1. Fitting a tree with the default settings and reporting its training accuracy.

    Why it causes problems
    scikit-learn's defaults grow the tree until every leaf is pure, so training accuracy is close to 100% whatever the data contain. In this lesson's noisy example the default tree scored 100% on its training half and 77% on the test half, while a pruned tree with 6 leaves scored 84%.
    How to recognise it
    Training accuracy at or near 100% with a clear gap to cross-validated accuracy, a leaf count in the dozens or hundreds from get_n_leaves(), and many leaves that hold one or two training rows.
    How to fix it
    Limit max_depth or min_samples_leaf, or prune with ccp_alpha, and choose the value by cross-validation. Report held-out accuracy together with the number of leaves.

  2. Choosing max_depth or ccp_alpha by comparing scores on the test set.

    Why it causes problems
    The test set then helps to fit the model, and the score reported from it is optimistic. With a small test set the effect is large: on 143 test rows a single row is worth 0.7 percentage points, about the size of the differences between neighbouring settings.
    How to recognise it
    The same rows are used to pick the setting and to report the final number, or the notebook contains a loop over settings that prints test accuracy.
    How to fix it
    Tune on the training portion only, for example with GridSearchCV over the alphas returned by cost_complexity_pruning_path, and score the test set once at the end.

  3. Presenting the top split or the feature-importance ranking of a single tree as a fact about the data.

    Why it causes problems
    When features are correlated, which of them the tree uses is close to arbitrary: in the resampling experiment above, five different features took the root position. Impurity-based importance also rewards whatever an overgrown tree splits on. A column of standard-normal noise added to the noisy two-feature example received 10% to 15% of the importance in the fully grown tree across ten random seeds, although shuffling it moved test accuracy by less than two percentage points in either direction.
    How to recognise it
    Refit on bootstrap resamples or cross-validation folds and compare the root split and the ranking. Compare the built-in importances with permutation importance computed on held-out data.
    How to fix it
    Report only splits and rankings that persist across resamples, prune before reading importances, prefer permutation importance on held-out data, and describe the result as an association and not as a cause.

  4. Training on heavily imbalanced classes with default weights and judging the tree by accuracy.

    Why it causes problems
    A split that isolates a few rare cases reduces overall impurity very little, so the rare class is often the first thing that depth limits and pruning remove. A tree that predicts the common class everywhere can still show high accuracy. The scikit-learn guide warns that trees become biased when some classes dominate.
    How to recognise it
    Recall for the rare class is near zero in the confusion matrix, and most leaves predict the majority class.
    How to fix it
    Use class_weight="balanced" or sample weights so that both classes contribute equally to impurity, evaluate with precision and recall for the rare class, and prefer weight-aware limits such as min_weight_fraction_leaf.

Exercise 2

Size, prune and stress-test a tree on real data

CodingIntermediateAbout 1 h (estimate)

Use Python with scikit-learn, which is free and runs locally or in a hosted notebook. The breast cancer dataset ships with scikit-learn (load_breast_cancer): 569 tumours, 30 numeric measurements and a benign or malignant label.

  1. Split the data with train_test_split(test_size=0.25, random_state=0, stratify=y). Fit a DecisionTreeClassifier(random_state=0) with default settings. Report its number of leaves, its depth and its training and test accuracy.
  2. Refit with max_depth from 1 to 5 and report training and test accuracy for each.
  3. Get the candidate alphas from cost_complexity_pruning_path on the training set, drop the last one, and choose ccp_alpha with GridSearchCV(cv=5) on the training set. Report the chosen alpha and the pruned tree's size and accuracies.
  4. Measure instability. Draw 100 bootstrap resamples of the training rows with numpy.random.RandomState(0), fit a default tree on each, and report how often each feature is chosen at the root, the range of leaf counts and the range of test accuracy.
  5. In three or four sentences, say which tree you would hand to a clinician to read and what you would tell them about how far to trust its first question.

Requirements

  • Use random_state=0 for the split and for every tree so that the numbers can be compared.
  • Choose ccp_alpha with cross-validation on the training rows only and touch the test set only to report results.
  • Read the root feature of each resampled tree from tree_.feature[0] and map it to a name with the dataset's feature_names.
  • Base the written answer on the measured numbers, including the size of the test set.

Expected behaviour

With scikit-learn 1.9.1 the default tree has 18 leaves, depth 5, 100% training accuracy and 90.2% test accuracy. Test accuracy by depth is 88.8%, 88.8%, 91.6%, 90.9% and 90.2%. Cross-validation chooses an alpha of about 0.0138, which gives a tree with 5 leaves and depth 3 that scores 95.5% on training data and 90.2% on the test set: the same test accuracy as the default tree with fewer than a third of the leaves. Across the 100 resamples the root feature is worst perimeter 38 times, worst concave points 32, mean concave points 16, worst radius 9 and worst area 5; leaf counts range from 8 to 16 and test accuracy from 86.7% to 95.1%. Other library versions may give slightly different numbers.

Hint 1

The last alpha returned by cost_complexity_pruning_path prunes the tree down to the root alone, so remove it before searching.

Hint 2

A bootstrap resample is rng.randint(0, n, n): n row indices drawn with replacement.

Hint 3

The test set has 143 rows, so one row changes accuracy by 0.7 percentage points. Keep that in mind before calling one tree better than another.

Show solution
python
from collections import Counter

import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import GridSearchCV, train_test_split
from sklearn.tree import DecisionTreeClassifier

data = load_breast_cancer()
X_train, X_test, y_train, y_test = train_test_split(
    data.data, data.target, test_size=0.25, random_state=0, stratify=data.target)

# 1. Fully grown tree
full = DecisionTreeClassifier(random_state=0).fit(X_train, y_train)
print(f"full tree: {full.get_n_leaves()} leaves, depth {full.get_depth()}, "
      f"train {full.score(X_train, y_train):.3f}, test {full.score(X_test, y_test):.3f}")

# 2. Depth sweep
for depth in (1, 2, 3, 4, 5):
    tree = DecisionTreeClassifier(max_depth=depth, random_state=0).fit(X_train, y_train)
    print(f"max_depth={depth}: train {tree.score(X_train, y_train):.3f}, test {tree.score(X_test, y_test):.3f}")

# 3. Cost-complexity pruning, alpha chosen by 5-fold cross-validation on the training set
alphas = full.cost_complexity_pruning_path(X_train, y_train).ccp_alphas[:-1]   # drop the root-only tree
search = GridSearchCV(DecisionTreeClassifier(random_state=0), {"ccp_alpha": alphas}, cv=5)
search.fit(X_train, y_train)
pruned = search.best_estimator_
print(f"{len(alphas)} candidate alphas, best ccp_alpha = {search.best_params_['ccp_alpha']:.5f}, "
      f"CV accuracy {search.best_score_:.3f}")
print(f"pruned tree: {pruned.get_n_leaves()} leaves, depth {pruned.get_depth()}, "
      f"train {pruned.score(X_train, y_train):.3f}, test {pruned.score(X_test, y_test):.3f}")

# 4. Instability: refit on 100 bootstrap resamples of the training set
rng = np.random.RandomState(0)
root_features, leaf_counts, accuracies = [], [], []
for _ in range(100):
    rows = rng.randint(0, len(X_train), len(X_train))          # sample rows with replacement
    tree = DecisionTreeClassifier(random_state=0).fit(X_train[rows], y_train[rows])
    root_features.append(str(data.feature_names[tree.tree_.feature[0]]))
    leaf_counts.append(tree.get_n_leaves())
    accuracies.append(tree.score(X_test, y_test))
print("root feature counts:", Counter(root_features).most_common())
print(f"leaves: {min(leaf_counts)} to {max(leaf_counts)}; "
      f"test accuracy: {min(accuracies):.3f} to {max(accuracies):.3f}, mean {np.mean(accuracies):.3f}")

Reading the results. The default tree fits its training rows perfectly and loses about ten points on the test set. Limiting depth or pruning does not buy much accuracy here: every tree lands between 88.8% and 91.6%, a spread of four test rows out of 143, which is too small to rank them. What pruning buys is size. The tree chosen by cross-validation matches the default tree's test accuracy with 5 leaves, and a five-leaf tree can be read and questioned.

What to tell the clinician. Hand over the pruned tree with its held-out accuracy and the number of test rows behind it. Present its first question as one of several nearly equivalent choices: under resampling the root was worst perimeter in 38 of 100 trees and one of four related size and shape measurements in the rest, so the data cannot say which is "the" most important. Single-tree accuracy across resamples ranged from 86.7% to 95.1%, which is the reason to prefer an ensemble when accuracy matters more than having one tree to read.
