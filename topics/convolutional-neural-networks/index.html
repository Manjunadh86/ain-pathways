Convolutional Neural Networks

A convolutional neural network (CNN) is a neural network whose early layers slide small learned filters, called kernels, across an image or similar grid, so the same pattern detector is applied at every position. Pooling and strides shrink the grid layer by layer, and later layers combine the detected patterns into a label, a set of boxes or a label for every pixel.

1Overview

Why it matters

Images, video frames, medical scans and spectrograms are grids in which neighbouring values belong together and the same pattern can turn up anywhere. A dense layer ignores that structure: mapping a one-megapixel image to an output of the same size would need about 101210^{12}1012 weights. Convolution builds the structure in, which is why a small network with tens of thousands of parameters can read digits, and a few hundred kilobytes of weights can cut a person out of a webcam feed in a browser.

Many failures in practice are arithmetic and design failures rather than exotic ones. A flatten layer is sized for the wrong input. Early striding discards small objects. A pooled network is trusted to be perfectly shift-invariant when it is only partly so. Pixel accuracy hides a segmentation model that predicts only background. Engineers who fine-tune pretrained vision models, read model cards or budget memory and latency for a phone need to be able to compute shapes, parameter counts and receptive fields by hand.

Key terms

Kernel (filter)
A small grid of learned weights, such as 3×3, that is slid across the input to measure how strongly one pattern appears at each position.
Feature map
The grid of numbers a kernel produces, one value per position, recording where its pattern was found.
Channel
One 2-D grid of values. A colour image has three input channels (red, green, blue); a layer with 16 kernels outputs 16 channels.
Convolution (cross-correlation)
Multiplying a window of the input by the kernel element by element and summing, at every position. Deep learning libraries do not flip the kernel, so strictly they compute cross-correlation.
Padding
Extra border values, usually zeros, added around the input so that the output can keep its size and edge pixels contribute to more output positions.
Stride
The number of positions the kernel moves between outputs. A stride of 2 produces an output with roughly half the height and width.
Pooling
Replacing each small window of a feature map by one number, usually the maximum, to shrink the map without learned weights.
Receptive field
The region of the input image that can influence one unit in a given layer. It grows as layers are stacked.
Parameter sharing
Reusing the same kernel weights at every position, so the parameter count does not grow with image size.
Fully convolutional network
A network built only from convolution-style layers, so it accepts any input size and returns a map of predictions instead of a single vector.

2Explanation

Introduction

A dense layer multiplies every input by its own weight. For a photograph that breaks down fast: a one-megapixel image has a million input values, and a dense layer producing an equally large output would need about 101210^{12}1012 weights, as Dive into Deep Learning (opens in a new tab) works out. It would also learn a separate whisker detector for every pixel position, although a whisker looks the same wherever it appears.

A convolutional neural network (CNN) builds in two assumptions instead. Nearby pixels matter together, so each unit looks only at a small window. And a pattern detector that is useful in one place is useful everywhere, so the same small set of weights is reused at every position. That reusable set is a kernel (or filter). Sliding it over an image and computing a weighted sum at each position produces a feature map, a grid that records how strongly the pattern appears at each location.

Picture a stencil that you slide across a page, noting at each position how well the text underneath matches it. A CNN learns many stencils at once, with the training process choosing their values, and then stacks layers so that later stencils match combinations of what earlier ones found. Zeiler and Fergus visualised a trained network and reported a hierarchy: layer 2 responds to corners and other edge and colour combinations, layer 3 to textures, layer 4 to more class-specific structures such as dog faces, and layer 5 to entire objects in varied poses.

A few terms before the details. A channel is one 2-D grid of numbers; a colour image has three. Stride is the step by which the window moves, padding adds a border of zeros, and pooling shrinks a feature map by summarising small windows.

The lesson builds the operation up piece by piece (convolution, channels, padding and stride, pooling, stacking) and then shows how one backbone serves classification, detection and segmentation. It assumes you have met training deep networks: a CNN is trained with the same loss, backpropagation and optimiser loop, applied to a different kind of layer.

How it works

Two ideas that make convolution fit images

Dive into Deep Learning (opens in a new tab) derives convolution from two principles. Translation equivariance: shifting the input should shift the detector's response by the same amount, so one detector can serve every position. Locality: a unit should depend on nearby pixels, not the whole image. Impose both on a dense layer and its weights collapse into one small kernel. CS231n (opens in a new tab) calls the reuse parameter sharing; in its AlexNet example the first layer would have about 105.7 million parameters without sharing and has 34,944 with it.

It makes the output somewhat less sensitive to exact position, but only somewhat, as the worked example shows. Strided convolutions are an alternative way to downsample.

Deep units can therefore respond to larger, more complex patterns. In Zeiler and Fergus (opens in a new tab), the layers of one trained network showed corners and other edge and colour conjunctions (layer 2), textures such as mesh patterns (layer 3), more class-specific structures such as dog faces and bird legs (layer 4) and entire objects with significant pose variation (layer 5). The classic layout, from CS231n, is INPUT -> [[CONV -> RELU]*N -> POOL?]*M -> [FC -> RELU]*K -> FC: spatial size falls and channel count rises as depth increases.

The convolutional backbone produces feature maps; what changes between tasks is the head on top.

Edge cases and limitations

Libraries compute cross-correlation, so kernels do not transfer to flipped convolution
PyTorch documents Conv2d with the cross-correlation operator: the kernel is not rotated. A routine that performs true convolution flips the kernel by 180 degrees first. For learned kernels the difference is irrelevant, but if you copy a hand-made kernel such as a Sobel filter from a signal-processing reference, or compare outputs with such a routine, expect edge responses with the sign reversed.
Unpadded layers eat the border
Each unpadded k × k layer removes k - 1 rows and columns. Dive into Deep Learning shows ten 5 × 5 layers turning a 240 × 240 image into 200 × 200, which discards about 30% of its area, and border pixels are read by fewer windows than central ones. For segmentation, where every pixel needs a prediction, use padding that preserves size, or crop deliberately and say so.
A stride that does not divide the input leaves pixels unread
The floor in the output-size formula silently drops a partial window. An 8 × 8 input with a 3 × 3 kernel, stride 2 and no padding gives a 3 × 3 output whose windows start at rows 0, 2 and 4, so row 7 is never read. Nothing fails; the model simply cannot see that edge. Choose sizes so that n + 2p - k is divisible by s, or accept and document the loss.
Pooling forgives small shifts, not all shifts
In the worked example a one-pixel shift of the bar changed the pooled map from [[27, 0], [18, 0]] to [[27, 27], [18, 18]] because the edge crossed a window boundary. The convolution is equivariant to shifts, but pooling and striding sample the grid at fixed positions. In practice, tolerance also comes from training on shifted and cropped examples (data augmentation).
A dense head ties the network to one input size
In the LeNet-style network the first dense layer takes 400 = 16 × 5 × 5 inputs, which is correct only for a 28 × 28 image. Another size gives a shape error or needs a different layer. Fully convolutional networks (Long, Shelhamer and Darrell) avoid the problem: they accept any input size and return a correspondingly sized output.
Layer-by-layer stories are tendencies, not guarantees
The progression from corners and textures to parts and whole objects comes from visualising particular trained networks. Olah and colleagues, in their Distill article on feature visualization, caution that individual neurons are not necessarily the right semantic units; one unit they inspected responded to both animal faces and car bodies. Treat the hierarchy as a guide to intuition, not as a property you can assume of every channel.

When to use it, and when something simpler is enough

Use it when

  • The input is a grid in which nearby values are related and the same pattern can appear anywhere, such as photographs, video frames, medical images or spectrograms.
  • You need a label, boxes or a per-pixel mask from images and have labelled examples, or a pretrained backbone you can fine-tune.
  • The model has to run within a tight budget on a phone, browser or camera, where a small convolutional network with tens or hundreds of thousands of parameters is realistic.

Think twice when

  • The data are rows of a table with no spatial order. Neighbouring columns share no meaning, so local kernels add nothing; use gradient boosting or logistic regression.
  • The answer depends on relationships between far-apart positions more than on local patterns. A stack of local kernels needs many layers to connect distant positions; see attention and transformers.
  • You have a few hundred labelled images and plan to train from scratch. Start from a pretrained model instead.

A simpler alternative. When images are few and consistently framed, hand-built features (colour histograms, edge counts) with logistic regression or gradient boosting can be enough. A pretrained CNN used as a frozen feature extractor feeding a simple classifier is the next step up. Fine-tune the whole network only when frozen features plateau, and train from scratch only when you have plenty of data that differs strongly from natural photographs.

Key takeaways

  • A convolution slides one small learned kernel over every position, so a pattern detector is reused everywhere, the parameter count does not grow with image size, and responses shift with the input.
  • Output size is floor((n + 2p - k) / s) + 1 and a layer has c_out × (c_in × k_h × k_w + 1) parameters, so you can check shapes and memory before you run anything.
  • Padding keeps borders from shrinking away, while strides and pooling downsample; downsampling is what makes the receptive field grow fast enough for deep units to see parts and whole objects.
  • Visualisations of one trained network show a progression from corners and edge combinations to textures, class-specific structures and whole objects, but that is a tendency, not a guarantee for every network or channel.
  • The same backbone serves classification, detection and segmentation; only the head, the loss and how much spatial detail is kept change.
  • Pooling gives only partial shift tolerance and dense heads fix the input size, so check small objects, input resolution and the evaluation metric against the task.

Example 1 of 5

LeNet-5 and bank cheque reading: a convolutional character recogniser in a deployed system

Documented in a paper

The 1998 Proceedings of the IEEE paper by LeCun, Bottou, Bengio and Haffner reviews handwritten character recognition and, in its Section X, describes a bank cheque reading system whose core is the convolutional network LeNet-5, later integrated into NCR's cheque-reading products. The Dive into Deep Learning chapter on LeNet gives a modern version of the architecture and the network's history in ATMs. [12][13][7]

The problem

A cheque-reading system must turn a scanned image of handwritten or printed text into an amount. The paper's system reads the courtesy amount, the one written in numerals. It has to find the candidate amount fields among all the text on the cheque, cut each field into pieces that may be characters, recognise each piece despite differences in slant, stroke thickness and position, and choose the best reading using knowledge of how amounts are written. The paper says verifying amounts by hand is time-consuming and costly for banks, so even partial automation is valuable. The convolutional network is the recognition step of that chain.

Where this topic fits

The paper builds the cheque reader as a cascade of stages that pass graphs of hypotheses along. A field locator proposes zones, a segmenter cuts each zone into candidate characters, and the recognition stage runs LeNet-5 on every candidate image. A grammar of valid amounts then removes impossible readings and a best-path search picks the final amount. The CNN's input is one small grayscale image of a candidate character and its output is a score for each character class.

How it is applied, step by step

  1. Find the amount. The paper's field-location stage uses classical image analysis, such as connected components, ink-density histograms and layout analysis, to propose rectangular zones that may contain the courtesy amount.
  2. Cut each zone into candidates. The segmentation stage uses heuristic image processing to cut a zone into pieces of ink that may be whole characters or parts of characters, and keeps the alternative groupings as hypotheses.
  3. Run the CNN on every candidate. LeNet-5 classifies each segment image into one of 95 printable-character classes plus a rubbish class for badly formed characters and segmentation errors, so a bad cut is scored instead of being forced into a digit.
  4. Keep the model small through weight sharing. The paper reports that LeNet-5 has 345,308 connections but only about 60,000 trainable parameters. The Dive into Deep Learning version, with two 5 × 5 convolution layers of 6 and 16 filters, has by our count 61,706 parameters.
  5. Choose the reading. A composition stage keeps only the paths that spell a well-formed amount, adding the recogniser's penalties to the grammar's, and a Viterbi step selects the lowest-penalty path. Cheques whose confidence is too low are rejected and sent to a person.

Why this approach fits

Handwriting varies in slant, thickness and position from writer to writer, but a short stroke looks the same wherever it occurs in the patch. Shared kernels give stroke detectors that work across the whole patch, and subsampling absorbs small displacements; the paper names local receptive fields, shared weights and subsampling as the ideas that give a degree of shift and distortion tolerance. The small parameter count also keeps the recogniser cheap to train and run (our analysis).

Limitation or tradeoff

A character classifier sees only the patch it is handed. If the segmenter cuts a character in the wrong place or two digits touch, convolution cannot recover what the patch no longer contains, so the other stages matter as much as the network. On the machine-printed business cheques the paper reports, 17% were still rejected for a person to read. The paper also notes that global training of the whole cascade mattered only a little in this task, because it adjusted a small subset of the parameters. Digits and printable characters are a far easier domain than natural photographs, and the Dive into Deep Learning network is a modern reconstruction that differs from the 1998 network in detail.

AppleDocumented in an engineering article

The problem

Detecting faces in photos must find every face, at any size and position, in images of arbitrary dimensions. Apple's privacy position meant the work could not be done on iCloud servers, so it had to fit the memory, power and thermal limits of a phone while sharing the GPU with the rest of the system.

Where this topic fits

The CNN is the detector itself. It scans the image in one pass and outputs, for every tile of the input, whether a face is present and the parameters of its box. An image pyramid handles different face sizes, and post-processing merges the candidate boxes.

How it is applied, step by step

  1. Define a classifier of fixed receptive field. The article's example is a 32 × 32 window with a natural stride of 16 pixels, trained to say whether the window contains a face.
  2. Make the network fully convolutional, so it can be applied to an image of any size in a single pass. Its output is a 2-D map in which each point corresponds to a tile of the input and carries a face score and box parameters.
  3. Handle different face sizes with a multi-scale image pyramid. The detector runs on each scale and the candidate boxes from all scales are combined in post-processing.
  4. Shrink the model. A thin, deep student network, a repeating structure of 3 × 3 convolutions and pooling, is trained to reproduce the outputs of a larger teacher network.
  5. Fit the runtime. Reuse memory by aliasing layers to the same buffer, share weights across the pyramid-scale networks, and split GPU work into items shorter than a millisecond.

Why this approach fits

A fully convolutional detector turns detection into the operation the earlier layers already perform: slide a learned window across the image. One forward pass scores every position, which avoids running a classifier on thousands of separate crops, and the stride sets how coarsely positions are sampled. The receptive field and stride arithmetic in this lesson is what determines the smallest face a given network can find.

Limitation or tradeoff

A fixed receptive field puts a floor on the face sizes one scale can detect, and a stride of 16 samples positions only every 16 pixels, which a typical design offsets with box regression and a pyramid. Every extra scale costs computation, and distilling a large teacher into a thin student usually gives up some accuracy to fit the device. The article gives no accuracy or latency figures for the shipped detector.

  • The detector is a fully convolutional network with a multitask objective: binary classification of whether a face is present, and regression of bounding-box parameters. The article's example uses a fixed 32 × 32 receptive field with a natural stride of 16 pixels. [18]

4Common mistakes

  1. Converting height-width-channel images to channel-first order with reshape instead of permute

    Why it causes problems
    reshape keeps the memory order and only relabels the dimensions, so pixel values are scrambled across channels while every shape stays valid. The network still trains, learns far less than it should, and raises no error.
    How to recognise it
    Plot a batch after your preprocessing code; the picture looks like noisy stripes. Accuracy lags well behind a known-good baseline although all shapes are correct.
    How to fix it
    Use permute (or transpose) to reorder axes, keep one documented layout such as (batch, channels, height, width) for PyTorch, and add a test that a known image survives the pipeline unchanged.

  2. Hard-coding the input size of the first dense layer after the convolutions

    Why it causes problems
    That size depends on the image size, kernels, padding, strides and pooling. Change any of them and the first forward pass fails with a shape error, or the layer is quietly resized to match while the design no longer does what you intended.
    How to recognise it
    An error naming two matrix shapes that cannot be multiplied, such as 64 × 1296 against 400 × 120, on the first training step after an architecture or input-size change.
    How to fix it
    Push a dummy tensor through the convolutional part and read its flattened size, use a lazily sized linear layer, or end the convolutional part with global or adaptive pooling so the dense head always sees a fixed size.

  3. Downsampling so early or so much that small objects disappear

    Why it causes problems
    Every stride or pooling step halves the grid. A detector whose prediction layer has a total stride of 16 samples positions every 16 pixels and has a fixed receptive field, so objects much smaller than that get no usable response and recall for them collapses.
    How to recognise it
    Break detection or segmentation results down by object size. Large objects look fine while recall for the smallest drops sharply.
    How to fix it
    Compute the total stride and receptive field at the layer that makes predictions. Reduce early strides, raise the input resolution, or run several scales, as the image pyramid in Apple's face detector does.

  4. Judging a segmentation model by pixel accuracy

    Why it causes problems
    When most pixels are background, a model that labels everything as background scores a high pixel accuracy while finding no objects, so the metric hides the failure you care about.
    How to recognise it
    Accuracy is high but predicted masks look empty or blobby, and per-class intersection over union for the foreground classes is low.
    How to fix it
    Report per-class intersection over union and a boundary measure, as the Google Meet article does, and look at predicted masks overlaid on images from every important subgroup.

  5. Splitting images at random when several images come from the same patient, scene or camera

    Why it causes problems
    Near-duplicates land in both the training and test sets, so the test score measures memorised identities, backgrounds or camera quirks and overstates performance on new patients, places or sites.
    How to recognise it
    Test accuracy is far higher than on a fresh batch from a new hospital, camera or location, and the same group identifiers appear in both splits.
    How to fix it
    Split by group (patient, scene, session or site) before any augmentation, and keep a final evaluation set from a different source where you can.

def conv2d(x, k, padding=0, stride=1):
    n_h, n_w, k_h, k_w = len(x), len(x[0]), len(k), len(k[0])
    padded = [[0] * (n_w + 2 * padding) for _ in range(n_h + 2 * padding)]
    for i in range(n_h):
        for j in range(n_w):
            padded[i + padding][j + padding] = x[i][j]
    out_h = (n_h + 2 * padding - k_h) // stride + 1
    out_w = (n_w + 2 * padding - k_w) // stride + 1
    return [[sum(k[a][c] * padded[i * stride + a][j * stride + c]
                 for a in range(k_h) for c in range(k_w))
             for j in range(out_w)] for i in range(out_h)]

def relu(m):
    return [[max(0, v) for v in row] for row in m]

def max_pool(m, size=2):
    return [[max(m[i * size + a][j * size + c] for a in range(size) for c in range(size))
             for j in range(len(m[0]) // size)] for i in range(len(m) // size)]

def trace(shape, layers):
    channels, height, width = shape
    reach, jump, total = 1, 1, 0
    for layer in layers:
        if layer[0] == "conv":
            _, out_ch, size, pad, stride = layer
            params = out_ch * (channels * size * size + 1)
            height = (height + 2 * pad - size) // stride + 1
            width = (width + 2 * pad - size) // stride + 1
            channels = out_ch
            reach, jump = reach + (size - 1) * jump, jump * stride
        elif layer[0] == "pool":
            _, size, stride = layer
            params = 0
            height = (height - size) // stride + 1
            width = (width - size) // stride + 1
            reach, jump = reach + (size - 1) * jump, jump * stride
        else:
            _, units = layer
            params = channels * height * width * units + units
            channels, height, width = units, 1, 1
        total += params
        print(f"{layer[0]:5s} -> {channels} x {height} x {width}   params {params:,}")
    print(f"total parameters {total:,}   receptive field {reach} px   total stride {jump}")

Show solution
python
import torch
from torch import nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

torch.manual_seed(0)
device = "cuda" if torch.cuda.is_available() else "cpu"
to_tensor = transforms.ToTensor()
train_set = datasets.MNIST("data", train=True, download=True, transform=to_tensor)
test_set = datasets.MNIST("data", train=False, download=True, transform=to_tensor)
train_loader = DataLoader(train_set, batch_size=128, shuffle=True)
test_loader = DataLoader(test_set, batch_size=1000)

def make_cnn():
    return nn.Sequential(
        nn.Conv2d(1, 6, kernel_size=5, padding=2), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(6, 16, kernel_size=5), nn.ReLU(), nn.MaxPool2d(2),
        nn.Flatten(),
        nn.Linear(16 * 5 * 5, 120), nn.ReLU(),
        nn.Linear(120, 84), nn.ReLU(),
        nn.Linear(84, 10),
    )

def make_mlp():
    return nn.Sequential(nn.Flatten(), nn.Linear(784, 256), nn.ReLU(), nn.Linear(256, 10))

def count(model):
    return sum(p.numel() for p in model.parameters())

def accuracy(model, shift=0):
    model.eval()
    correct = 0
    with torch.no_grad():
        for images, labels in test_loader:
            images, labels = images.to(device), labels.to(device)
            if shift:
                images = torch.roll(images, shifts=shift, dims=3)
            correct += (model(images).argmax(dim=1) == labels).sum().item()
    return correct / len(test_set)

def train(model, epochs=3):
    model.to(device)
    optimiser = torch.optim.Adam(model.parameters(), lr=1e-3)
    loss_fn = nn.CrossEntropyLoss()
    for _ in range(epochs):
        model.train()
        for images, labels in train_loader:
            images, labels = images.to(device), labels.to(device)
            optimiser.zero_grad()
            loss_fn(model(images), labels).backward()
            optimiser.step()
    return model

x = torch.zeros(1, 1, 28, 28)
for layer in make_cnn():
    x = layer(x)
    print(layer.__class__.__name__, tuple(x.shape))

for name, make in [("cnn", make_cnn), ("mlp", make_mlp)]:
    model = train(make())
    print(name, count(model), accuracy(model), accuracy(model, shift=3))

The shape printout is Conv2d (1, 6, 28, 28), ReLU (1, 6, 28, 28), MaxPool2d (1, 6, 14, 14), Conv2d (1, 16, 10, 10), ReLU (1, 16, 10, 10), MaxPool2d (1, 16, 5, 5), Flatten (1, 400), Linear (1, 120), ReLU (1, 120), Linear (1, 84), ReLU (1, 84), Linear (1, 10). The two parameter counts are 61,706 and 203,530, so the CNN has about a third of the MLP's parameters. Each of the last two lines gives the model name, its parameter count, its accuracy on the original test images and its accuracy on the shifted ones.

How to read the result: the convolution is equivariant, so a shifted digit produces a shifted feature map, but the dense layers after Flatten read each position of that map with its own weights. Pooling forgives only part of the shift. A digit that moves 3 pixels therefore still changes the input to the dense layers, in the CNN as in the MLP. Expect both accuracies to fall and compare the size of the fall. If the CNN falls less, the shared kernels are helping; if it does not, say so, because one seed and three epochs is a small experiment. Training with randomly shifted images would improve both models, and is a good follow-up.
